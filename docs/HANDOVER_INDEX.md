## 6. 突然の会話上限への備え：終了時ではなく節目で保存

本節は今回のユーザー依頼に基づく引き継ぎ記録の運用。バックグラウンド自動同期や新しいタイマーを実装したという意味ではない。

- 相談役は、方針・優先順位・許可範囲の確定／変更、指示発行、監査の受理／修正、担当・報告先変更を、そのターンで本書の該当箇所へ反映し通常commitする。会話の最後やリミット警告まで待たない。保存できなければ未保存と明示する。
- Codexは、指示受領、既存checkpoint、完了、中断の記録に、担当範囲の現在地とreport参照を含める。報告前にGitへ記録し、送信失敗でも成果・次に必要な判断が失われないようにする。人間の未回答を自分で閉じない。
- 状態は少なくとも、方針確定、指示発行、受領、着手、実行中、判断待ち、技術完了、監査受理、人間判断保留を区別する。全状態のための新システムは作らず、既存のreportと本書の表で管理する。
- 並行担当は自分の状態と参照だけを更新し、remote最新版と現在blob SHAを確認する。競合は取り込み直し、他担当の変更を消して上書きしない。内容・長い証拠・回答原文は既存reportへ置き、本書を全ログの複製にしない。

- 次の起動指示に本書の読了・記録更新を含める。日付付き引き継ぎファイルを毎回プロジェクトへ差し替える運用には戻さない。
