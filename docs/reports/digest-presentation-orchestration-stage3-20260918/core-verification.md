## 元の時計と表示時計

接続を加える前の確定字幕、保持区間、素材参照は元の時計で保存する。接続の自動原本と人間上書きから具体的な接続を解決し、その一組から共通の表示時計を作る。字幕の開始・終了、測定ピーク、動作開始、音響証拠の表示位置はすべてこの時計へ移す。

境界ちょうどの点は後続保持区間へ属する。一方、字幕の終了位置は区間の外側を指すので、直後の挿入を字幕自身の長さへ加えない。字幕は開始側の移動量を使って元の表示期間を保つ。既に移動済みの計画を元計画として再投入する処理は拒否する。

音響候補が接続をまたぐ場合、元の観測記録は変更せず、表示側では保持区間との交差部分へ分ける。黒画面への挿入と、元動画の提示末尾を超えるデコード余剰部分を音響証拠の保持部分へ混ぜない。

元の確定字幕・保持区間・素材・Digestの版とハッシュ、具体的な接続を表示時計に束縛する。BlackとSoftは同じ長さでも別の時計識別になり、長さが一致するという理由で古い時計を再利用できない。

## 16 kHz観測と44.1 kHz再生

映像は30 fps。44.1 kHzの再生では1フレームが1,470サンプル、12フレームの挿入が17,640サンプルになる。16 kHzの観測では同じ挿入が6,400サンプルになる。

16 kHzでは一般のフレーム境界が整数サンプルに一致しない。そのため、サンプルを一度フレームへ丸めて境界を判定せず、元のサンプル数とフレーム数の整数積で前後を比較する。必要な座標変換は有理数で保持し、整数にならない値を勝手に丸めない。測定証拠のサンプルレートと観測時計の一致も要求する。

実状態検査では最初のNormal接続へ一時的にBlackを指定した。表示長は4,867から4,879フレームとなり、次を確認した。

| 実在する対象 | 変更前 | 変更後 | 差 |
|---|---:|---:|---:|
| 測定ピーク000067の表示フレーム | 367 | 379 | +12 |
| 同ピークの16 kHz表示サンプル | 195,840 | 202,240 | +6,400 |
| 同ピークの44.1 kHz再生サンプル | 539,784 | 557,424 | +17,640 |
| 選択済みShake字幕000008の開始フレーム | 340 | 352 | +12 |

自動選択された3件のPulseはすべて最初の接続より前にあり、118・259・323フレームのまま移動量0となる。実候補にPulseを追加して非ゼロ移動を作ることはしていない。非ゼロ移動後の描画状態と観測時刻の導出は模擬結合試験で確認し、実PNGによる独立した物理検証でも確認した。後述の物理検証は模擬JSONのPNGを使わず、実候補に使った同SHAの画像を使う。48 kHz再生についても別の回帰試験で1フレーム1,600サンプル、12フレーム19,200サンプルを確認した。

## 意味上の許容集合と再現可能な選択

AIには具体的な描画値を作らせず、意味上許される有限プリセットの集合を返させる。字幕では通常表示、意味の強調、声の強さ、反応を区別する。接続では連続、区切り、どちらも許容を区別する。部分強調はColorだけを許し、Pulseは実測済みで当該字幕に収まるピークへの参照を必要とする。

回答は新入力のハッシュ、全IDの一意な網羅、完了状態、理由、実在する根拠IDを検査する。根拠には入力内のASR観測IDも含める。全音響候補の欠落、未知ID、重複プリセット、任意の描画数値、物理的に成立しない選択は固定前に拒否する。未解決と表現不能は空の許容集合と独立した状態で保持する。

具体的な演出は、DigestのSHA、オーケストレーションの版、字幕／接続の種別、安定IDの4項目を曖昧さのないJSON配列として直列化し、SHA-256全体を整数として、名前順に並べた許容集合の要素数で剰余を取って選ぶ。順番による割当、件数ノルマ、他の字幕の選択に応じた変更、再抽選は行わない。回答の列挙順や他項目の判断を変えても、同じ項目の選択は維持される。

実装：[判断固定・描画用の導出](../../../evals/clip_composition/presentation_orchestration_v001.mjs)、[許容集合と選択の試験](../../../evals/clip_composition/presentation_orchestration_v001.test.mjs)。

## 追加検査：実ファイルへの保存・変更・再読

既存検査プログラムの変更前バイト列を別名で保存してから、検査プログラム内だけを補強した。候補生成の実装は変更していない。未使用の検査フォルダーに10状態を順番どおり作り、各状態へ自動原本2ファイル、人間上書き2ファイル、選択根拠1ファイルを実保存した。分岐する状態は、遷移元フォルダーの実ファイルを読み、別inodeの独立ファイルとしてコピーした。コピー完了後を変更前の比較基準にした。

変更処理は実ファイルから読み出した状態へ既存の上書き・Reset処理を適用し、その返却内容を対象の上書きファイルだけへ書いた。対象外の4ファイルは各変更の前後でバイト列・SHA-256・ナノ秒単位の更新時刻・inodeが一致した。自動原本2ファイルと選択根拠は、全状態で元入力のバイト列を保持した。遷移元のフォルダーも変更していない。

Resetの検査では元ファイルをコピーし直さず、Reset処理の返却内容を通常のJSON保存形式で書き、元入力とのバイト一致を確認した。片側だけのResetは他方の上書きを残し、両方のResetはどちらの順序でも5ファイル全部が元入力と一致した。既に空の上書きに対する最後のReset 2操作は、書込みが発生せず、更新時刻も変わらなかった。

| 観測 | 結果 |
|---|---:|
| 独立した検査フォルダー | 10状態 |
| 初期コピーによるファイル作成 | 50ファイル |
| 対象上書きだけの実ファイル変更 | 8回 |
| 差分がなく書込みを省いたReset | 2操作 |
| 元の保存入力への書込み | 0回 |

各状態の5ファイルを実際に読み直し、元の入力も実ファイルから再読して、新しい処理文脈から時計と描画内容を導出した。保存状態と導出された全内容が期待する10状態へ一致した。これは検査プログラムによる保存・既存導出処理への再入力の検証であり、描画証拠そのものの実ファイル保存・再読は追加していない。描画証拠の検証範囲は前節のメモリ内変換・復元である。
