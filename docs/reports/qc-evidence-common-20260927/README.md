担当: Codex2。2026-09-27のkawafmm承認済み指示に基づく。対象は制作時間の基準整理と、同じQC共通資料の保存・再読・検証の重複除去だけ。

## 14.1 時間の訂正と分類

詳細と根拠は [時間の基準整理](timing-baseline.md) と [105行の工程記録](timing-baseline.json)。

- 素材取得開始から初稿固定までの実測: **17時間29分54.243秒**。commit/pushと相談役報告までの時間ではない。
- 正常経路参考: **約10時間03分**。このうち約3時間23分は、保存失敗末尾や復旧処理を分離できない包括時間の代用。正常に一度で完走した実測・最短保証ではない。
- 本体合成までの参考: **約5時間14分**。描画前安全検査を含み、完成動画走査・全編再現・字幕状態QC・最終照合・固定保存を除く。
- 以前の「11時間5分」は、同じ回答の表の合計565分と100分違っていた計算誤りを訂正。「約6時間」も工程境界を分け直した。今回のQC改善による短縮量とは扱わない。

必須・外部待機・失敗/再試行・復旧・重複検証候補に分け、親子工程と並行工程の二重加算を避けた。正常参考の上位は、字幕状態QC約148分、全編再現約86分、本体合成約85分、STT送信等約69分。順位を検査省略の根拠にしていない。

## 14.8.1 現物で確認した重複

今回runの `finite-result.json` は3,428,363,761 bytes、326字幕・424サンプル。各字幕の証拠へ、次の資料が繰り返し埋め込まれていた。

| 資料 | 共通・固有の区分 |
|---|---|
| 保存済み通常案・自動案・演出入力・入力一覧・描画範囲・全字幕の画像対応 | 同じ検査範囲内で共通。自動案の独立欄がない今回runでも、演出入力内の元案は保持 |
| 実行ファイルの版・SHA・process記録 | 入力一覧や実行記録内に存在。同一内容だけ共有し、別コマンド・時刻・入出力は区別 |
| 指示ID・frame・比較矩形・参照class・RGB距離・visible・violation | 字幕/sampleごとの観測。全件と順序を保持 |
| 参照画像・実行対応の記録 | 同一内容は共有し、異なる参照候補を削除・混同しない |

従来の保存は共有しているオブジェクトも全文へ展開し、再読すると独立したコピーになる。さらに全体QCの構築で字幕ごとにコピーし、validatorも共通の演出解決・入力照合・画像対応を毎回繰り返していた。

## 保存と検証の変更

- `presentation_qc_evidence_store_v001.mjs`: QC専用の版付きJSON束。各object/arrayを内容SHA付きの浅いnodeとして一度保存し、字幕/sampleから参照する。全体を単一の巨大文字列へ展開しない。同一インスタンスも、別インスタンスの同一内容も共有する。
- SHAはソート済みkeyと子のSHAを含むnodeの正規形へ付ける。これは旧形式の展開済みJSONに対するcanonical SHAとは別の値。元証拠内の既存SHAは変更しない。root・全node数・参照到達性・各nodeの内容SHAを照合し、渡された全file SHAも確認する。
- readerはこの新形式だけを受け、各nodeを一度復元する。旧JSONへのfallbackはない。古い成果物と歴史用readerは変更せず、今回の比較スクリプトだけが旧保存済み証拠を読む。
- 共通の演出解決・入力照合・画像対応の検証を、1回の同期検査呼び出し内でまとめる。字幕/sample固有の検査は全件実行する。次の呼び出しへ合格結果を持ち越さず、外部から検証済みcacheを注入できない。
- 全体QCのコピーは1個のグラフとして行い、入力から分離した状態のまま共通参照を維持する。
- 正常QC保存と、不合格・例外時の証拠保存へ接続。不合格のCLI報告は保存先・SHA・要約を返し、全文を再展開しない。証拠の保存失敗は明記し、不合格を合格へ変えない。
- 現行の一件修正/全編修正も、描画結果・完了記録・worker結果保存・job登録・独立preview再検証を同じwriter/readerへ接続。復元後の完了記録とUI応答の構造は維持する。固定済みの過去run専用スクリプトは書き換えない。

書込みはすべて上書き禁止。途中で失敗した新fileも既存fileも黙って上書きしない。証拠の外側にあるmanifestまたは保存receiptのfile SHAをreaderへ渡す。正規形のSHAだけを、外部で確定したfileとの同一性の代わりにはしない。

## 実証と効果測定

測定値は [measurement.json](measurement.json) に保存済み。入力は既存runの保存済み証拠であり、動画再encode・字幕再描画・STT再実行・有料APIは0。Apple M3 Max、36GiB RAM、Node v20.19.6で測定した。以下のGBは10進表記。

| 対象 | 旧形式 | 新形式 | 差 |
|---|---:|---:|---:|
| 同じQC証拠1束のJSON総量 | 3,428,363,761 bytes | 869,774,951 bytes | **2.559GB、74.63%減** |
| 別processの読込み最大常駐メモリ | 5.651GB | 1.529GB | **4.121GB、72.94%減** |
| 読込み | 37.737秒 | 10.061秒 | **27.676秒、73.34%減** |
| 読戻した全証拠の再保存 | 18.706秒 | 6.599秒 | **12.108秒、64.73%減** |
| 全326字幕のnative validator | 単独計時なし | 2.852秒 | 旧値を推定で補わない |

共通の判断資料と描画範囲は1組7,779,707論理bytes。旧形式は全体1＋字幕326の327組で、追加複製分は2,536,184,482論理bytesだった。物理file量とはkey・書式・他の固有資料の分だけ異なる。新形式は1,460,153個の固有nodeを保存し、旧展開中の14,298,219個の重複nodeを参照に置き換えた。

旧展開データを初めて新形式へ変換する処理は**69.241秒**であり、再保存6.599秒とは区別する。新形式の再保存値は、再読で共有を復元したグラフに対する値。新しい全編描画からの最初の保存時間そのものは未計測。検証用の全値digestは旧54.469秒・新4.556秒で、保存/読込み時間へ含めていない。

元の証拠と完成MP4は保存したままなので、今回ディスクから2.559GBを削除したという意味ではない。同等の証拠fileを1つ作る際の容量差である。複数の独立した完了記録をまたぐ共有ストレージは導入せず、各証拠束の中で共通資料を一度保存する。

別processで全値digest・全326字幕のvalidator・違反数/内容が一致。424サンプル中423件visible、000103の1件not visibleを保持した。000103は7801f、757参照・741class、RGB距離1,345,125 / 1,344,947のまま。初稿MP4 SHAと元巨大証拠SHAも一致した。

比較は旧形式の読込み・同形式再保存と、新形式の別Node processでの読込み・再保存。旧形式は今回runで使用した分割reader/writerを使い、コピーのbyte一致を確認する。展開済み全データの論理digestも一致させる。別processで全326字幕を検証し、元の合否・違反配列・000103の不合格を照合する。

読込み時の最大常駐メモリと、worker全体の最大値を区別する。旧worker全体には旧データの論理digest計算と新形式への一度限りの変換も含まれるため、通常の保存・再読時間と混ぜない。OS file cacheと他process競合を排除した性能試験ではなく、同じMac上の各1回の実測である。

大規模検証の設営中に2回の計測を中断した。独立digestのscalarごとのSHA生成を整理した後、OS sampleでNodeの弱参照表の再配置へ処理が集中していることを確認。呼び出し中は元データ全体を保持しているため、保存処理と検証器の同一性索引を呼出し内の通常の参照表へ変更した。全キー・配列順・scalar型/値、保存形式・判定の意味は維持し、未使用の `measurement-v003/` で新旧双方を計測し直した。中断記録・読込みcheckpoint・process観測を残し、今回作った一時コピーだけ削除した。GPU job・媒体・元証拠へ作用していない。

## 検証条件と限界

- [対象試験](test-results.json): **79/79合格**（共通保存/共通検証/不合格保存/native/全編再現71件、編集job8件）。
- 共通/字幕固有の改ざん、SHA不一致、欠損、未知schema、循環参照、上書きを拒否。
- 合成証拠を別Node processで再読。2200MiB（2GiB超）の展開相当の共有資料を128MiB heap上限でも保存・再読し、巨大文字列を作らないことを確認。
- 共通資料の同一性、全体/局所証拠の対応、呼び出し間で変更された資料の再検証、不合格保存と小型CLI報告を検査。
- 一般のQC条件・RGB距離・unique minimum条件・対象frame・参照候補・字幕・codecは変更しない。全編再現検査も保持。
- 元native QCは423/424合格、000103の1件不合格を保持する。元の expected=1,345,125 / duplicate=1,344,947 は書き換えない。以前のcodec領域限定診断による解決と、元native合格は区別する。
- rendererの既存「12 行数・行の正の交差・安全領域・空alpha」試験には旧形式の完成映像証拠を使う期待値の不一致が残る。変更前HEADのrenderer QCで同じ失敗を再現した。全test合格とは記録しない。
- 編集jobのretry試験は、保存版を進める操作を既存の接続変更へ差し替え、実書体・字幕画像生成への依存を除いた。元版retry・保存版分離・旧版動画のassertはすべて維持した。
- 全編描画は再実行していない。描画所要時間や全runの最大memory改善は未計測。比較画像の生成・保持（約232GB）には未着手で、14.8.2へ残す。
