### 3.2 保全と整理の権限を分ける

今回、次を明示的に許可する。

- 既存ignore設定を読んで、確認済みの生成物専用範囲へ狭い除外規則を追加する。
- 元workspaceでもその規則を有効にし、実際の `git status` と照合する。

- 今回の関連処理で生成物が追跡対象へ増殖する原因を、出力先指定・狭いignore・最小の入口検査で直す。

**旧「元workspaceのstatusを開始時と同一に保つ」は、この整理対象のignore設定・意図した保存処理に限り変更する。** 未追跡表示は減るのが正しい。コード内容、素材、完成候補、固定判断、過去証拠、無関係な差分の保全は引き続き必須である。

元workspaceのbranch・HEADは原則動かさない。実行中の仕事と同じindexや出力を並行更新しない。書込競合の可能性があれば、該当書込だけ調整し、無関係な実行を勝手に停止・killしない。

既存の最終記録を再利用し、現在の差分だけ補う。必要なのは、root、HEAD／branch、worktree一覧、追跡済み変更、stage済み変更、有効ignore、未追跡の分類、出力rootと稼働中writerである。

### 3.4 三分類の後に、必ず実処理する

**A：Gitへ残すべきsource／test／docs／軽量の再現定義**

由来の明確なコード、試験、指示書、手書きhelper、軽量報告等の未保存分は、対象pathを明示して保存する。工程III機能実装と混ぜず、元系統が分かる整理・救済用commitへまとめる。未完成のコードは「保存済み、未受入」と明記し、完成品や正式契約へ昇格させない。既存branchに同じ内容が保存済みなら重複commitせず対応SHAを残す。

元workspaceのコード内容やbranchを動かさず別worktree／保存branchへ複製して救済できる。元に残したsourceの差分は隠さず、「どのcommitへ保全済みか」を残す。これら少数の意図した差分が表示されることは整理失敗ではない。

**B：Gitへ入れない生成物・素材・大きな証拠**

MP4、PNG群、復号dump、cache、実行log、ダウンロード済み素材、ASR出力などは、再現sourceと区別する。STT本文やJSONでも、手修正された正本・唯一の入力・必要な軽量証拠なら、単純なcacheへ分類しない。

当面、既存実体は移動・削除せず、その位置で非Git管理とする。生成専用と確認した範囲へ、将来の同種runも覆うroot相対の狭い規則を追加する。巨大な1回分のIDを延々と列挙する対処だけにしない。一方、`evals/`全体、`*.json`、`*.md`、`*.png`などの広い除外でsourceやfixtureを隠さない。

`/evals/clip_composition/outputs/`全体を除外してよいのは、生成物専用という責務と、残すべき未追跡source・正本が隠れないことを確認できた場合だけ。それ以外は確認済みrun rootまたはさらに狭い範囲から処置し、既存の追跡済みfixtureはindexから外さない。`research/downloads`や`stt`も一律に除外せず、生成・保管専用範囲と手管理情報を分ける。

元workspaceへ共有 `.gitignore` commitをすぐ適用できない場合は、Gitが返す実際の `info/exclude` の所在を確認して、**同じ検証済みの規則をローカルにも追記してよい。** 既存設定を上書きせず、追加部分と理由を記録する。共有規則は専用branchの `.gitignore` へ保存し、ローカルだけの隠蔽で終えない。履歴のmergeや正式版変更はこのために行わない。

「Git対象外」は「バックアップ済み」「削除可」「容量解消済み」ではない。素材・成果物・監査証拠・再生成可能cacheをrun単位の簡単な表で区別し、現在の所在、参照元、保持理由を残す。既存manifestを優先し、新しい巨大なデータ管理基盤や全量hash台帳は作らない。容量と整理対象は把握するが、容量回収を今回の必須作業にしない。

**C：用途不明・別作業・権限が不明な物**

その物だけを保留する。削除・移動・ignore・外部pushをしない。最小のpath一覧と理由を残し、A/Bの処理と工程IIIは続行する。未知のファイルが1件あることを理由に全体を本人待ちへ変えない。秘密情報は内容を保存しない。

### 3.5 発生箇所と再発防止を閉じる

1. 既存runで作成されたBの実体と参照pathは、そのまま保持する。過去の証拠hashや保存pathを「きれいにする」ために書き換えない。

## 4. 工程IIIの正しい合成順

今回ここを明示的に固定する。

### 4.1 正本の順序

```text
保持済みDigestの基礎映像・PCM・元表示時計
        ↓
接続の固定自動案 + 接続overrideを解決
        ↓
接続による表示時計を一度だけ生成
        ↓
基礎映像へNormal / Black / Softを適用
音声へ必要なゼロ挿入を適用
        ↓
元字幕時刻・音響候補・局所ピークを
同じ接続表示時計へ一度だけ投影
        ↓
字幕の固定自動案 + 字幕overrideを解決
        ↓
投影済み字幕時刻上でColor / Scale / Panel / Pulse / Bounce / Shakeを描画
        ↓
共通QC
        ↓
完成Digest
```

### 4.2 字幕は接続処理の後に描画する

工程IIの焼込短尺では字幕画素もフェードしたが、工程IIIの本経路では**字幕を焼込前の基礎映像から分離して扱う**。

初期契約は次とする。

- 接続のfade／blackは基礎映像へ作用する
- 字幕overlayは、その後の表示時計に描画する
- 接続表現が字幕文字自体を暗くすることを、初期仕様にはしない
- 字幕を一緒にfadeさせる演出が必要なら、後で別の明示的表現として扱う

これにより、接続処理が字幕の可読時間やColor／Panel／Bounce等の画素を暗黙に変更しない。

ただし、字幕がSoftの6frame窓へ時間的に重なる場合は、**背景だけがfadeし字幕は通常overlayされる**ことになる。その状態を仕様として記録し、実frameで確認する。見心地の最終判断は技術完成とは分ける。

## 5. 共通表示時計を一つにする

工程IIIでは、映像・音声・字幕・音響根拠へ別々にshiftを足してはいけない。

### 5.1 一つのtime projectionを作る

入力は少なくとも次を持つ。

- 元Digest frame clock
- 元PCM sample clock
- 接続ID、元境界frame
- 接続の具体preset
- 各接続の挿入frame数

出力は、任意の元frame／元sample／元字幕区間／元peak位置を、完成表示時計へ変換できる決定的なprojectionとする。

30fps／48kHzでBlack／Softが12frameを追加する場合は、該当境界より後の元位置へ12frame／19,200sampleを加える。Normal Cutは追加0。

境界**ちょうど**から始まる後側のframe・sample・字幕・peakは、挿入後へ写す。境界直前の保持側は挿入前へ残す。

### 5.2 二重投影を拒否する

- 既にdisplay timeへ移したplanをもう一度projectionへ渡さない
- 元時計か表示時計かを版・refで区別する
- 接続override変更時は、元正本からprojectionを再派生する
- 変更済み表示planへ差分shiftを積み重ねない

Resetも同じで、毎回元時計＋固定自動案＋overrideから再解決する。

## 6. Pulse／Bounce／Shakeの時計契約

### 6.1 Pulse

Pulseの根拠は、元音響観測にあるpeak IDと元sample／元時刻を正本として保持する。

接続projection後に、同じpeak IDへ表示sample／表示frameを派生して追加する。元peak位置を書き換えない。

- peakが境界より後なら先行挿入量だけshiftする
- peakが境界ちょうどなら後側として挿入後へ置く
- peakをblack挿入区間へ移動しない
- 音響候補と字幕の対応も同じprojection版へ束縛する

Pulseの発火frameは**投影済みpeak**から作る。接続変更で先行挿入量が変われば、元peakから再投影する。

### 6.2 Bounce／Shake

Bounce／Shakeは元発声時刻ではなく、既存仕様どおり**字幕表示開始**を基準とする。

工程IIIでは、投影後の字幕startFrameを一回だけ基準にする。

- 接続前のstartFrameを使ってから後でshiftしない
- 動作内部frame数は変えない
- Resetや接続変更時には投影済み字幕開始から再生成する

### 6.3 Color／Scale／Panel

本文・範囲・表示長は変えず、投影後の字幕区間全体へ適用する。部分Colorの文字範囲は時刻投影と独立に保持する。

## 7. 全体での自動使い分け

ここが工程IIIの中心である。

### 7.1 「唯一の正解」を要求しない

AIへ、全字幕・前後文脈・音響候補・接続境界の前後文脈を渡し、各対象について次を判断させる。

1. 表現を付ける意味があるか
2. どの意味役割が許されるか
3. その役割を表現できるpresetのうち、どれが**許容可能**か
4. 表現不能か、判断材料不足か

AIはpx、frame数、色、曲線、座標、filter式を決めない。

### 7.2 字幕は「意味役割 → 許容preset集合」の二段にする

初期の役割整理は、既存表現を壊さない範囲で次のように扱える。

| 意図 | 許容候補の例 |
|---|---|
| 通常表示 | Normal |
| 意味上のfocus | Color。全文をまとまりで読ませる場合はPanelも許容候補になり得る |
| 発声エネルギー | Scale。局所peakとの対応が強い場合はPulseも許容候補になり得る |
| 短い反応・出現表現 | Bounce／Shake。両方が物理・意味的に許容なら複数候補としてよい |

Colorの部分範囲など、片方しか意味を保持できない場合は一候補だけにする。

Normalを、単に安全だからという理由で全件の逃げ道へ入れない。逆に、演出する意味が薄い字幕はNormalだけでよい。

### 7.3 接続は三分類する

接続について、AIは具体的なfade長を決めず、前後文脈から次のどれかを返す。

- `continuation`：Normal Cutのみ許容
- `separator`：Black／Softのseparator系を許容
- `either`：Normal Cut／Black／Softの複数が許容
- `unresolved`／`unrepresentable`

`either`を無理に意味説明で一つへ閉じない。

### 7.4 複数許容時だけ再現可能なvariationを使う

AIが複数presetを許容した対象では、同じ入力で毎回同じ結果になる**決定的variation resolver**を用いる。

推奨方式：

```text
sha256(
  digest SHA
  + orchestration version
  + item kind (caption/connection)
  + stable item ID
)
```

を、安定順に並べた許容preset数へ写す。

要件：

- process乱数を使わない
- 実行時刻をseedにしない
- 件数quotaを使わない
- every-Nや交互配置を使わない
- 「全部使うため」の後補正をしない
- 許容候補が一つならその一つを使う
- 選択後の**具体presetを固定自動案へ保存**し、再render時に再抽選しない

これにより、将来「どの場面でどの表現が使われたか」を実データとして追える。

## 8. 固定自動案とoverrideを二系統のまま保つ

```text

→ caption fixed auto
→ caption override

connection baseline
→ connection fixed auto

        ↓
共通time projection上で統合
```

### 8.1 必須locality

次を実証する。

- 字幕1件を変更してもconnection fixed auto／connection overrideはbyte不変
- 接続Resetは字幕overrideを消さない
- 字幕Resetは接続overrideを消さない
- 接続変更で表示時刻が変わっても、字幕の**意味選択・本文・preset選択**は保持し、投影時刻だけ再派生する
- Reset後は、それぞれの保存済みfixed autoへ戻る

「完成planを直接書き換えてUndoする」方式へ戻らない。

## 9. 工程IIIで使う実Digest

第一候補は、工程Iで使用した161.033秒・32字幕のDigestと、その**字幕焼込前の基礎媒体**である。

着工時に次を確認する。

- 字幕焼込前の基礎媒体が現存し、既知SHAと一致する
- 32字幕のnormal plan／context／音響候補・peak証拠が現存する

## 10. 自動判断の実行方法

工程IIIの実Digestでは、開発者が最終presetを手配置しない。

### 10.1 一回の新しい判断として固定する

- 現行の全字幕、前後文脈、音響候補、peak
- 全接続と前後の文脈
- 各presetの物理的適用可能性
- 採用状態／技術候補状態

を、今回の判断入力として保存する。

過去の工程I割当を正解ラベルとしてコピーしない。ただし既存の意味根拠・観測データそのものは再利用してよい。

AI回答を保存 → schema／参照／意味境界を検証 → 許容preset集合を固定 → variation resolverで具体presetを決定 → **固定自動案として保存**する。

最初の回答が構造不正なら、失敗した回答と理由を保持して範囲内で訂正する。無制限に繰り返したり、人間が最終presetを手で当て込んで「自動成功」と記録したりしない。通常の限定修正は本人承認待ちにしない。

手修正0の候補動画を最初に作る。

### 10.2 未解決を隠さない

- unresolved
- unrepresentable
- Normal判断

を区別する。

unresolved／unrepresentableが画面上Normalでrenderされても、「Normalと判断した」件数へ合算しない。

## 11. QCと故障注入

既存QCを再利用し、工程IIIで増えた境界だけ追加する。

### 11.1 共通時計

最低限、次を拒否する実故障を作る。

1. 接続後の字幕shiftを1回抜く
2. 同じ字幕へshiftを二重適用する
3. Pulse peakだけ旧時計のまま残す
4. Bounce／Shake開始を投影前frameのままにする
5. 接続override変更後も旧projectionをreuseする

### 11.2 合成順

次を区別できるfixtureを作る。

- 正：基礎映像へSoft → 投影済み字幕をoverlay
- 誤：字幕焼込後のframe全体へSoft

Soft窓内に字幕が存在するfixtureで、正しい経路では字幕overlayの画素がSoftの黒係数で暗くならないことを実画素で確認する。

### 11.3 保存locality

- caption overrideだけ変更
- connection overrideだけ変更
- 両方変更
- captionだけReset
- connectionだけReset
- 両方Reset

を異なる順序で行い、保存状態と最終planが期待どおり収束することを確認する。

順序が独立な操作はcommuteすること。Resetは再判断を起こさない。

### 11.4 variation resolver

- 同じ入力 → 同じ選択
- item ID違い → hash domainが別
- orchestration version違い → 別版として明示的に変化可能
- 許容集合の順序が外部入力順で揺れても、stable sort後に同じ結果
- 候補外presetを絶対に出さない
- 1候補なら常にその候補
- 件数quotaやglobal countへ依存しない

を検査する。
