# 工程IIの接続表現一覧

工程IIで扱う有限な接続表現と、工程IIIへ渡す統合事項を整理する。通常カット・12frame黒の採用状態を保持し、黒を経由する短い映像フェードを一種類追加する。Soft Separatorは仮称であり、技術候補を描画することと、人間が名称・見心地を採用することは別に扱う。

今回の範囲は[工程II実装指示書](digest-connection-expression-stage2-sources-20260918/work-order-v001.md)。工程Iの字幕表現は[既存の一覧](digest-caption-expression-catalogue-20260918.md)を引き継ぐ。本書の有限仕様は実装・検査対象を示すもので、検査結果や人間の品質評価を先行して記録するものではない。

## 1. 役割・描画・採用状態

| 表現 | 役割 | 外観と時間の変化 | 有限preset・版 | 採用状態 |
|---|---|---|---|---|
| Normal Cut（通常カット） | 通常につなぐ | 前区間から後区間へ、そのまま切り替える。frame・音声sampleを追加しない | `normal-cut` / `v001` | 採用済み。今回再認定しない |
| Black Separator（既存黒） | 区切る | 12frameの黒を挿入し、次の場面へ切り替える。音声は挿入分だけゼロを加える | `black-separator` / `v001` | 採用済み。黒の可否を再研究しない |
| Soft Separator（仮称） | 区切る | 保持映像の末尾6frameで黒へ移り、12frameの黒を挿入し、次の保持映像の先頭6frameで元の画素へ戻る | `soft-separator` / `v001` | 工程IIの新しい有限候補。小型実素材で技術検査合格。正式名称・デザイン・人間品質の採用は未決 |

「通常につなぐ」「区切る」という役割と、黒・フェードという具体的な見せ方を分ける。Soft Separatorを新しい感情分類にはしない。通常カットと黒を再現可能なランダムで併用する上位方針は保持し、今回の技術手指定を全体の自動選択規則へ読み替えない。

## 2. Soft Separatorの有限仕様

対象は30fps、8bitのYUV420p。黒の数値はlimited rangeのY=16、U=128、V=128に固定する。既存短尺には色域・色変換のタグが記録されていないため、タグ未記録を許容して画素値をそのまま処理する。明示されたfull rangeやYUVJは対象外とし、色域変換を挟まない。前後の場面を混ぜず、それぞれの元frameと黒の間だけを変化させる。

| 対象 | frame順の保持係数 | 端点の意味 |
|---|---|---|
| 前区間の末尾6frame | 5/5、4/5、3/5、2/5、1/5、0/5 | 最初は元画素と同じ。最後は完全黒 |
| 挿入する12frame | すべて完全黒 | 元動画のframe参照を持たない追加区間 |
| 後区間の先頭6frame | 0/5、1/5、2/5、3/5、4/5、5/5 | 最初は完全黒。最後はその時点の元画素と同じ |

各画素成分の計算は、係数の分子を0〜5の整数として、次の一式に固定する。

```text
出力画素値 = floor((元画素値 × 係数の分子 + 黒値 × (5 − 係数の分子) + 2) / 5)
```

最後に小数部分を切り捨てる。係数はこの有限描画の仕様であり、品質点数・合否の救済・入力ごとの最適化には使わない。外部の割当から任意の長さ、色、係数、曲線、音量、filter式を受け取らない。

前後のフェードは、元から保持するframeへの画素処理である。各frameの件数・順序・元動画との対応を保ち、静止frameの複製や区間の切詰めで時間を作らない。時間として増えるのは黒の12frame、30fpsで0.4秒だけである。240frameの入力へ一接続を適用する場合の予定出力は252frameとなる。

### 挿入した黒と、完全黒が続く長さ

新たに挿入する黒は12frame。一方、直前の保持frameと直後の保持frameにも係数0/5を適用するため、仕様が作る連続した完全黒は**保持端点2frameを含む14frame**となる。これは14frameを追加するという意味ではない。元映像が周辺でも黒い場合、実画素として観測する連続黒はさらに長くなり得るため、実測値と挿入数を分けて記録する。

フェード窓の外は元frameとの完全一致を要求する。窓内は、対応する元frame・所定の係数・黒値・丸めから計算した期待画素と照合する。圧縮後のH.264画素と可逆中間物の画素が完全一致するとは扱わない。

## 3. 三つの時計と音声

| 時計 | 基準 | 接続処理での扱い |
|---|---|---|
| 元動画の時計 | 既存の素材参照と保持判断 | 元時刻・保持区間・順序を変更しない |
| 保持後・挿入前のDigest時計 | 正本の保持時間表と字幕計画 | 接続の同一性、前後区間、元境界を固定する基準として保つ |
| 挿入後の表示時計 | 元入力から一度だけ解決した挿入時間表 | 保持映像・音声・字幕を、先行する挿入分だけ後ろへ移す |

時間区間は開始を含み、終端を含まない。境界で終わる字幕は前側に残し、境界から始まる字幕は挿入後の後側へ置く。字幕の開始と終了へ同じ挿入量を加え、本文・改行・ID・元の表示長・元対応を保つ。移動済みの計画へさらに挿入量を足さず、常に束縛済みの元入力から計算する。

今回の音声条件は48kHz・2chのfloat32 PCM。映像1frameに1,600sample/channelが対応し、黒12frameには19,200sample/channelの厳密なゼロを挿入する。保持PCMは全量の値・順序・チャンネルを保つ。映像の前後フェードに音声fadeを付けず、音量調整・crossfade・再sample・click補修も行わない。工程Iの44.1kHz条件と混同しない。

最終H.264/AACでは、音声packetの時計、duration、先頭skip・末尾padding、実復号sample数、予定終端を越えた復号末尾、挿入区間と前後の実復号状態を分けて観測する。過去素材の末尾+256sampleや挿入端の非ゼロ384sampleを今回の期待値にはしない。AACの非ゼロ値だけで可聴性を判断せず、音声の滑らかさが改善したとも主張しない。

## 4. 字幕に及ぶ作用

今回の小型実証では、既存の焼込字幕を含む保存済み短尺へ全画面のフェードを掛ける。したがって、窓内の字幕画素も映像と一緒に黒へ変化し、後側で戻る。字幕本文・表示時計の保持は、字幕画素・可読時間の不変を意味しない。

この作用は接続表現の一部であり、新しい字幕presetではない。工程Iの字幕保存・動作処理を変更せず、焼込済み動画から字幕を除去しない。将来の映像と字幕の合成順は、工程IIIで別に定める。

## 5. 保存・一件変更・Reset

元Digestの版・SHA、元の字幕計画と保持時間表の生byteのSHA、前後の保持区間、挿入前の境界、選択したpresetと版を照合する。字幕と接続を混ぜた旧保存物を新しい保存正本へ読み替えない。

保存済み原案は不変とし、変更指定は原案のSHAに結び付けて別保存する。Resetは対象一件の変更指定を削除する操作である。原案がSoft SeparatorならSoft Separatorへ、既存黒なら既存黒へ戻り、常に通常カットを設定する処理にはしない。他の接続の指定を保ち、元入力から表示時計・画素列・PCMを再解決する。

開発fixtureの原案と変更指定は技術手指定として記録する。実AIの判断、人間の評価、全体の自動割当の証拠にはしない。

## 6. 対応しない入力は拒否する

- 元Digest、元計画、保持時間表、原案またはpresetの版・SHAが一致しない入力。
- 未知ID、非隣接の前後区間、実時間表と異なる境界、同一接続の重複、未知の役割・preset・自由描画値。
- 30fps・48kHz・2ch、所定の画素形式・色域に適合しない媒体。黙って変換して通さない。
- 前後6frameの窓がそれぞれの保持区間に収まらない入力。
- 元の保持frame上で二つのフェード窓が重なり、同じframeへ二重に作用する入力。
- 挿入する境界を跨ぐ字幕。切詰め、移動、本文分割、表示長の延長で救済しない。
- 既に表示時刻を移した計画を元入力として渡すなど、正本の生byteと実際に処理する内容が異なる入力。

適用不能を通常カットへ自動置換しない。技術上の適用不能と、表現の人間採用は別の状態として残す。

## 7. 出力例・技術結果の記録範囲

使用する実例は既存接続1・2・11の保存済み短尺。3例はいずれも240→252frameとなり、一候補にまとめた実測は756frame・25.2秒だった。各例の開始位置と対象境界を主報告に記録した。例どうしの梱包用の連結は元Digestの実接続ではなく、新しい接続能力として数えない。

[工程II主報告](digest-connection-expression-stage2-20260918.md)と[軽量証拠](digest-connection-expression-stage2-evidence-20260918.json)で、3実例各252frame、窓外228frame・窓内12frame・黒12frame、保持PCMと無音、保存／Reset、通常／黒の回帰を確認した。四つの実故障は画素不一致として拒否された。候補は756frame・25.2秒、SHA-256 `38fe5cb7e5a4bd546a667926f71d98815af1dc848242d947d620f205ceb3d662`。AACの復号末尾は予定終端より768sample/channel長く、可逆PCM保持と分けて記録した。

技術成立だけで、人間の見心地、音の自然さ、字幕の読みやすさ、既存黒より優れた表現、自動選択の品質を認定しない。通常file入口の正式受入、renderer正式版、trust再発行は別管理事項として残す。

## 8. 工程IIIへ渡す最小統合の残件

| 残件 | 工程IIIで明確にする処理 |
|---|---|
| 映像と字幕の合成順 | 焼込前の基礎映像へ接続を適用してから字幕を描くか、どの画素へ接続効果を掛けるかを定める |
| 共通表示時計 | 映像、PCM、字幕の開始・終了、接続の挿入を同じ時間表へ投影する |
| Pulseの根拠ピーク | 元の音声ピークとの対応を保ったまま、挿入後の表示時刻へ移す |
| Bounce／Shakeの開始基準 | 字幕の開始を表示時計へ投影し、その開始から有限動作を一度だけ実行する |
| 接続と字幕の変更指定の独立性 | 一方の変更・Resetで他方の割当や見た目を失わず、必要な共通時計の再計算だけを行う |
| 表現の全体使い分け | 採用状態・適用可能性を材料に有限表現を選択し、保存した具体presetと選択根拠を残す |

工程IIは、接続表現を一種類増やして次へ渡す工程である。上記の全面統合や全Digestの再生成を、今回の小型技術実証で完了したとは記録しない。
