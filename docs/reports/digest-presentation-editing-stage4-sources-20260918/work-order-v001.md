## 4. 最小の操作画面

一つの動画・編集状態を開き、動画プレイヤー、対象一覧、選択対象の操作、保存・確認・全編出力の状態が分かる画面にする。汎用タイムラインや自由なドラッグ編集は不要。

対象は次の方法で探せるようにする。

| 入口 | 必要な動作 |
|---|---|
| 動画の再生位置 | その位置の字幕、接続、近傍の対象を示す |
| 字幕文の検索 | 原文を検索し、同文が複数ある場合は時刻・前後文で区別する |
| 字幕・接続の一覧 | 表現名、変更の有無、未解決等の状態から絞り込む |
| 接続の選択 | 前後の字幕・場面情報と、現在の接続表現を表示する |

内部IDは詳細情報として保持してよいが、操作の前提にしない。

一覧から選ぶと該当箇所へ移動でき、再生位置から対象を選んでも同じ安定IDへ到達すること。字幕が存在しない時刻を、勝手に近い字幕への変更として処理しない。

## 5. 表現の追加・変更・削除・Reset

### 字幕

Normal、Color、Scale、Panel、Pulse、Bounce、Shakeを対象にする。技術試用中の表現には、その状態を表示する。

自動ではNormalだった字幕へ演出を追加する操作も必須とする。削除だけできる画面にはしない。

Colorは全文と一つの連続範囲を選び直せること。利用者には文字列上で指定させ、内部では既存の原文一致・出現位置・書記素境界へ変換する。同語反復・改行・結合文字・絵文字の扱いを維持する。対象文字列が曖昧なら別の出現へ近似適用しない。

Pulseには既存の実在する適格ピークが必要である。利用者が生のpeak IDを入力する方式ではなく、適格な候補を時刻等で示して選べるようにする。勝手に新しい発火時刻を作らない。

### 接続

Normal Cut、Black Separator、Soft Separatorの変更を扱う。接続の追加・削除や保持区間の組替えではなく、既存の接続IDに対する見せ方の変更とする。

### 共通の操作意味

| 操作 | 保存する内容 |
|---|---|
| 通常表示へ固定／演出を外す | 対象一件に明示Normalを保存 |
| 別の表現へ変更 | 対象一件に有限presetを保存 |
| Color範囲を変更 | 対象一件の有効な連続範囲を保存 |
| 自動案へ戻す | 対象一件のoverrideだけを削除 |

AIの許容集合は自動選択の判断であり、利用者の修正可能範囲そのものではない。利用者が自動案と異なる表現を指定できるようにする。ただし、有限preset、物理的適用条件、文字範囲、Pulse根拠等の既存検査は通す。

適用不能の表現は理由を表示する。収まらないものを勝手に縮小したり、別の表現やNormalへ変更して保存したりしない。

## 6. 保存と局所性

字幕自動案、字幕override、接続自動案、接続overrideの独立性を維持する。判断根拠も変更しない。

編集は利用者用の作業状態に保存し、工程IIIで確定した無修正自動候補とその証拠を上書きしない。

一件の保存では、その系統のoverrideだけを変更する。別の字幕・接続の指定を再配置しない。接続変更で後続字幕の表示時刻が変わることは許されるが、後続字幕の表現選択やColor範囲が変わることは許されない。

保存処理は、描画完了を待たず終了できるようにする。変更と再出力は別操作にする。

保存失敗や途中終了で既存状態を壊さないよう、検証後の安全なファイル更新を行う。同じ編集状態への書込みは直列化し、古い画面からの保存で新しい変更を無言で上書きしない。大規模な履歴管理や共同編集は不要で、期待する編集版との一致確認でよい。

再読込み・プロセス再起動後も、保存済みの変更と対象版を復元できること。ブラウザー内の一時保存だけを正本にしない。

## 7. 保存版と再生版を区別する

ここは今回の必須機能とする。

画面では、少なくとも次を別々に表示する。

画面上の未保存変更、保存済み編集状態、再生中動画を作った状態、実行中の確認／全編出力が使用する状態。

表示例は「保存済み変更あり・再生中の全編には未反映」「この周辺だけ最新状態で確認済み」でよい。利用者にhashの読み比べを要求しない。

内部では、入力・固定自動案・両override・描画規則・投影・出力範囲を識別できる参照へ束縛する。表示用の版番号だけで一致を判断しない。

特に接続変更では、後続の表示時刻が変わる。旧動画の再生時刻を、新しい編集状態の表示時刻として直接検索してはいけない。

再生中動画の対応表から安定した字幕ID／接続ID／元時計へ戻し、その対象を現在の編集状態で開く。挿入された黒の中なら、所有する接続へ対応させる。短い確認動画では、確認動画内時刻と全編表示時刻の対応も保持する。

## 8. 周辺確認は同じ描画経路の範囲限定にする

周辺確認を別の簡易rendererやブラウザーCSSによる見た目の模倣で済ませない。

工程IIIと同じ有限preset・時計・合成順で、対象範囲だけを描画する。

### 確認する範囲

字幕は対象の表示期間と前後の文脈、接続は境界前後とフェード窓・挿入区間を含める。初期の文脈余白は前後各2秒を基準にしてよいが、機械的な上限にはしない。

必要な前後状態が見えない場合は、対象の動作・復帰・隣接字幕が確認できる範囲へ広げる。利用者が文脈をもう少し見たい場合に範囲を広げられればよく、自由な動画編集機能にはしない。

### 切り出しで動作を再開始しない

全体の接続計画と保存状態を先に解決し、その表示時計上の範囲として確認出力を作る。

確認範囲が字幕の途中から始まっても、Bounce／Shakeをその位置から再発火させない。Pulseのピーク、既存fade、字幕の残り表示時間も元の進行状態を保つ。

共通rendererへの範囲指定や描画用の時刻原点は追加してよい。ただし、投影済み計画を新しい原時計の正本と偽って再投入しない。元正本・全体投影・確認範囲・局所時刻の関係を追えるようにする。

### 周辺確認の仕事量を限定する

周辺確認の前提として、全編の再描画や全編QCを毎回実行してはいけない。

字幕だけの変更では、接続済み背景を再利用できる範囲を確認する。接続を変更した場合も、元入力と新しい投影から必要な周辺を作り、全編背景の再生成を必須にしない。

同じ状態・範囲・描画規則の結果は、整合性を確認して再利用してよい。新しい汎用cache基盤は作らない。BlackとSoftは同尺でも別結果であり、尺やファイル名だけで再利用しない。

### 音声と検査

44.1kHzの再生時計と16kHzの観測時計を混同しない。確認範囲の音声は、表示時計に対応するsample範囲から作る。AACの遅延・末尾余りを字幕やピークの位置へ加算しない。

周辺確認の圧縮動画と、全編動画を後から切り出したものに、MP4全byte一致は要求しない。一方、圧縮前の対象状態・時刻・合成順・音声範囲は一致させる。

周辺確認は「この範囲の確認」として表示し、全編QC合格や全編反映済みへ読み替えない。

## 9. まとめた全編出力

複数の変更を保存・周辺確認した後、一回の操作で、その保存状態から全編を出力できるようにする。

最初は、一つの編集対象について描画jobを一件ずつ実行する方式でよい。複雑な並列job管理は作らない。

job開始時に使用する状態を固定する。処理中に次の変更を保存できても、実行中jobの入力を書き換えない。完成した動画が旧状態なら、その版の出力として保持し、現在の編集状態に反映済みと表示しない。

途中失敗では、最後に成功した動画と保存済み編集状態を保持する。失敗した出力を完成品へ昇格させない。同じ状態から再試行できるようにする。

正式file入口やtrustの更新をこの工程に混ぜず、利用者向け画面から既承認の共通描画入口まで実際につながることを確認する。

## 10. ローカル操作環境の範囲

既存のZEV画面・ローカル起動方式を優先する。必要であれば、同じ利用者環境内の薄い画面と操作用処理を追加してよい。ローカルサービスが必要な場合はloopbackに限定し、外部公開・外部サービス接続をしない。

ブラウザーへ任意のファイルパスやコマンドを実行できる入口を公開しない。登録済みの編集対象と出力範囲へ限定し、外部からの書込み要求、範囲外path、字幕文からのスクリプト実行等を拒否する。

依存の新規取得は行わず、導入済みの部品を使う。

実ブラウザーでの操作検証を行う。以前のfile URL拒否など、ツールの安全方針をこの指示で無効化しない。拒否された場合は同じ操作を別経路で迂回せず、許可された既存の起動・操作方式を確認する。それでも必要な検証ができない場合は、その部分だけ同じ相談役へ具体的に相談し、保存・描画・検査等の独立作業は続行する。

「ブラウザーで未検証」の静的ページだけを、操作環境完成として報告しない。

## 11. 実装順と検証

最初から画面を作り込まず、実操作の一往復を先に通す。

まず一件の字幕変更で、画面→保存→別processで再読→周辺描画→画面再生まで通す。その後、接続変更、Color範囲、Pulse、版管理、まとめ出力へ広げる。

以下を、単体・小型媒体・実Digestの適切な層で確認する。すべての操作について全編を再encodeする必要はない。

| 検証のまとまり | 必須内容 |
|---|---|
| 対象探索 | 再生位置、字幕検索、同文の複数出現、接続一覧から正しい安定IDへ到達する |
| 基本編集 | 自動Normalへの追加、表現変更、Normal固定、Color範囲変更、Resetが画面から通る |
| 適用条件 | 不正範囲、不適格ピーク、短過ぎる字幕、画面外等を拒否し、前の保存状態を保つ |
| 独立保存 | 字幕／接続の変更とResetを両順序で行い、他方の固定案・overrideを変えない |
| 版と再生 | 未保存・保存済み・再生中・処理中を区別し、旧動画の時刻から誤対象を編集しない |
| 周辺の時刻 | 字幕途中からの確認、非ゼロ移動後のPulse、Bounce／Shake、Soft窓、挿入区間を正しく描く |
| 古い結果の拒否 | 同尺Black→Soft、変更中job、古いpreview・cache、保存競合を誤って最新扱いしない |
| 失敗と再開 | 保存失敗・描画失敗・画面再読後も、最後の有効状態と完成動画を失わない |
| 全編反映 | 保存済みの複数変更を一つの修正後Digestへ反映し、QCと対象版の一致を確認する |

工程IIIの実Digestを利用者向け操作の実証対象にする。品質判断のための手修正ではなく、動作検証用の修正であることを記録する。

少なくとも字幕側と接続側の変更を含む修正後の全編候補を一度、実際に生成する。全表現の操作確認や異常系は小型試験で補い、各操作ごとの全編生成はしない。

Reset後の保存・全体計画の復元を確認する。元の自動状態と完全に一致した場合に、保存済みの検査済み全編を再利用する方式は許可する。その場合は「再利用」と記録し、「Reset後に全編を再生成した」とは書かない。

## 12. 待ち時間を測り、重い経路を残さない

対象探索、保存、確認範囲の準備、描画、範囲QC、再生可能になるまで、全編出力を分けて計測する。初回と再利用時も分ける。

自動操作による探索時間を、人間が実際に判断した時間と呼ばない。

最低限、実Digestで次を測る。

字幕の一件変更、接続の一件変更、同じ保存状態・範囲の再確認、複数変更後の全編出力。

数値を記録しただけでは完成にしない。次の構造上の問題があれば、この工程内で修正する。

- 保存ボタンが描画終了まで返らない。
- 周辺確認のたびに全編を作り直す。
- 同じ背景・PNG・同じ確認結果を、必要性なく再生成する。
- UIが止まり、処理中か失敗か分からない。
- 古い結果が新しい結果に見える。

## 13. 未管理データを再発させない
