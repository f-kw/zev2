## 2. 意味役割と描画presetを分ける

| 意味役割の案 | 意味上の責任 | 描画側の責任 |
| --- | --- | --- |
| Normal Cut | 追加の区切りを置かず、確定した前後区間をそのままつなぐ。固定基準は全接続がこの状態 | その境界での挿入0。他の境界の挿入による表示時間の移動は共通時間表に従う |
| Separator | 前後を別のまとまりとして受け取れるよう、区切りを明示するという仮説を表す | 束縛した有限presetから具体的な映像・音声・長さを決める |

Normal Cutは「人間が自然と認定した」という評価を含まない。Separatorも、画素差が大きい、元時間の省略が長い、Prospectが違うというだけでは自動選択しない。なぜ区切りが必要かという意味上の理由と、使った証拠を原案へ残す。観測されていない見心地を理由の事実欄へ追加しない。

研究で成立した具体表現は、旧処理が持つ12frameの黒と同じ長さの無音挿入だけである。30fps・48kHzでは0.4秒・19,200sample/channelに対応する。これは**Separator用の研究候補**であり、Separatorという役割の定義を「12frame黒」に固定しない。採用する長さ・画面・音声の仕様は版付き描画presetの責任とし、最終採用は未定。

接続の役割と描画presetは別々に版とSHAを束縛する。意味上の指定が同じでもpresetを変えた結果は別の実行入力として扱い、既存の承認やQCをそのまま引き継がない。今回は汎用的な演出言語、大きなregistry、任意パラメーターの受付を設けない。

## 3. 入力schemaの案

以下の型名・field名は責任境界を説明するための案であり、正式schema名・保存pathを新設するものではない。型と値の正式化は本番着工時に行う。未定義fieldは拒否する方式を前提とする。

### 3.1 正本と接続一覧を束縛する入力

| 保存する単位 | 必要なfieldの案 | 意味 |
| --- | --- | --- |
| 正本Digestへの束縛 | `digestVersion`, `completionId`, `completionRef`, `finishedMediaRef`, `retainedMediaRef`, `retainedTimelineRef`, `canonicalCaptionPlanRef` | 完成Digestの版・完成記録・完成MP4と、その完成記録につながる基礎媒体・保持時間表・元字幕計画を固定する。参照はpathとSHA-256の組 |
| 接続一覧 | `schemaVersion`, `canonicalDigestRef`, `connections` | 正本の保持時間表から隣接関係だけを決定的に列挙する。新しい区間や順序は作らない |
| 接続1件 | `connectionId`, `beforeSegmentId`, `afterSegmentId`, `canonicalBoundaryFrame` | 正本の挿入前時計で、前区間終端と後区間開始が一致する境界を指定する |

接続の同一性は、**正本Digestの版・SHA、前後の保持区間ID、正本の境界frame**の組で確定する。接続IDはその一覧の中だけで有効な参照とする。一覧番号や現在の表示秒数だけでは対象を確定しない。前区間終端と後区間開始の不一致、非隣接、同一境界の重複、正本と異なる版への流用を拒否する。後から挿入時間が変わっても、この同一性は移動しない。

正本の完成MP4だけで、字幕の見た目を独立に変更できるとは扱わない。既存研究は焼込済み字幕を含む画素を保持している。本番で接続と字幕の見た目を両立させる案では、完成記録に束縛された**焼込前基礎媒体・保持時間表・元字幕計画**を製造入力にする。焼込済みMP4から字幕を除去したり、別媒体を黙って代用したりしない。必要な基礎媒体との束縛が成立しない場合は、本番入口の設計未成立として停止する。

### 3.2 AIが返せるのは対象・意味・理由だけ

```ts
type ConnectionChoiceDraft = {
  connectionId: string;
  role: 'normal-cut' | 'separator';
  reason: { text: string; evidenceIds: string[] };
};
```

AIへ渡す判断材料は、固定した接続一覧、既存の保持構造・字幕・許可された観測記録など。AIはその証拠一覧のIDを理由に引用する。本文の説明は描画命令として解釈しない。色、frame数、ms、fade、音量、座標、任意filter、描画presetの選択値をAI出力へ追加させない。独自の係数・閾値・重みや総合点から役割を決める規則も追加しない。

正本の束縛、役割語彙の版、判断実行への参照、原案全体の版・SHAは、検査して保存する処理が外側へ付ける。AI自身が描画値や正本SHAを作り直す責任は持たない。固定AI原案を使うモードでは、接続一覧の全件に1件ずつ判断があることを要求し、欠落・重複・未知の証拠参照を拒否する。実際のAI判断がない研究用配置は、その作成者と「仮説fixture」を記録し、AI実走の原案と偽らない。

### 3.3 三つの保存状態と解決要求

| 保存単位 | fieldの案 | 所有する内容 |
| --- | --- | --- |
| 固定Normal基準 | `canonicalDigestRef`, `connectionCatalogueRef`, `baselineVersion` | 正本の全接続を通常カットとする不変の基準。人間の品質採用を意味しない |
| 固定AI原案 | `schemaVersion`, `canonicalDigestRef`, `connectionCatalogueRef`, `roleVocabularyVersion`, `judgmentRef`, `choices` | 検査済みの全件判断と理由。保存後の編集・Resetで再判断しない |
| 接続の人間override | `schemaVersion`, `baseSelectionRef`, `revision`, `entries` | 対象基準または固定AI原案へ束縛した、変更対象の接続ID・意味役割・人間の理由。指定した接続だけを保持 |
| 接続の解決要求 | `canonicalDigestRef`, `connectionCatalogueRef`, `normalBaselineRef`, `selectionMode`, `aiDraftRef`, `humanOverrideRef`, `renderPresetRef` | どの不変入力の組から実効指定と表示時計を作るか。参照はすべて版・SHAに束縛 |

`selectionMode`は「固定Normalのみ」または「固定AI原案を使用」の二択とする案。前者だけはAI原案への参照を明示的に空にできる。後者で参照先が失われた、判断が未完了だった、SHAが違った場合は拒否する。読めないAI原案を「原案なし」と解釈してNormalへ落とさない。原案を新しく作り直す操作は、Resetとは別の版更新であり、この草案では自動実行しない。

人間overrideは同じ接続IDにつき最大1件。接続を通常へ変更した場合も、その明示指定を保存する。人間の理由は既存の指示・操作記録への参照で足り、自由記述の入力を必須にしない。役割にResetやinheritは追加しない。Resetは保存行を削除する操作であり、描画時に選ぶ第三の表現ではない。

## 4. 三層の解決とReset

各接続について、固定Normal基準、保存済みAI原案、人間overrideの順に重ね、その接続に最後に存在する指定を実効結果とする。人間指定がない接続は固定原案へ戻り、明示的なNormalのみモードなら固定Normal基準へ戻る。この順序は編集した時刻や配列順に依存させない。

| 固定AI原案 | 人間指定 | 実効結果 | その接続をResetした後 |
| --- | --- | --- | --- |
| Separator | なし | Separator、理由はAI原案 | Separatorのまま |
| Separator | Normal Cutを明示 | Normal Cut、理由は人間指定 | **Separatorへ戻る** |
| Normal Cut | Separatorを明示 | Separator、理由は人間指定 | Normal Cutへ戻る |
| なしと明示したNormalのみモード | Separatorを明示 | Separator、理由は人間指定 | 固定Normalへ戻る |

Resetの手順は次のとおりとする案。

1. 操作対象の接続ID、対象の固定原案またはNormal基準、現在の人間指定の版・SHAを照合する。
2. 対象1件の人間指定だけを除いた次の保存状態を作る。別接続の指定と字幕側の保存状態は変えない。対象指定が既になければ状態は変わらない。
3. AI原案を使うモードでは固定原案を、Normalのみモードでは固定基準を読み直す。AIへ問い直さず、理由も再生成しない。
4. **正本Digestの不変入力から、残った全接続を毎回再解決する。** 前回の派生動画、移動済み字幕、挿入済み時間表を入力にしない。
5. 新しい実効指定・時間対応・来歴を出力する。壊れた参照や不整合なら新しい実行候補を確定せず、既存の保存物を保持して拒否理由を返す。

「他の指定を保持する」と「他の表示時刻が動かない」は異なる。手前のSeparatorがなくなれば後続の表示時刻は短くなるが、他の接続の意味役割・理由と字幕の見た目の指定はそのまま保つ。移動量の差分を前回の時刻から手で引く方式にしない。実効結果には採用元も残し、人間がNormalへ変えた箇所で、AIのSeparator理由を現在の指定理由として表示しない。

## 5. 字幕の見た目との分離

接続の固定原案・人間指定は、字幕presentationの固定原案・人間指定とは別の保存物にする。接続のResetで字幕の指定を消さず、字幕のResetで接続の指定を消さない。

解決処理も次の責任に分ける。

1. 接続の解決は、元の保持時間表と接続指定から映像・音声共通の挿入時間表を作る。
2. 字幕の時間投影は、元字幕計画とその挿入時間表から表示開始・終了を一度だけ移動する。
3. 字幕presentationの解決は、既存字幕IDに対して見た目だけを決める。接続の役割・長さ・保持区間・字幕時刻を変更しない。
4. 製造入口が同じ字幕IDで時間と見た目を結び、描画後の検査へ渡す。

旧実装は[共有型](../../packages/shared/src/presentation-effects.ts#L1) L1–12と[解決処理](../../evals/clip_composition/presentation_effects_v001.mjs#L26) L26–98で字幕と接続を同じobjectへ入れている。本番案ではこの混在形式を受付ける互換分岐・自動変換を作らない。旧処理は研究の比較基準として保持し、再利用する計算部品も新しい分離入口の検査後にだけ呼ぶ。旧objectを内部で再構成すれば分離を実装したことになる、とも扱わない。

## 6. 三つの時計と保持する値

| 時計 | 所有者 | 接続処理ができること |
| --- | --- | --- |
| 元動画の時計 | 既存の素材参照・保持判断 | 確定済みの対応を参照する。元時刻や採用区間を推定し直さない |
| 保持後・挿入前のDigest時計 | 正本の保持時間表 | 接続同一性と字幕時刻の基準として不変保持する |
| 挿入後の表示時計 | 接続の決定的な解決処理 | 有効な挿入だけを加え、保持frame・音声sample・字幕の対応を出力する |

区間は開始を含み終端を含まない。保持frameの表示位置は、そのframeまでの正本境界に置いた挿入frame数の合計だけ後ろへ移る。映像と音声で別々の丸めや累積秒計算をしない。研究条件は30fps・48kHz、1映像frameにつき1,600sample/channel。元60fpsからの対応も、既存時間表の規則をそのまま参照する。本番で別のfpsやsample rateを扱う契約は未定であり、未対応条件を近似して通さない。

保持する条件は次のとおり。

- 接続処理の前後で、保持映像の全frameの値・件数・順序、復号float32 PCMの全sampleの値・件数・チャンネル順を保つ。再サンプリング、fade、crossfade、音量変更、保持frameの複製・削除・並べ替えはこの接続案に含めない。
- 追加できるのは、束縛済みpresetが定める挿入区間だけ。挿入frameとsampleに元動画の参照を作らない。表示時計上の位置、対象接続、presetへの参照で来歴を持つ。
- 保持区間には、表示位置から挿入前Digest位置、既存時間表による元動画位置へ戻れる対応を残す。元素材の論理対応と、元素材との画素・PCM一致は別の主張にする。
- 字幕は、本文・改行・順序・元動画時刻・表示長・字幕IDを保つ。開始と終了に同じ挿入量を加える。境界で終わる字幕は前側、境界から始まる字幕は挿入後の後側へ置く。挿入境界を跨ぐ字幕は、伸長・分割で救済せず拒否する。
- 本番で字幕の見た目を変える場合、画素不変を確認する対象は**同じ表現状態の基礎媒体から接続後・字幕描画前まで**とする。変更した字幕を描いた最終画素と、別の字幕を焼き込んだ旧Digestの完全一致は要求しない。
- H.264/AACへの再圧縮後のbyteや復号sampleが可逆中間物と一致するとは主張しない。可逆中間物での保全、圧縮後の時計・padding・decode状態を分ける。既存黒の確認MP4では末尾256sampleと挿入両端の非ゼロ値を観測済みであり、これを消えた問題として扱わない。

映像と音声を同じ時間表から切出して連結する根拠は[旧filter構築](../../evals/clip_composition/presentation_effects_v001.mjs#L119) L119–139、字幕の等量移動と跨ぎ拒否の根拠は同L81–96。これらは計算部品の再利用根拠であり、本番の新しい入力境界が成立した証拠ではない。

人間が確認する実行前下書きには、変更する接続と意味上の理由、使う有限表現、元内容を保持する範囲を提示する。JSON閲覧や長文入力を主導線にしない。承認後の型付き実行命令は、その時点の入力参照の組へ固定する。承認後に人間指定・原案・presetが変われば別の実行入力であり、既存命令を同じ意味のまま更新したことにしない。この承認境界の正式な型と既存jobへの接続は未実装。

## 8. QCとfail-closedの配置

| 層 | 検出する故障 | 確認方法の案 |
| --- | --- | --- |
| 入力の受入 | 別Digest、古い原案への流用、不明な接続、非隣接、重複、未知の役割・preset、任意描画値の混入 | exactな型・ID・版・SHA・隣接関係を検査。欠落や不正をNormalへ置換しない |
| 三層の解決 | Resetが原案を消す、AIを再実行する、明示Normalを未指定扱いする、他の指定を失う | 小さい保存fixtureで、各層の優先順とReset後の保存状態・採用理由・再解決結果を確認 |
| 時間対応 | 二重shift、保持frame/sampleの欠落・重複、字幕長変更、元参照の捏造、字幕跨ぎ | 全保持区間と字幕の整数時計・元対応を一度計算して照合。順序の違う編集から同じ保存状態へ到達しても同じ結果になることを確認 |
| 接続rendererの回帰 | 計画は正しいが切出しや連結が壊れる、挿入が予定と違う | 小型可逆fixtureの全frame・全float PCM比較と実時計検査。今回の証拠を再利用し、三層統合分は別の未検証事項として残す |
| 字幕の描画 | 指定した見た目が表示領域を外れる、時間投影と別の字幕へ結び付く | 字幕側の既存データ・実画像検査へ、投影済み時刻と同じIDで渡す。接続側から本文や見た目を修正しない |
| 完成MP4 | stream・寸法・fps・予定frame数・音声・padding・decodeの不整合 | 既存の通常媒体QCへ接続。AACの圧縮差を可逆保全の検査結果へ混ぜない |
| 品質評価 | 意味上の区切りが有効か、長さ・テンポ・音が自然か | 技術合格とは別に記録。研究の設計完成を人間の品質合格と表現しない |

研究で行った全11窓の精密比較を、完成動画ごとの全接続再製造や全字幕再符号化へそのまま昇格させない。必要な追加QCは検出する故障と上流で検出できない理由を示して正式化する。ここで新しい数値閾値、許容誤差、点数、強制停止上限を設けない。

異常時は、対象の束縛・実測・拒否理由を保存し、不正な結果を実行候補へ昇格させない。既存の正常な保存物と完成Digestは保持する。勝手な別preset、時間短縮、字幕分割、通常カットへの代替で処理を完了させない。

## 9. 本番導入前に正式化する事項

1. **入力と承認の契約**：完成Digest・焼込前基礎媒体・元時間表・元字幕計画の束縛形式、実行前下書きから型付き命令への固定方法、実行入口と保存path。
2. **最小役割と有限描画能力**：Normal Cut / Separatorという案の採否、役割語彙の版、Separatorの具体表現・長さ・音声仕様。旧12frame黒は候補のまま。
3. **AI原案の生成責任**：どの判断材料から何を理由にSeparatorを選ぶか。仮説を事実や人間評価として扱わない方法、原案未完成時の扱い。自動選択規則は未定であり、数値の大きさから代用しない。
4. **保存と操作**：固定原案と人間指定を別に保持するschema、版違いの編集拒否、Resetの対象1件削除、採用元・理由の表示。旧混在objectを受け付ける互換は作らない。
5. **時計と製造能力**：対応fps・音声条件、挿入区間、字幕投影、可逆保全と最終符号化の検査責任。既存の30fps・48kHzの証拠を他条件へ一般化しない。
6. **本番の受入と着工**：研究fixtureから新三層保存・承認・正式job・renderer・QCへ通す最小統合の範囲と、必要な正式契約・着工判断。今回の草案をproduction実装、Normalの採用、trust／renderer版、main／tag／stable／releaseの変更許可にはしない。

人間観測なしでこの設計草案を完成できることと、Separatorが視聴上有効と確定できることは別である。後者は未判定と記録し、前者の作業を待たせる条件には戻さない。

## 10. 草案の自己点検

- 目的は、既存Digestの内容を保った接続変更と確実な取り消しである。registryや汎用DSLを作るための設計へ拡張していない。
- 正本の版・SHA、前後区間、挿入前の境界で対象を固定し、AIの出力は意味役割と理由根拠に限定した。
- 固定Normal → 固定AI原案 → 人間override → 実効指定を定義し、Resetと明示Normalの違い、他の指定の保持、原入力からの再解決を表で確認した。
- 接続と字幕presentationの保存・解決を分け、時間投影だけを共通の挿入時間表へ結び付けた。
- 既存9物理fixtureと時計検査が証明していない三層統合を明記した。研究条件・物理値の変更、コード実行、媒体生成、本番変更はこの文書作成では行っていない。
- 本書はschemaと工程の提案であり、技術検査の結果や人間の品質合格を新しく作る文書ではない。
