## 動画別のフレーム対応

全て30fps、ゼロ始まり、終端は排他。Beforeは保存済み一件修正版全編（SHA-256 `1454ca54018edcfc16b7139336e60ae28e9f32bc617cb476d87b689cf5afcbb6`）を再利用する。修正版はその編集後の元時計を保持する計画で、各短尺の先頭を明示し、旧自動版の時計を混ぜない。

| ポイント | Before：全編内の標準区間 / 前後を含む範囲 | After：短尺の元時計・長さ | After：短尺内の標準区間 / 前後を含む範囲 |
|---|---|---|---|
| 短文の整列 | 486–568 / 456–593 | 456から137frame | 30–112 / 0–137 |
| 横長の整列 | 1747–1818 / 1731–1830 | 1731から99frame | 16–87 / 0–99 |
| 背景三種類 | Beforeを設けない | 各短尺は456から137frame | 各30–112 / 0–137。同じ発話を背景だけ切替 |
| 動きの滑らかさ | 0–170 / 0–170 | 0から170frame | 0–170 / 0–170 |

上記は投入前の対応計画。実際の生成物のfps・総frame・由来の先頭frameを照合して採用し、ずれがあればデータを訂正する。SHAや元時計を推測で埋めない。短尺を再生するだけで、字幕の動作を再発火させない。映像の途中を抜き出す際の位相保持はQ1の生成記録で確認する。

## データ・HTMLの最終確認

固定テンプレートは変更せず、今回の修正版Batchと、用途を明示した異なる二組目のreview dataを同じ生成器へ投入する。二組目の確認を、本人への重複レビュー依頼にはしない。

1. **実媒体**：旧Beforeの実SHA一致、新短尺それぞれの実SHA・30fps・総frame、元時計と各viewの区間、前後を広げた範囲を確認する。
2. **IDと問い**：point ID・媒体ID・同一ポイント内view IDの重複を拒否する。HRC-001のようなreview IDの再参照は許すが、回答の主キーはpoint IDと対象版。黒・Softの問いが混ざっていないことを確認する。
3. **回答の帰属**：背景と動きのまとめた回答はbundleのまま保持する。関連review IDへ機械配布しない。「良い」を機能使用許可や課題CLOSEDにしない。初期値は全件未回答。
4. **必要な比較だけ**：整列と動きだけBefore／Afterを持たせる。三背景は候補の切替とし、三viewなので「両方使える」は無効。二viewの「両方使える」は、その問いに示した二候補だけに適用する。
5. **保存と誤帰属拒否**：正しい版の回答保存・再読を確認し、別Batch／別revision／別SHA／別ポイント／別scope／改変区間を拒否する。読み込み失敗時に現在の回答を失わない。
6. **検査の区別**：NodeとDOMを模したコード試験、HTML生成と実媒体照合、実ブラウザー、人間品質を別々に報告する。既存のブラウザー自動操作拒否は維持し、実ブラウザー未確認を合格へ変えない。人間が直接開く従来の提示方式を使う。
