## 1. 今回作るもの

**黒へ急に切り替える以外に、短いフェードで黒へ移り、次の場面へ戻る接続表現を一種類作る。** 仮称は `Soft Separator`。黒Separatorの置換・上位互換ではなく、同じ「区切る」役割に対する別の有限描画候補である。

比較の勝者を探す研究ではない。実際に描画でき、意図した範囲だけ変化し、元内容・時計・保存・復元を壊さないところまで進める。

到達点は次の一まとまりとする。

> 有限presetの定義 → 既存接続処理への小さな描画接続 → 実境界を使う小型fixture → 保存・再読・変更・復元 → 実画素／PCM／時計の検査 → 候補動画1本と報告

**161秒や24分のDigest全編を、この工程のためだけに再生成する必要はない。** 全体の自動配置、字幕動作と接続の本格的な統合、通常jobの正式受入は工程IIIまたは別管理事項に残す。描画部品は後で再利用できる入口にするが、今回それだけのために大きな共通基盤は作らない。

## 3. 最小の描画方式

### 3.1 第一候補を具体化する

以下を初期実装方式とする。

1. 前区間の末尾の短い窓で、元の各frameを順番どおり使いながら黒へフェードする。
2. 既存と同じ12frameの黒と、19,200 sample/channelのゼロ音声を挿入する。
3. 後区間の先頭の短い窓で、元の各frameを順番どおり使いながら黒から戻る。

フェード窓の初期値は前後各6frame（30fpsで各0.2秒）を候補とする。**追加される時間は黒の12frameだけ**であり、前後フェードは既存保持frameへ作用する。240frameの入力なら252frameとなる。最後のframeを静止複製して尺を稼いだり、前後場面を重ねて短縮したりしない。

6frameは品質の最適値や人間承認値ではない。実装側は、既存経路での成立性と短い動作の確認に基づき、必要な局所修正で窓長・曲線を一組へ固定してよい。ただし別duration候補の大量生成や人間への細かな数値質問はしない。12frame黒そのものの採用を再審査せず、変更が必要なら新表現との差分として報告する。

### 3.2 有限仕様として必ず記録する

名称／preset ID／版、フェード窓、係数列または固定曲線、黒への到達・元映像への復帰、端点の扱い、画素形式・色域・丸め、追加frame数、適用不能条件を固定する。フェードで使う係数は描画仕様であり、品質点数や合否救済の係数ではない。

完全な黒が何frame見えるかと、時間表上12frameを挿入することは別に記録する。係数の端点により保持frameも完全黒になるなら、その区別を曖昧にしない。

再利用可能な小さな描画処理として作る。新しい動画renderer、汎用transition engine、任意filter式／keyframe／曲線を入力できるDSLにはしない。

### 3.3 対象範囲外へ広げない

場面どうしを混ぜるcrossfade、wipe、zoom、white flash、音声だけのtransitionを同時追加しない。第一方式が成立しない場合は、同じ「黒を経由する短い映像フェード」の範囲で最小修正を行う。新基盤や保持内容の削除が必要になる場合だけ、具体的な理由と限定代案をGPT_DECISIONへ戻す。

## 4. 音声は別の責務として固定する

今回の新規効果は**映像のフェード**である。音声の滑らかさを改善したとは主張しない。

既存黒と同じ音声方針を使う。保持PCMは値・順序・チャンネルを保ち、挿入分だけ厳密なゼロを追加する。音量正規化、音声fade、crossfade、音源分離、click補修、新しい発話検出を追加しない。

可逆中間物で全保持float32 PCMと挿入sampleを照合する。確認用H.264/AACでは再圧縮後のPCM完全一致を要求せず、packet時計・duration・padding・decoded tail・挿入前後の実復号状態を分けて記録する。

過去研究の末尾+256 sampleや、挿入端の非ゼロ384 sampleは過去素材の観測である。今回も必ず同じ値になるという期待値にはしない。新しい実測を記録し、違いの由来を確認する。可聴性の未評価を「問題なし」「修復済み」に変換しない。

## 5. 変えてよいものと守るもの

| 対象 | 契約 |
|---|---|
| 正本の内容・保持 | Prospect、保持区間、順序、元動画時刻、入力正本を変更しない |
| 保持frame | 件数・順序・source対応を保つ。画素変化は明示した前後フェード窓だけを許可する |
| フェード窓の外 | 可逆比較で元frameと完全一致を要求する |
| フェード窓の中 | 元frameへの所定の黒フェードとして検査する。元画素との完全一致は要求しない |
| 挿入区間 | 12frame黒と対応するゼロ音声。元素材のframe参照を捏造しない |
| 字幕 | 本文、改行、ID、元の表示長、元対応を保持。挿入後だけ共通の時間投影で等量移動する |
| 保存状態 | 元入力・原案は不変。変更は別保存し、Resetで保存済みの元案に戻る |

画素が変わることは本表現の意図である。ただし「フェードだから」と境界窓外まで変化を許さない。窓が保持区間へ収まらない、隣のフェード窓と重なる、挿入境界を字幕が跨ぐ等の未対応入力は、切詰め・移動・本文分割で黙って救済せず拒否する。

### 焼込字幕を含む既存短尺の扱い

小型研究実証では、既存の焼込字幕を含む正本短尺をそのまま使ってよい。この場合、**フェード窓では字幕画素も映像と一緒に変化する**ことを仕様と報告へ明示する。字幕本文・時計の保持と、字幕の画素・可読時間の不変を混同しない。

字幕画素の変化は新しい字幕presetではなく、この小型接続試験の全画面処理である。工程Iの字幕保存・動作プログラムを変更しない。焼込済み動画から字幕を除去しない。

将来、映像だけをフェードして字幕を別に描く場合は、焼込前基礎媒体からの合成順と字幕の扱いを工程IIIの統合契約で明示する。今回の焼込短尺で、その本番統合まで証明したとは呼ばない。

## 6. 接続指定・保存・Resetへの最小接続

Normal Cut、Separatorという役割と、既存黒／新しいフェードという描画presetを分ける。仮称Soft Separatorを新しい感情・意味分類として増やさず、同じSeparatorの具体的な見せ方として扱える構造を優先する。

小さな型付き開発入力で、元Digestの版／SHA、前後segment、挿入前境界、選んだ有限presetとその版を束縛する。任意のframe数・色・音量・filter式を外部の割当へ受け付けない。実装が使う値はpreset側に置く。

既存の接続三層researchの意味論を再利用する。必要な小さな接続は許可するが、今回改めて一般化した保存基盤・正式registry・全11件のselectorを作らない。研究文書を本番schemaへ改名して完成扱いにしない。既存の字幕と接続を混ぜたobjectを新しい保存正本にしない。

少なくとも、一件について保存済み原案→別の許可表現またはNormalへの変更→再読→解決→描画→Resetを通す。Resetは対象overrideの削除であり、常にNormalを書く処理ではない。原案が新フェードなら新フェードへ、原案が既存黒なら既存黒へ戻る。比較に使う原案とoverrideが開発fixtureなら、その作成者を明示し、実AI・本人評価と記録しない。

接続IDは挿入前時計へ固定する。一件の変更によって後続の表示時刻が移動することと、別接続の割当・字幕の見た目が変わることを区別する。元入力から一回だけ再解決し、移動済み時計への二重加算・手引き戻しはしない。

## 7. 小型fixtureと候補動画

### 7.1 技術fixture

既存接続1・2・11を原則として使う。旧研究と同じ3件の技術条件を利用し、全11件の主観観測やYUV／RMSの再棚卸しへ戻らない。保存済み通常／黒の媒体と証拠は、入力・関連sourceが同じで適用範囲が一致する部分だけ再利用する。新方式に影響する回帰は小型で行う。

新フェードが窓に収まり、挿入・字幕時計が異なるケースで成立することを確認する。新しく都合のよい字幕文面・演出用の発話時刻を作らない。必要な純粋な異常系だけは、媒体や時計の技術fixtureとして合成データを使用できる。

### 7.2 人間へ渡すものは一候補だけ

新フェードを含む既存3短尺を、一つの短い候補MP4にまとめてよい。各例が240→252frameなら合計756frame、約25.2秒となる。これは想定値であり、実測して確定する。

例同士をつなぐ部分は元Digestの実接続ではない。対象接続の完成時刻と各例の対応を別の短い一覧に残す。パッケージの連結を新しい演出能力として数えない。タイトル・新テロップ・比較UIをこのために作り込まない。

通常版・既存黒版・新方式の複数全編を人間へ並べ、優劣・理由を回答させる運用には戻さない。旧媒体と故障動画は技術証拠として別保持する。候補は技術上の手指定見本でよく、無修正自動Digestと偽らない。全体の自動選択は工程IIIで扱う。

実ブラウザーのfile URL等に既存の操作制約がある場合は迂回しない。ローカルMP4と、技術的に確認できた再生・媒体条件を提出し、UI未検証を正直に残す。人間が今見られないことだけで工程IIの技術作業を止めない。

## 8. 検査を閉じる範囲

| 層 | 必須の検査 |
|---|---|
| 入力・保存 | 正本／境界／preset版の不一致、未知ID、非隣接、重複、自由描画値を拒否。旧保存物は不変 |
| 時間と対応 | 元frame・sampleの順序と個数、挿入量、source対応、字幕の等量shift、二重shiftなし |
| 映像・可逆 | 窓外全frame一致。フェード窓全frameが固定係数・色域・丸めに対応。黒区間と元映像への復帰を確認 |
| 音声・可逆 | 保持float PCM全量一致、挿入ゼロの位置と個数一致。音声への別効果なし |
| Reset | 保存・再読から元案へ戻り、元入力から同じ時間表・画素列・PCMを再現。別の指定を失わない |
| 最終MP4 | 寸法・fps・予定frame数、映像／音声時刻、decodeとpadding、フェードが実frameに現れること |
| 既存回帰 | 変更した接続部品に関係する通常／黒／Resetのみを小型確認。工程Iの字幕部品を変更しないなら全再描画を要求しない |

フェードの期待値は、実装の最終出力をそのまま正解にするだけでは不十分である。小型fixtureで入力frame・所定の係数・色域・丸めから追える期待結果を別に置く。同じ不具合を共有する再描画byte一致だけを、効果成立の唯一の証拠にしない。

少なくとも、フェードなし、窓の時刻ずれ、元映像に戻らない、窓外frameの改変の実故障を検査が拒否することを確認する。可能な範囲で一つの小型素材にまとめ、全Digestの反実仮想再encodeを復活させない。

可逆保持と最終圧縮の検査は分ける。圧縮後の画素が可逆入力と完全一致するとは主張しない。逆に、有限候補の相対距離が最小というだけで未知の破損を合格にしない。既存QCの対応profile外なら、その合格を流用せず、小型試験の証明範囲と必要な統合上の残件を明示する。

**今回、接続挿入に対応するA+B汎用QCの全面拡張、全24分のexact replay、字幕ごとの全編再encodeを必須にしない。** 小型で新しい故障を閉じ、既存の媒体検査へ正しくつなぐことに集中する。適切な既存低コスト検査が使えるなら重複開発しない。

## 9. 自動配置と正式統合は工程IIIに残す

工程IIでは表現の能力を作る。適切な接続を最適に当てるAI、YUV差／RMSからの品質判定、頻度最適化、嗜好学習、全編割当は作らない。

通常カットと黒を再現可能なランダムで併用する採用方針は保持する。ただし、今回の小型フェード実証にそのproduction selector実装を追加しない。保存した具体presetが何かは必ず記録し、将来の工程IIIが使えるようにする。

工程IIIへの引継ぎには、字幕と接続の合成順、共通表示時計、Pulseの根拠ピークの表示時計への投影、Bounce／Shakeの開始基準の投影、接続／字幕overrideの独立性を残す。**これらを今回全部実装する指示ではない。** 対象例外が出ても工程Iの正本や過去案を改変して整合させない。

正式trust、Normal再認定、renderer正式版、契約path会計等は別管理する。旧2job限定snapshotは再利用しない。共通描画の開発入口で許可された小型実証は進められるが、通常file入口の正式受入が済んだとは記録しない。

許可しないもの：新素材・書体・モデル・依存取得、有料API、Gemini等への新たな媒体送信、自由編集Agent、GUI、任意animation DSL、新しい汎用renderer、ショート、正式契約／Goal／DECISIONS改訂、main merge／tag／stable／release。

ツール拒否を別経路で回避しない。禁止退避folderは列挙も行わない。入力や正本に影響する不可逆操作・大きな削除は行わない。無関係な既存treeを保全し、選別してcommitする。

人間不在だけで停止しない。権限外の処理が不可欠なら、具体的な必要性・影響・許可内代案をGPT_DECISIONへ出し、その作業だけ保留する。別の承認が必要な工程を、待機を埋めるための大量fixtureや再監査に置き換えない。

## 11. 完了条件（八項目）

1. 通常カット・既存黒と区別された、短い黒経由フェード一種類が有限presetとして実装され、定義と出力例がある。
2. 変更窓、挿入量、三つの時計、frame／sample対応、焼込字幕への作用が明記され、意図した変更と不変条件を分離している。
3. 元の保持内容・順序、窓外全frame、保持PCM、字幕本文・元表示長・元対応を検査し、必要な等量shiftが正しい。
4. 別保存→再読→描画→Resetで保存済み原案へ戻り、同じ内容と時間対応を復元する。原案や他の指定を破壊しない。
5. 新しい映像変化の小型全frame検査、実故障拒否、変更影響に合う通常／黒回帰が成立している。
6. 実接続で新表現が出る候補動画1本と媒体QCがあり、技術手指定・未実施の自動選択・未評価の人間品質を区別している。
7. 新表現を含む接続表現一覧と、工程IIIで必要な最小統合の残件がある。黒の採用を再審査せず、新候補の正式採用を偽らない。
8. 指示・参照・実装・試験・再現方法・失敗履歴・報告を選別してcommit／pushし、remote読戻しと既存作業保全を確認している。

微差の人間比較、全11件の採点、新フェードの正式採用、24分全編再生成、通常jobの正式受入、trust再発行は今回の完了条件ではない。

## 12. 完了時の報告と次工程

同じ相談役会話へAUDIT_ONLYを一回のまとまりで送る。branch／base／checkpoint／compare／変更一覧に加え、有限仕様、既存黒との差、実素材の出所、fade窓／字幕／音声の作用、変更と不変の検証、保存／Reset、候補path／SHA、故障試験、未検証事項、正式統合の残件を含める。

実MP4や巨大な生証拠は無断uploadしない。Gitには再現source・試験・文書・軽量証拠を残す。実行した修正のcommit漏れ、未pushを確認し、既存の無関係差分を混ぜない。

監査後の計画上の次は工程III「E：許容される表現の全体使い分け」である。工程IIの正常技術結果を受けた後、同じ会話へ次の指示書を求める。本人の細かな好み待ちを理由に旧工程へ戻らず、次の切出し範囲に従う。
