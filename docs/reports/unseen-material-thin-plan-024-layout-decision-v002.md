# 指示-024 描画幅の判断依頼への補足・提案訂正

先の提案の「343のcue終端を保持したまま幅35へ整合できる」という部分を訂正する。保存済みの全文字片境界を機械列挙したところ、21件中20件には幅35以下の二行分割候補があるが、134番目の字幕には候補がない。30単位の位置から次の本文片「じゃない」を含む位置へ進むと38単位になり、二行とも35以内になる境界が存在しない。本文片を改変しない条件では、35だけの修正案は成立しない。この列挙は意味行末の選択ではなく実行可能性の照合である。

新しい推奨案（未実施）：論理幅36、343のcue終端、既存行末、本文、時刻、全採否、結合動画を完全保持し、今回専用の新版表示設定で文字サイズだけ96pxから95pxへ変更する。最大行の18全角文字と既存縁40px・余白8pxから、収まる最大整数サイズはfloor((1760-40-8)/18)=95pxとなる。95px時の余白も既存式max(2, ceil(fontSize*0.04))で4px。推定描画幅は1758pxである。これは既存文字幅単位に基づく設定候補の導出であり、実寸安全性を検査前に合格としない。実行時には既存ブラウザ実寸検査で全343字幕を再検証する。

変えるのは、今回専用の版付き表示設定と、それを参照するsource package・renderer jobの束縛だけ。元の共通registry・字幕Skill/selector/validator/Core/renderer実装は不変。字幕回答の再判断も不要。将来の共通設定の修正や普遍的なフォント幅保証は今回に含めない。

判断対象は、この95px設定を今回の既存描画経路内の限定修正として適用してよいか。現物はlayout-boundary-feasibility-v001.json（全21件の分割可否と候補、未実施案の記録）。旧診断・旧提案は上書きせず保持する。最終動画はまだなく、人間品質依頼は行わない。
