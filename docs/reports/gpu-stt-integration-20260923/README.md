## ZEVへの接続と使い方

通常工程の「入力動画参照→文字起こし→保存・検証→後続のテーマ入力」という経路へ接続した。変更前は開発機でFLACを抽出し、同期の `/transcribe` に完了まで接続していた。変更後は準備済み動画をそのまま送る。動画はファイルから送信し、全動画をメモリーへ読み込まない。

既存の `config/runtime.jsonc` の文字起こし実行方法を `local` にし、backendとrunnerを起動する環境で次を指定する。

```sh
export STT_BASE_URL=http://<GPU機のLANホスト名または予約IP>:8000
```

接続先環境変数を優先し、未指定なら既存設定の接続先を使う。個別設定ファイルは既存の `ZEV2_RUNTIME_CONFIG_PATH` でも指定できる。今回の実走は個別設定で文字起こしを `local`、後続入力の読込みを `transcript` にして確認した。管理中の既定設定はUI確認用の `fixed` を維持しており、**環境変数だけを指定してもfixedの文字起こしはGPUへ切り替わらない**。

| 処理 | 接続後の扱い |
| --- | --- |
| health | 利用可能なworkerを確認してから投入 |
| 受付 | job番号、接続先、入力動画参照、入力SHA、言語、受付応答を `gpu-stt-job.json` に保存 |
| 完了待ち | 2秒間隔で同じjobの状態を確認。最新状態を `gpu-stt-status.json` に保存。待機中に再投入しない |
| 待機上限 | 既存設定の既定30分をhealthから結果の本文取得まで共通適用。変更する場合は既存の `ZEV2_STT_SERVER_TIMEOUT_MS` を使用 |
| 失敗 | HTTP/通信エラー、失敗・中断したjob、不正な応答、動画との不一致は工程失敗として返す。自動再送・旧同期APIへの切替はしない |
| timeout | 待機を終了し、取得済みjob番号を通知。GPU側のjobを取り消さない。保存した接続先とjob番号で状態を確認できる |
| 生結果 | `gpu-stt-{job番号}.response.json` を応答byteのまま保存。同じ保存先の内容が異なる場合は上書きせず停止。従来の生STTファイルへ触れない |
| 入力との対応 | 送信動画のSHAを受付・状態・結果のSHAと照合。ZEVの動画参照を文字起こしと工程manifestへ保持 |
| 変換 | 発話番号・開始終了ミリ秒・本文・話者を既存形式へ移す。まとまりはZEV側の既存製造規則に従い1断片につき1件とする。GPUの文単位まとまり・話者候補・確信度は生結果へ保持 |
| 全体長 | GPUのZEV向け部分は最後の発話時刻を長さとしていたため、入力全体の実音声長を使う。末尾の無発話区間を長さから消さない |

既存のsample/fixed経路、後続のtranscript契約、テーマ作成ロジックは変更していない。CLIによる過去のSTT製造物・凍結済みfixtureも変更していない。

### 監査後の発話まとまり修正

比較元の旧STT製造処理 `evals/clip_composition/run_local_stt.ts:315` と `run_local_stt_chunked.ts:399` は、発話断片ごとにその番号1個のまとまりを作る。旧保存結果も全23,963断片/23,963まとまりが同順序の1対1、candidate 59の区間は281件だった。一方、GPUの生結果は認識文2件に対応し、160断片と109断片を束ねていた。両者は同じfield名でも意味が異なる。

既存の後続はそのまとまりをテーマ候補と構成範囲の母集団に使う。初回実装がGPUの2まとまりをそのまま渡して最大2候補にしたことは、schema合格だけでは防げなかった不備である。GPU専用変換で検証済み断片ごとに1まとまりを生成し、ZEV側の既存製造粒度へ揃えた。新たな時間閾値・分割係数・内容選択規則は設けていない。

GPU生結果のSHA `bb178bd7152fe69fec7e3e39592dafab4afc67d3e47a276b8a791f6a786fd7c6` は不変。本文、時刻、話者、入力全体長も初回の正規化結果と同一。変えたのはZEVへ渡すまとまりの構成だけで、sample/fixed、テーマ生成、構成、Prospect、selector、GPU側の処理は変更していない。

同じcandidate 59の保存結果を修正済み変換へ通し、旧STTとGPUの両方で、3候補要求→3件、5候補要求→5件となることを確認した。各候補を既存の構成工程まで渡して検証した。GPUのgroupを1件・2件・断片ごと・空へ変えた回帰試験でもZEVの候補参照は同じ。修正時のAPI通信は0回で、上記の時間は初回LAN実走の実測値として保持する。

本文は「作業中に別のことを始める→あちこち30%になる→最終的には片付く→服を脱いで寒い」の内容が対応した。NFKCと英数字・文字の抽出による比較では、旧277文字、新268文字中267文字が一致した。主な差は旧「片付けてる片付けよう」に対する新「片付くよ」、フィラーと末尾1文字の欠落。品質得点や独自の重みは導入していない。

一致文字の開始時刻差は中央値8ms、最大842ms。旧時刻が正解であるとの判定はしていない。旧STTにない長い発話の追加・同文の大量反復はなく、今回の実素材に大量の幻覚発話が増えた証拠はない。無音・BGM・ゲーム音だけの素材を別途網羅評価したものではなく、録音全体の人間による精度評価も未実施。STTモデルの精度改善へ範囲を広げていない。

同じ入力を旧機で再実行していないため、旧機に対する速度向上率は未測定。今回実証したのはLAN接続、手作業の受渡しの解消、新規非同期処理と再利用、ZEVの入力受理である。
