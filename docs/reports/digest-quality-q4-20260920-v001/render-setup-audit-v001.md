# Q4 描画起動条件の読み取り監査

## 結論

Node 20.19.6 のディレクトリを起動環境の PATH 先頭へ置き、NODE_OPTIONS を外す修正で、今回検出された親子の Node 不一致を解消できる。最小の親子起動でも双方が 20.19.6、追加 Node オプションなし、標準エラー0であることを独立確認した。描画実装は変更していない。

## 確認した根拠

- 初回は完成動画の再合成照合に合格した後、描画に使う実行環境の照合で停止している。描画子プロセスは PATH から Node 23.7.0 を選び、親の Node 20.19.6 と一致していなかった。
- この描画入口は Remotion の実行ファイルを直接起動する。その実行ファイルと文字配置検査の実行ファイルは、ともに PATH から Node を選ぶ。pnpm の起動補助ファイルの隣に優先される Node は存在しない。
- 子プロセスは修正した親環境を継承する。既存処理が指定する依存ライブラリの検索先と一時ディレクトリも維持される。
- 初回の保存PNGは3組あり、それぞれ初回・再描画・保存先の計9参照で実バイト数とSHAが一致した。ただし、実際に使った子Nodeが記録された描画環境と異なるため、今回の再実行でこれらを再利用する根拠にはできない。
- 再実行の指示は新しい描画素材の保存先を指定している。初回PNGを再利用せず、背景のみを既存の検証付き再利用入口へ明示参照していることを確認した。背景の検証記録は合格で、描画子Nodeに依存するPNGとは別の成果物である。

## 保存記録との照合

[起動修正記録](render-setup-correction-v001.json) の初回失敗記録・背景検証記録・再実行指示について、実ファイルのバイト数とSHAを再照合した。描画前の候補選定と描画規則は、初回と再実行でバイト一致している。

起動修正記録のSHA-256：`3c2c54f5590701c6d2a6265e1e611ea3790f4e0a26b2bf9335781130ec8a7ab4`。

本監査では描画・画像閲覧・音声復号・意味判断を実施していない。再実行の最終QC合格を先取りするものではない。
