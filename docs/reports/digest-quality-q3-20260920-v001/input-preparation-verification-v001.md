# Q3 入力準備・時計対応 検証 v001

Codexです。HRB001の保存済み入力を完成動画の時計へ結び付ける処理を実装し、専用試験26件と実入力の全体対応を確認した。品質の採否は扱っていない。

## 実装と結果

- 元媒体と全参照の実bytes、保存済み投影、完成字幕計画、元の切り出し記録を照合する。旧自動案は再実行しない。
- 全32字幕・6接続・8無字幕区間を扱い、字幕と無字幕の合計は完成動画4867フレームを重複なく覆う。
- 旧音声候補27件・音声認識70区間392語・音量頂点1064件を保存元と対応付けた。挿入や素材境界を跨ぐ証拠は分け、元観測全体の集計値と部分区間を区別する。
- 元素材映像は保存済みの30fps論理フレームから60fpsの偶数フレームへ接続する。16msの表示開始差を保持し、元素材音声は生成記録のサンプル位置から別に接続する。
- 黒・無音の挿入には元Digestや元素材の時刻を付けない。通常カットでも元素材の位置が飛ぶため別の部分に分ける。
- 16kHz観測と44.1kHz再生は別の時計として、有理数で対応を保持する。旧観測末尾の974/3サンプルは完成区間へ投影しない。

## 実入力で確認した2件の準備修正

1. 旧通常版のコンテナ音声終端は基礎媒体より15サンプル短い。AAC音声packetの実bytesと先頭skipは保存生成記録に一致した。完成媒体の終端一致条件を旧観測媒体へ当てた検査を分け、コンテナ差と復号末尾を別記録にした。
2. 保存音声認識の8端点に長い小数表記があった。整数サンプルへの丸めを要求せず、保存小数を正確な有理数で運ぶようにした。これは音声認識自体の物理精度を保証せず、微小な桁差を発話切れの根拠にはしない。

修正前の入力実走をattempt-001／002に保存し、attempt-003で入力準備を完了した。媒体や字幕本文、接続、旧観測は変更していない。

Node v20.19.6で時計21件・入力準備5件、合計26/26合格。通常カット・挿入・範囲端・旧観測末尾、小数の分数化、長さ0の語、二重投影、参照改変、HRB002と同尺別版の拒否を含む。実入力は全対象・全観測件数と入力検証器への適合を確認した。入力準備の後、音声認識の精度に関する説明だけを加えた版を保存している。
