## 対象と最初の指摘

最初に `tools/digest-quality/measure-pcm.mjs`、`run.mjs`、`review.mjs`、`judgment-prompt.md` を読んだ。全対象区間のPCM計測、計測前後の完成媒体SHA照合、AAC復号末尾の分離、初回判断の情報制限、0候補と未完了・失敗の区別、固定Q2形式への完成時計と未回答の接続に、具体的な必須修正は見つからなかった。

唯一の指摘は、回答受理時に保存済みの依頼を読み直していなかったこと。入力と回答のハッシュだけを合わせ直すと、判断依頼時の入力・指示・媒体と違う組合せを受理できた。

## 対応後に確認したこと

- 保存した入力ファイルのbyteハッシュ、入力の正規化ハッシュ、保存指示本文のbyteハッシュ、媒体ハッシュを、保存依頼と照合する共通処理を追加している。
- 回答受理は、受信原文の排他的な新規保存を先に行う。その後に保存依頼との照合、参照ファイルの照合、回答の内容検証へ進む。
- 依頼との不一致は、受信原文のハッシュと理由を拒否記録へ残す。原文を消したり、回答を直したりしない。
- レビュー生成も同じ保存依頼の照合を先に呼ぶ。不一致の入力を標準レビューへ渡さない。
