# Q3：入力とAI回答の検証

Codexです。指定の入力・回答形式に対する検証を `tools/digest-quality/validate.mjs` と同じ場所の試験へ実装した。既存の厳密JSON読取器、Q2の正規化処理、今回の保存時計対応処理を再利用している。入力と回答を補完・修復しない。

## 確認すること

- 入力の正規化ハッシュ、対象媒体のハッシュ、必須項目、対象と根拠の一意な識別を照合する。
- 字幕と無字幕の区間が全編を欠落・重複なく覆うことを確認する。接続はそれらと重なってよい。
- 保存時計から元Digest・元素材の対応を再計算し、対象ごとの対応と完全一致を求める。挿入には元素材の時刻を付けない。保存音声観測は保持区間へ分割されていることを確認する。
- 完成音声のsample数は映像期間を覆うことを求め、AAC復号時の末尾余剰は許容して保持する。
- 完了回答では全対象が一度ずつ処理されていることを求める。未知の対象・根拠、対象や観測範囲と無関係な引用、対象区間の集合では覆えない候補を拒否する。
- 事実の記述には、その候補へ含まれる根拠の識別を必須とする。自然文そのものの正しさを機械で証明したとは扱わない。
- 完了して候補0件の回答を受理する。失敗・未完了では部分回答を保持できるが、レビューへは渡さない。
- 受信原文のハッシュを保持する。原文保存は呼出し側がJSON読取りより前に行う。

ファイル照合は明示的な非同期処理で、媒体と全参照の実在・実byteのSHA・読取り中のファイル同一性を確認する。通常の入力検証だけではファイルI/Oを行わない。

## 試験と初回失敗の帰属

最終の局所試験は **81件成功、失敗0、stderr 0 byte、終了0**。小型の字幕・接続・挿入・無字幕区間を使い、別媒体、古い入力、欠落・重複、範囲端、誤った移動、二重投影、未処理対象、根拠の誤帰属、0件・失敗・未完了、実ファイルの差替えと欠落を確認した。

初回71件中の5失敗は同一の試験設営原因だった。既存の厳密JSON読取器はprototypeを持たないオブジェクトを返し、試験は通常のオブジェクトとprototypeまで比較していた。JSONの値は同じだった。比較時に構造を複製してJSON内容を比較するよう一箇所の方針で訂正し、読取器・受信byte・返却する内容は変更していない。初回TAPを保持し、5件を製品欠陥5件とは数えない。

時計との完全照合を加えた79件、無字幕の識別と保存音声観測の範囲境界を加えた81件を、それぞれ別ログへ保存した。[実行・帰属・SHAの記録](validator-verification-v001.json)を参照。

## 適用範囲

この試験は検証器の境界確認であり、HRB-001の実判断、完成映像の意味観測、人間の品質認定ではない。実入力の作成・現物計測・判断実行・レビュー変換は各担当の記録へ接続する。選択処理、描画処理、Q2の固定schema、媒体は変更していない。外部送信、新依存、API通信はない。
