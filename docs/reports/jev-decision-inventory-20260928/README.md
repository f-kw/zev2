### 5.2 Typed出力案

第一対象の意味は「現在使える演出語彙のどれかを付ける根拠があるか」。質問は一つの要否判断とし、どのpresetか・どの範囲か・理由の文章は求めない。

```ts
type EffectNeed = "normal" | "effect" | "unresolved";
// APIの質問IDと元字幕IDの対応は呼出側が保持する。
type ShadowAnswer = {
  choice: EffectNeed;
  probabilities: Record<EffectNeed, number>;
  confidence: number;
};
```

- `normal`：意味・反応・保存音響に演出を付ける明確な根拠がなく、通常表示を保つ。
- `effect`：現行語彙のいずれかを付ける根拠がある。範囲・presetを決定したことにはならない。
- `unresolved`：与えた文脈や観測だけでは判断できない。Normalの代用にはしない。

JevではChoiceの3選択肢に対応させる**案**。質問ID自体は推論に渡らないため、質問文にも対象配列位置を明記する。providerが返す型・確率・confidenceを原形で保存し、ZEV側で字幕ID完全被覆・重複・未知選択肢・数値範囲を検査する。通信失敗、欠落、物理的表現不可は意味上のNormalへ押し込まず別の実行状態に残す。これはreport内の比較型で、本番schemaの新設ではない。[O1][O2]

### 5.3 小さい実走構造と速度・費用

基本案は**5場面batch＝5 request、326 question**。1問1callにはしない。調整用1batchの確認後、固定した判定用4batchを実行する仕様。場面batch同士は独立だが、送信許可・rate制限・実行条件が確定するまで並列数や再試行回数を設定しない。APIが入力上限を満たさない場合は実走前に入力tokenを確認し、勝手に本文を切ったり326直列callへ変更したりせず、比較単位を再確認する。

14.3で記録するもの：準備・読込み・通信待ち・推論応答・型検証・比較保存を含む全体経過、requestごとの時間、成功/失敗/再試行、質問数、入力/出力token、返却modelの固定版、実課金、文脈重複量。batchの所要時間を字幕数で割った値を独立APIのlatencyと呼ばない。Codex側も同じ開始/終了条件で計測し、取得できないtoken・契約原価は未取得のまま残す。

**復帰の評価：** shadowでは本番は常に保存された現行結果を維持し、現行判断の再実行で動画を変えない。Jevのunresolved・不正応答・通信失敗、将来のconfidence基準による要復帰件数を分けて集計する。候補基準ごとの「同一場面の要復帰字幕を1batchへまとめる」場合の追加依頼数を計数する。個別字幕callを加算しない。保存回答との照合だけの所要時間を、Codex再判断のlatencyに置き換えない。

本番候補の総時間を評価するなら、後日許可された範囲で、演出あり群に残る範囲・理由等の生成と復帰batchの**実測**を足す。まだ測らない場合は「Jev5 request＋残存生成batch＋復帰batch＋再試行」という未計測構造までの報告に留める。現行一括判断を丸ごと続ける案は、速度・費用とも追加になり得るため、採用根拠としない。

### 5.5 品質・confidenceの評価方法

一致率に加え、現行Normal→Jev演出あり、現行演出あり→Jev Normal、unresolved、実行失敗を分ける。Normalが多いため、全件一致率だけでなく両側の件数と分母をそのまま示す。重み付き合成scoreや独自の合格係数は作らない。

| 比較後に分類する差 | 扱い |
|---|---|
| 軽微な選好差 | 本文の意味・読みを変える根拠がなく、両案が成り立つ可能性。相違だけで誤りと断定しない |
| 人間確認が必要 | 皮肉、音声だけの反応、文脈不足、好みの差。保留のまま保持 |
| 見た目を明確に悪化 | 強調の過剰等は、実際の出力と人間確認が別途揃った場合だけ確定。要否JSONだけでは認定しない |
| 内容意味を壊す | 否定・数字・固有名詞・前振りとの不整合を比較根拠付きで点検。要否だけでは範囲や最終見た目を確定できず、疑いと確認済みを区別 |

今回14.2ではこの分類を実素材へ適用していない。14.3も6/13.3未回答の素材の違いを自動でhuman ground truthへ書き込まない。新たな人間視聴やレンダリングが必要なら、その採否は既存の品質確認後に別途扱う。

confidenceは確率分布の値とともに保存し、**閾値を14.2で決めない**。判定用273件について、confidence順の不一致一覧と、将来選ぶ各閾値候補に対する低信頼割合・復帰割合を後から算出できるようにする。調整用と判定用を混ぜて閾値を最適化しない。現在判断との一致は正答率ではないため、高confidenceの「不一致」と、人間等の独立根拠を得た「確認済み誤り」を分ける。高confidence誤りの確認可能件数/未評価件数も表示し、人間根拠0のまま校正済みとは言わない。

## 6. 公式情報と未計測の境界
