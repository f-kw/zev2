# Digest完成動画のQC高速化：検証記録

## 目的と範囲

対象は、人間修正0で作った約161秒・4,831frame・32字幕の完成候補である。字幕ごとに先頭から再エンコードしていた可視性検査を短縮し、通常字幕を含む全32件とPulseの3時点を維持する。新しい演出の追加、完成動画の再生成、本文・改行・表示時刻・位置・Prospect・保持区間・音声の変更は含まない。

この完成候補の実選択は通常20件、Color 9件、Panel 2件、Pulse 1件、Scale 0件である。Scaleの不適用検出は別の実画素fixtureで確認する。完成動画の長さは4,831frameだが、完成画素の検査対象は32字幕の代表計34時点であり、全4,831frameの画素検査ではない。

この工程は、相談役の前工程最終監査後に受け取ったQC高速化指示に基づく。Color / Scaleは採用済み、Panel / Pulseは技術成立・人間未採用の状態を維持する。正式採用、見心地の判定、旧trust台帳更新、main統合、tag、stable、releaseは含まない。

**現在は実測検証中であり、通常検査の切り替えと技術第一完成は未確定。**

## 旧方式が検査していること

旧方式は、対象字幕だけを透明にした全タイムラインを既存のH.264条件で先頭からエンコードし、指定frameが復号された後に終了する。完成frameと対象字幕を除いたframeを、字幕の画素領域内で比較する。画素差が0なら字幕が見えないとして拒否する。Pulseには、通常・最大・復帰後の3時点で有限3状態の参照画像と照合する追加検査がある。

この方法はエンコーダーの時間方向の履歴を保持する。一方、静的字幕の判定は字幕を除いた場合との画素差の有無であり、見えている色・パネル・拡大が正しいことを単独で識別する検査ではない。故障注入では旧方式の実際の結果を記録し、通過した故障を拒否したものとして扱わない。

## 新方式の判定

1. 同じ元動画と完成動画から、従来と同じ代表frameを取り出す。Pulseは従来どおり3時点を取り出す。
2. 実際の字幕PNG、表示開始からの経過frame、既存の4frameフェード、Pulseの有限状態、同時に表示される字幕の順序から、期待する画面を独立に組み立てる。
3. 対象字幕の欠落、通常状態、部分Colorの全文化、Panelの背景塗り欠落、Pulseの別状態、別字幕の置換・追加、同時字幕の順序交換を、正常入力から決定的に作る。
4. 完全に同じRGB画像は一つの比較対象として扱う。期待画像が欠落画像と異なり、期待画像への整数RGB絶対距離が他の異なる画像より一意に小さい場合だけ合格する。同率は拒否する。

経験的な閾値、重み付きスコア、画素許容率は使わない。比較範囲も正常側の全候補から先に決め、故障した動画に合わせて変更しない。故障名や合格値を検査への入力にしない。

新しい参照の描画には既存の字幕描画部品を使う。診断用の通常状態や背景塗りを除いた状態は検査の一時領域だけに作り、固定通常計画・固定自動案・人間修正・本番PNG・完成MP4を変更しない。

## 来歴と改変の検出

元動画、完成動画、固定通常計画、解決済み計画、自動選択、実PNG、描画条件、フォント、既存描画コード、実行プログラムをハッシュで結び付ける。生成前後で入力を再読し、生成したframeとRGB証拠も終了前に再照合する。診断PNGは同じ既存描画経路で2回作り、バイト一致を要求する。同じ描画条件の本番PNGが既にある場合だけ再利用する。

保存された合格フラグだけでは通過しない。保存証拠を評価するときは、対象字幕、代表frame、Pulseの3時点、状態、比較候補、描画順、画素領域、実測した整数距離の集合から判定を再導出する。この純粋な判定検証は、画素ファイルを再読して距離を再計算する検証とは区別する。

本番の字幕合成引数、合成実行、従来の再エンコード検査、字幕描画条件、既存PNG描画コマンドは、前工程から本文の完全一致を確認した。有限演出・自動選択・Pulse状態・既存Pulse検査・字幕描画部品の対象8ファイルも変更していない。

## 実測の境界と限界

時間は単調増加timerで測定する。新方式では診断PNGの準備時間も含め、完成動画を新たに生成する時間は含めない。出力したframe数、再エンコードしたframe数、実際に観測した子process数を分ける。復号器の内部処理frame数や、観測していない孫process数を推測して実測値として報告しない。

比較するのはQCの計算区間であり、動画生成全体の所要時間ではない。旧方式は字幕ごとの計算区間合計とPulse追加検査を合算し、外側の経過時間は別に示す。旧方式は固定した既存の検査関数を測定器から直接呼ぶため、字幕ごとのNode起動は計数に含まない。新方式のRemotionが起動する孫processも観測数に含まない。測定中に短い合成単体検査と1字幕の接続確認が重なったため、完全に独占した環境での比較とは扱わない。

局所参照はH.264の全時間履歴を再現しない。全32件の正常判定と指定の実故障で同等以上の検出を確認することを採用条件とし、すべての未知故障や任意の色・時刻の正しさを証明したとは扱わない。初期対象は自動選択に束縛された30fps・下中央の発話字幕で、挿入タイムラインを含まない。対象外は従来方式を明示して検査する。

字幕が重なる場合の順序故障は画素識別能力の検査として分ける。本番のレイアウト衝突検査が、その重なりを許可した意味にはしない。

比較候補には別字幕の実PNGを含むため、字幕数の増加に伴って参照生成量も増える。今回の速度実証は現在の161秒・32字幕入力に対するものであり、より大きな入力での処理時間や一時領域使用量を保証したものではない。
