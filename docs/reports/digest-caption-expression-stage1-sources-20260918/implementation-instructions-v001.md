## 1. 目的と完成単位

色・全期間拡大・板・ピーク拡大だけでは出せない字幕の見せ方を、**静的外観・短い動き・読める安定状態まで合わせた有限preset**として増やす。

完成単位は「調査報告」「案の一覧」「配管だけ」ではない。小型実描画、保存・後修正への接続、既存自動選択への最小接続を経て、**新表現が実際に現れる、まとまった候補動画1本**まで作る。

通常版に必ず勝つこと、人間が微差の理由を説明できること、各presetを個別に人間承認することは着工・技術完成の条件にしない。技術故障や内容の明確な誤読は、この方針を理由に放置しない。

本書は上位計画の第5・9〜11節を実行単位へ具体化したもの。以下の試作方向は既に効果が実証された事実ではなく、実装対象を絞るための候補である。

## 4. 作る表現：三方向を少数の完成形にする

各方向につき、最初は一案から具体化する。色違い・倍率違いを大量に並べない。実装側が固定値を決め、短い実描画で調整する。細かな好みの質問はユーザーへ返さない。

### 4.1 要点を落ち着いて読ませる別外観

管理済みの書体・縁取り・背景処理から、既存Color／Scaleとは異なる読みやすいまとまりを作る。既存Panelも利用対象とする。

単に色をもう一色増やしただけを、新しい能力の完成と数えない。一方、既存Panel等で狙った見せ方を十分に作れるなら、同じ部品を別実装で作り直さず、再利用したことを表現一覧へ記録する。

### 4.2 出現時に一度弾み、読める状態へ収まる表現

字幕出現付近に短い動きを付け、その後は安定して読める状態になる一つの有限表現を作る。

既存Pulseは表示期間内の音声ピークを根拠に拡大するもの。今回の候補は**字幕の出現に伴う動き**として区別する。字幕の表示開始を、精密な発声開始と偽らない。

動く時間、状態、拡大等の変化、安定状態への到達はpreset側が所有する。既存の表示開始・終了は変えない。短過ぎて所定の動きと安定表示が収まらない字幕は適用不能とし、本文分割や表示時間の延長で救済しない。

### 4.3 拡大以外の短い動き

短い揺れなど、拡大以外の一案を作る。動く範囲、時間、終わる状態を固定する。無限反復やランダムな振動を導入せず、決定的に再現できる表現にする。

表現の必要性を「叫びだから」「感嘆符があるから」という固定規則で決めない。今回は描画能力を作り、自動適用には既存判断材料を用いる。声の起源や感情を観測していないのに確定したとは書かない。

### 4.4 共通の限定

三方向すべてを無条件に正式採用する指示ではない。重複・物理的な不成立・既存経路で扱えない条件が分かった候補は、その具体的な理由を残し、他の実装可能な候補を進める。できない一候補のために無関係な作業まで止めない。

ただし、既存表現の説明整理や色違いだけで工程I完成とはしない。新しい外観・出現・動きの実描画と、その実動画への反映が必要である。

## 5. 外観と動きを一つの有限presetとして扱う

一字幕一選択を基本とする。外観と短い動きを組にしたpresetは許可するが、任意effectを自由に重ねるstacking機構へ広げない。

各presetについて、実装時に次を短い定義へ固定する。

- 公開名称または仮称、preset ID、版。
- 用途の説明、既存表現との違い、対象単位。
- 変える外観、動き、時間上の基準、安定状態と必要な復帰。
- 物理的に使える入力条件・使えない条件。
- 使用する管理済み書体と描画部品。

色、文字サイズ、変位、frame数、曲線、状態列は実装側の有限値とする。AIから自由なpx／時刻／座標／JSX／filter式を受け取らない。任意のanimation DSLや汎用motion editorを新設しない。

必要な入力・描画規則の変更だけを版と内容hashへ反映する。旧保存案を新規則へ黙って読み替えない。旧公開名へ戻したり、既存動画の採用状態を再解釈したりしない。

## 6. 変更してよいもの／守るもの

**守るもの：** Prospect採否、保持区間、動画・字幕の順序、字幕本文、改行、元の表示区間、元動画対応、固定通常計画、固定自動案、未編集対象の指定。

**意図して変えてよいもの：** 新presetに定義した書体・縁・板等の外観と、限定された動作区間の位置・大きさ等。動的表現では、動くこと自体を位置不変検査で禁止しない。通常状態・安定状態・可動範囲と安全域を別に確認する。

Colorの既存部分範囲契約とカラー字形の扱いは維持する。新しい反応表現の初期対象は全文単位とし、語／文字ごとの発声追従、字幕再分割、新しい時刻推定は持ち込まない。

既存fadeと新動作を二重に掛けて意図しない表示時間を作らない。重なり、仕様上必要な安定表示区間の欠落、画面外、安定状態へ戻らない等を技術検査で確認する。通常表示そのものを新デザインへ無断で置き換えない。

## 7. 保存・自動選択・後修正への最小接続

処理は既存構造を保つ。

> 固定通常計画 → 検証した固定自動案 → 一件override → 実効描画計画 → 既存共通renderer → QC

新presetも同じ保存・解決へ渡す。本文・時刻を複製した新しい編集正本や、別の自動編集基盤を作らない。

既存のAI判断入力へ、新表現の有限名称、用途説明、適用可否だけを必要な範囲で足す。全字幕と前後文脈、利用許可済みの保存音声観測を使い、未処理・不明・表現不能をNormal判断へ隠さない。追加の外部解析や有料APIは使わない。

今回の自動選択接続は、表現を実動画で使うためのもの。全体の頻度最適化、許容集合選択の本格設計、嗜好学習は工程IIIへ残す。接続で許可されたランダム併用を、無条件で字幕全体のランダム化へ広げない。

新表現を含む初回の判断案は別版として生成・検証し、固定保存する。過去の固定自動案を上書きしない。保存した割当は再描画・後修正・Resetのたびに再判断しない。新presetへの変更、Normal固定、Resetを既存CLI等から扱えるよう最小限接続する。Resetは対象override削除であり、固定自動案と他対象を保つ。GUIは今回作らない。

## 8. C：Panel／Pulseを同じ表現セットへ整理する

Color、Scale、Panel、Pulse、新候補を一つの小さな表現一覧へまとめる。必要な項目は、名称、用途、変化、対象単位、必要根拠、適用不能条件、版、出力例、技術状態、採用状態とする。

Panel／Pulseの再実装や、通常版との微差を説明させる再研究は行わない。新候補との重複や使い分けを整理する。

採用が未決なら一覧にそのまま残す。候補動画への試用は人間採用済みの意味ではない。Cだけを独立した長い人間待ち工程にせず、A・Bの実装と同時に進める。

## 9. 検証は小型から行い、全編はまとまりで確認する

### 9.1 小型の契約・描画試験

変更に関係する既存回帰を再利用し、次を確認する。

| 対象 | 必要な確認 |
|---|---|
| 入力・保存 | 不明ID、不明preset、古い版、任意描画値、重複、不正範囲を拒否する |
| 通常表示 | 指定なし／明示Normalが既存通常経路を保つ。新機能のために通常外観を変えない |
| 新しい外観 | 文字だけでなく意図した輪郭や背景も実画素へ出る。本文・改行・表示区間を保つ |
| 動き | 開始、途中、最大変位／最大状態、安定／復帰を実frameで確認。短いfixtureの動作区間は全frameで所定状態との対応を確認する |
| 表示不能 | 短い字幕、安全域超過、2行衝突等を適切に拒否。縮小・再改行・時刻変更で黙って救済しない |
| 後修正 | 新preset→Normal→Resetで元案へ戻り、他対象不変。Color部分指定も必要な回帰を保つ |
| 故障検出 | 動作なし、誤った時刻、安定状態／復帰欠落など、新表現に対応する故障を実検体で拒否する |

検査数を増やすこと自体を成果にしない。全repositoryを繰り返し監査せず、変更影響と必要な回帰を説明する。既存の不合格は新規故障と区別して記録し、台帳や期待値を都合よく更新して合格扱いにしない。

### 9.2 候補動画の検査

新表現が最終動画にも実際に反映されていること、字幕の内容・区間・元対応、映像frame数と音声が保たれることを確認する。新表現以外の指定と物理入力の局所性も確認する。

既存の対応済みQCを利用し、新しい有限状態に必要な期待参照と拒否試験だけを追加する。未知の動作を既存QCの成功フラグで通さず、候補外画像を最も近い状態へ分類しただけで正当性を保証しない。

全字幕ごとの全タイムライン反実仮想再encodeは復活させない。必要な検査を省略して高速化したことにもせず、小型の故障確認と、まとまった完成動画の検査を分ける。

## 10. 最後に提出する動画は一つ

優先する素材は、既に利用許可・完成経路のある**161.033秒・32字幕のDigest**と、その保存済み基礎媒体・確定字幕・文脈・音声観測である。入力の所在と版は開始時に既存記録から確認する。新素材の取得や無許可探索はしない。

既存自動選択へ新presetを渡して、新旧の表現を含む候補動画1本を生成する。新表現を実際に含むことは必要だが、全presetを各1件入れるノルマや、品質を装った手配置はしない。

小型描画の手指定は技術fixtureとして明示してよい。まとまった候補は既存自動判断の結果を固定して使い、開発側が指定した見本や修正を無修正自動出力と偽らない。使われなかった候補の技術成立は小型fixtureで示す。

全候補が未使用となった場合は、表現適用条件、入力情報、選択のどこが制約かを特定する。件数達成のために役割を手で足したり、「全部Normalでも完成」と扱ったりしない。

人間向けに通常版・少機能版を新たに何本も作らない。既存通常版、短い参照、故障検体は技術証拠として別管理する。候補の完了時に確認する主題は、動画の中で明確に邪魔な表現、内容と逆の見え方、足りない変化があるかであり、微差の優劣・理由の全件回答ではない。

## 11. 進行範囲と停止の扱い

### この工程で自走する

専用branchでの通常調査、追加部品と必要な局所改修、有限presetの値決め、小型fixture、保存・CLI・自動選択・共通描画への最小接続、対象QC、候補動画、文書保存、commit／push。

正式trustの再発行を先に終わらせるために主作業をすり替えない。既に許可された共通rendererの開発経路でできる試作を進め、通常file入口の正式受入を実証していなければその範囲を明記する。

### この工程では行わない

- Dのフェード接続、黒の再研究、接続だけの大規模production統合。
- Eの本格的な全体配置改善、FのGUI・確認時間最適化、ショートへの移行。
- 一般animation engine、任意keyframe／DSL、自由editing agent、汎用NLE、無制限stacking。
- 新しい本文・改行・字幕時刻・保持判断の生成。
- 新規素材・書体・モデル・依存の取得、有料API、新たな外部素材送信。
- 正式trust・Normal基準・renderer正式版・契約path会計の改訂、main merge、tag、stable、release。

特定jobだけに許可されたtrust snapshotは再利用しない。新たな信頼入力を自己承認して正式受入を通さない。ツールの拒否を別経路へ迂回しない。

**人間入力がないだけで停止しない。** 代替・延期・分離を検討し、別承認が必要な実行だけを保留する。独立して進む候補は続行する。一方、待機を避けるためだけの価値の薄いfixtureやschema追加はしない。

範囲外の新基盤・依存・外部送信・信頼変更が不可欠なら、具体的な対象、必要理由、限定代案を同じ相談役へGPT_DECISIONとして出す。本人判断が必要な事項を相談役が明示した場合に限り、その事項をHUMAN_DECISIONへ上げる。微差の見た目を説明してもらうことを停止理由にしない。

## 12. 完了条件

次を満たすまとまりで、工程Iの技術第一完成としてAUDIT_ONLYへ戻る。

1. 三方向を具体化し、既存再利用・新規実装・見送った候補を区別している。既存と異なる新しい見せ方が実描画されている。
2. 外観と動きが有限presetとして定義され、AIは任意描画値を出力しない。
3. 既存内容・字幕区間・元対応を保ち、意図した変化と不変条件を分けて検査している。
4. 新presetが固定案・一件override・Resetへ接続され、元自動案と他対象を壊さない。
5. 小型の実frame確認、故障注入、変更に関係する既存回帰が成立している。
6. 既存自動選択と共通描画を経た、新表現を含む候補動画1本を、必要な技術QC付きで提出できる。
7. Panel／Pulseを含む表現一覧があり、技術状態・採用状態・未検証の品質を区別している。
8. 指示書・実装・試験・報告の変更を選別してcommit／pushし、remote読戻しと既存作業保全を確認している。

「通常版に必ず勝つ」「全候補を動画へ強制使用」「全件の人間採点」「正式trustと全演出の認定完了」は、今回の完了条件に追加しない。

## 13. 報告・引継ぎ・次の工程

完了報告は同じ相談役会話へ一回、まとまった単位で送る。branch、base、checkpoint、compare、変更ファイル一覧と併せて、次を含める。

- 新しく作った見せ方と既存との差。外観・動作・安定／復帰・有限仕様。
- Panel／Pulseを含む再利用と採用状態の整理。
- 保存・自動選択・後修正・描画への接続と検査結果。
- 候補動画のpath／SHA、実際の使用箇所、割当の作成者、人間修正の有無。
- 内容・時計・音声・他対象の保全。未実行・失敗・未検証の正確な範囲。
- 設計選択や権限で残った事項。正式採用を技術監査へ代行させないこと。
- 当面の第一優先と次の計画上の工程を保持した引継ぎ参照。
