# 14.8.2 全比較QCの省メモリ化

担当: Codex2。着工基準: main `d65eba0a507218a5e2b3f6c606ec218cbe361344`。
状態: 実装・小型検証中。正常画像の整理方式は相談役監査前で、通常経路の自動整理は未採用。

## 目的と処理単位

保存初稿326字幕・424検査点の全論理候補、RGB実byte、距離、等価クラス、唯一最小条件を保持する。
全編描画・字幕PNG生成・STT・AI・有料APIは実行しない。旧画像、旧証拠、14.8.1の共有証拠、初稿は上書き・削除しない。

現物では、完成フレームの一括抽出と字幕PNGの共通準備・平面色変換は既に実装済み。
RGBも一候補ずつ読むが、比較用合成は一検査点の全候補を一processで出力し、
比較画像と距離の再利用参照を全検査点の終了まで保持する。
終了時に全生成物を再読し、統合QCはその実行列と画像一覧を完全照合している。

今回の処理単位は一検査点。既存の合成命令を、物理生成候補32件ずつのバッチで実行する。
32は実行単位であり候補数上限ではない。論理候補順を維持し、同じ背景・矩形・順序付き描画層に限って物理生成を共有する。
実byteによる等価クラス照合と距離計算は既存処理を利用し、代表画像と距離再利用の寿命を一検査点内へ閉じる。

## 保管方式の監査案

1. 完成側RGB、全比較RGB、距離・クラス・判定を確定する。
2. 既存の共有証拠保存を使い、検査点の再生成条件・固定入力SHA・tool/code SHA・全候補・実行列・全生成物SHAを保存し再読する。
3. 正常で唯一最小の検査点だけ、今回の排他的出力directoryで作った比較RGBを再照合して整理する。
4. 不合格点は比較RGB一式を保持する。子process失敗・不完全出力・取消・保存失敗は未完了として残し、正常扱いしない。
5. 背景/完成フレーム、完成側RGB、共通準備済み描画層、元字幕PNGは保持する。整理後は不存在を明示し、実画像を読んだという記録へ置き換えない。
6. 独立再検証は保存記録・必須入力を照合し、未使用directoryへ再合成してRGB・距離・クラス・判定を再計算する。

新版の実行方式と参照の保持状態を明示する。旧方式は履歴の旧版検証として区別し、欠損時に旧版へfallbackしない。
通常の保存・読戻しでは、保存記録と保持入力の検証と、整理済みRGBの再生成検証の範囲を区別する。

## 小型実証と通常経路

保存初稿の検査点0/1/18/54/118/163/164を使う。通常字幕、部分Color、Panel、Bounce/Shakeの動き、
同一PNGの別字幕000102/000103、元不合格000103を含む。全論理候補の順序・条件・RGBの実byteを旧画像と照合する。
旧コードの時間測定は着工HEADのnative moduleをGitから取り出し、相対importだけ実在URLへ置換して実行する。
関数本体は変更しない。全424点の旧合成は繰り返さない。

実行用の同じ保存済みフレーム/描画層を使うが、旧小型測定の全準備入力検証と、新方式の各点の入力検証・証拠保存は計測位置が異なる。
そのため生の全経過時間をそのまま速度比にしない。共通する切出し・参照合成・読込み・距離計算の時間と、
追加の新旧byte照合、入力照合、証拠保存、整理を分ける。OSキャッシュと他processの競合は制御していない。

最終コードの小型実測は [small-measurement.json](small-measurement.json)。Apple M3 Max・36GiB RAM・Node20.19.6。
7点の論理候補5,290件、物理生成5,203件は新旧同数で全件一致。GBは10進表記。

正常6点の整理後と不合格1点を、別Node processで再読・再生成した [revalidation.json](revalidation.json) では、

さらに別processで、再生成側と実際の旧コード側の全5,290参照対・完成側7対を直接byte比較し、すべて一致した。

実16×16・30frameの合成fixtureで、通常native検査→共通証拠保存→別Nodeでの再読→全編再現証拠との統合判定を確認する。

### 保存・再読の接続で見つかった既存不具合

全編再現証拠の旧validatorは、実行入力JSONを復元したobjectから再文字列化してbyte照合していた。
14.8.1の共通保存はobjectのkey順を正規化するため、内容が同じでも別processの再読で拒否される。
変更前コードを使った小型試験で再現した。

新しい全編再現証拠だけを明示的v002にし、実行時の入力JSON本文を保存する。
元artifactのSHA・byte数と本文を厳密照合し、解析した内容も固定計画・字幕画像対応・合成入力と照合する。
旧v001の照合規則と保存物は変更しない。画像、合成命令、検査条件を変える修正ではない。
今回の全424点では保存済み全編再現結果を利用し、元入力本文をSHA照合して参照する派生証拠として区別する。
全編再描画で埋め合わせない。
