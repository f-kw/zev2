## 時刻処理と保存形式の接続不具合

追加判断が合格した後、既存字幕時刻処理を実行した。製造に使用する区間は325件すべて正の長さ・保持区間内・隣接重複なしである。音響観測で両端が解決したもの271件、片側だけ43件、両端未解決11件。後二者は既存処理の明示的な元書き起こし端点へのfallbackを使用しており、音響同期が全件確定したという意味ではない。人間同期は未評価。

正式JSON保存の前に、未観測の任意診断欄8か所へJavaScriptの未定義値が残り、保存が拒否された。エラーログを保存し、純粋な再構築で上記時刻結果を確認した。診断ファイルでは未定義を明示した記号表現で記録し、時刻値は変更していない。

新しい製造接続moduleへ、未観測を示す任意の診断欄だけをJSONの欠落へ写す処理を実装した。採用時刻や他の欄が未定義の場合は拒否する。この2つの検査は合格したが、正式時刻保存の再開、動画製造、Core、rendererはまだ実行していない。追加意味判断・追加音響観測はない。

## 今回の停止原因と具体的な修正案

新しい回帰検査4件中3件合格、1件不合格。失敗したのは「依頼改訂前後で元入力が不変」の検査で、同じ内容のbyte列を参照同一性で比較している。失敗TAP自身が「同じ構造だが参照が等しくない」と記録している。入力が改変されたという検出ではない。

対象: `evals/clip_composition/digest_v1_phase2_caption_revision.test.mts` 16行目。修正案は1行のみ：

```diff
-  assert.equal(formal(original), bytes);
+  assert.deepEqual(formal(original), bytes);
```

**この修正は未実施。** 既存 `caption-adapter-development-correction-v001.json` に設営訂正累計5回が記録されている。今回の比較検査の訂正を行うと6回目になる。[AGENTS.md](../../AGENTS.md)の設営起因自走修正上限5回と、超過時の停止・報告規定により、Codexだけでは実行できない。規則の変更や上限の再設置はしていない。

推奨する第1層判断は、**この比較方法の1行訂正を今回に限り追加1回認め、検査合格後にすでに承認された字幕時刻保存→共通Core→renderer→technical QC→MP4へ戻ること。** 字幕の第3回判断や保持結果・本文・styleの変更は含めない。上限全体の恒久改訂も求めない。
