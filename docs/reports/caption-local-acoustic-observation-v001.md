## 4. 観測前に固定した方式

既存の固定本文整列と同じ、保存済み `Systran/faster-whisper-large-v2` のCT2モデルを一つだけ使った。CPU・float32、既存環境の `faster-whisper 1.0.3` と `ctranslate2 4.3.1`、日本語の固定本文token列による整列である。新しい文字起こし、別モデルとの比較、download、推論API通信は行っていない。

- モデル本体SHA-256：`bf2a9746382e1aa7ffff6b3a0d137ed9edbd9670c3b87e5d35f5e85e70d0333a`
- 最終観測実装SHA-256：`258fd83dfb82886e5edadbc5b94b6768b9b9060e52e9262173a4e73743d3568f`
- 最終実走前の固定記録SHA-256：`a65a52b05c824b27a7d310b155363b40b42bba2facf2fdf3a2f907112d4c88c1`
- 無変更のselector SHA-256：`3b0e9b7d5ff1cd1eb599c4635c264e8c3a430307d9a7fe530f9453819998fbed`

全モデル構成ファイル、実装・実行環境、入力音声、本文、媒体対応のSHAは、観測前の固定記録に保存した。ローカルのモデルpathだけを読み、offline設定とsocket通信の拒否を有効にした。既存の変換済みモデルの実行に不要なtorch/tensorflow変換機能を読み込まない方式も、従来の実行方法を引き継いだ。

windowと再観測は、実行前に次の順序で固定した。

1. 正式字幕の本文IDから、元の認識単位と既存の30秒音声chunkを特定する。本文・ID・順序が一致することを照合する。
2. 各chunk内で、採用媒体との交差、対象本文の元の認識区間、現在の字幕表示を元音声へ写した区間を含む範囲を初回windowとする。chunk外へは広げない。音声sampleへ直す際だけ外向きに丸める。
3. windowに交差する元の認識本文と対象本文を、元のID順の連続した固定本文として整列する。字幕がchunkをまたぐ場合は、その部分ごとに観測し、対象字幕の最初と最後の境界を別々に保持する。
4. 対象端がwindow端に接した場合だけ、元の30秒chunk全体とその固定本文へ一度拡張する。初回から全chunkなら再観測しない。必ず最後の観測を使い、都合のよい結果を選ばない。
5. 拡張後も端に接する境界、token群の内部に入る本文端、長さ0の単位、正長にならない候補は未確定のまま残す。端の扱いは、モデルの既存20ms整列格子の最初・最後の1セルに基づく。

20msはモデルが元から持つ時間分解能であり、今回の人間正解に合わせた閾値やoffsetではない。token内部補間、近傍tokenからの推測、STTとの平均、固定offset、正式字幕frameの書き換えはない。

37字幕に対して最終採用実走の整列は48回。拡張した字幕はダイジェスト9件、遠方接続2件で、無制限retryは0件。整列処理に記録された経過時間の合計は456.337秒である。モデル読込・SHA照合・検査・UI作業などはこの時間に含まれず、人間レビュー時間でもない。

## 8. 成立した範囲と限界

成立したのは、**完成字幕から音響観測を自動で用意し、既存条件のまま人間確認へ回す経路**である。遠方接続の「材料がないため4件すべて判断不能」は解消し、1件は表示との非重複という根拠、3件は観測境界が未確定という根拠を持って確認対象へ移った。

一方で、遠方接続は4件すべて確認対象であり、ダイジェストも確認対象が増えた。観測を自動生成すれば今回より少ない字幕だけを見ればよい、という効果は確認できていない。大半の既知問題が境界未確定で選ばれている点、強制整列は発話の存在や正しい発声位置を保証しない点、未評価の字幕が多い点を残す。観測が付いたことと、正しい同期を測れたことを分けて扱う。

この結果を良く見せるためのselector条件追加、モデル比較、windowの後付け変更、追加の人間評価は実施しない。推奨する監査上の扱いは「観測供給と要確認への接続は成立。確認対象をさらに絞る価値は未実証」である。
