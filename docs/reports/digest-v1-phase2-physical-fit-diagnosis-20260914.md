# ダイジェストv1 Phase 2 — 文字サイズだけの物理容量診断

2026-09-14 JST。診断結果は **95pxが最大安全整数サイズ**。現行96pxから1px減らすメモリ上のprobeで、元の23件すべての安全領域違反が解消し、既存302件の新規違反は0となった。全325件の行の交差・行数超過・画面外・その他の配置違反も0。正式styleへの適用と再描画は行っていない。

今回の指示は「DIAGNOSE / DO NOT RERENDER YET」。保存済み入力・結果から同じ原因かを確定した後、文字サイズだけをメモリ上で変更する診断を行った。checkpointと相談役への報告は診断結果の現物固定であり、正式styleの採用承認ではない。

## 診断1：現失敗の再現と原因

前回失敗時の配置入力を既存の配置検査関数へ直接渡し、保存済みの結果と325件全量・全フィールドで完全一致した。前回のrenderer失敗記録内の配置結果とも完全一致した。

325件すべてが論理幅上限36以下。違反23件はいずれも最大論理幅36の行を含み、縁取り・glowと安全paddingを加えた外枠の幅が1776pxとなる。同じ画面の安全領域の幅は1760pxなので、23件すべてが16px超過する。原因の混在は0。行数超過、行同士の面積を持つ交差、上下の安全領域違反、canvas外へのはみ出しはない。

既存計算から得た内訳は、文字本体1728px＋左右の装飾40px＋左右の安全padding8px＝1776px。縁取り設定は8px、glow設定は12pxで、既存計算による片側の装飾幅は20px。安全paddingは4pxのまま。独自の係数は導入していない。

この配置検査はNode上で動作し、DOMがないため、既存の文字幅計算を使う。ブラウザ上の実フォント輪郭や完成動画を測定した結果ではない。今回確定したのは、前回失敗と同じ配置検査を通過する最大サイズである。
