# AUDIT\_RESULT — P1：字幕画像生成の起動共有・一件後修正の高速化

## decision

P1を技術的第一完成として受理する。
今回確認した範囲に、必須reviseはない。

監査対象：
9ac340600ef9d7fcd4b7a7dadc1d16612be13a02

比較元：
3168836bb255d989b18fc7fc440a6fdb68fc17f1

受理範囲は、既存のPanel一件・Shake一件について、
画像生成の重複初期化を減らし、描画結果と検査内容を維持したまま、
適用検査から周辺媒体取得までの時間を短縮した技術実証である。

人間品質、全入力での性能保証、実編集UI受入、正式trust、
原版置換、別工程の着工は、この受理に含めない。

## finding

### 1. 再利用をjob内へ限定している

新しい共有環境は、一回の適用検査または周辺描画jobが所有する。
通常系列と再現確認系列は別ブラウザーで描画し、
受け付けたpropsを待機前に固定する構成を確認した。

同じ不変bundleを共有しても、通常PNGをコピーしただけで
再現確認を済ませる処理にはしていない。

実編集の適用検査と周辺描画の両方へ接続し、
既存の一枚完結アダプターを一律に共有寿命へ変更していない。
常駐サービスや複数job共有の可変描画環境も追加していない。

### 2. cacheの同一性条件と独立再現を維持している

cache keyは描画profileと完全なpropsを基準としており、
今回の高速化のために一致条件を緩めていない。

同じ行マスク等が通常系列で連続要求された場合も、
cacheへ新規登録する二枚は異なる描画系列を使う。
異なる出力先とPNG一致を確認してから登録する構成である。

既存出力へのコピーは上書きを拒否する。
cache再利用を新規描画として数えず、件数と時間も分離している。

### 3. 失敗・取消・資源回収の処理を確認した

画像はjob所有の一時領域で作成し、出力の種類・寸法・
PNGの枠組み・要求との対応を確認してから公開先へ渡す。

失敗後に前の成功画像を代用せず、
描画失敗・取消後の追加要求を拒否する。
観測記録の保存失敗でも資源回収を省略しない構成である。

適用検査・周辺描画とも、成功結果の保存前にcloseし、
finallyでも終了処理を行う。

試験には、描画中取消、準備中の終了、起動途中の失敗、
観測保存失敗、別jobと処理外の子processの保全が含まれる。

この確認を、試験していない全OS・全終了タイミングへの
無条件の保証には広げない。

### 4. 旧新の同一性は、報告値だけを比較する構成ではない

比較処理では、保存された旧新要求と実ファイルを読み、
props、出力の役割、native/cache件数、局所計画、
字幕適用結果、検査状態・時刻・候補を対応付けている。

提出記録の成立範囲は以下。

・90出力すべてのPNG byte一致。
・同一byteをまとめた23種類の全RGBA比較と、
90出力への対応を保持。
・別途22件のcache保存画像と独立描画の証拠を照合。
・53検査点、1,727論理候補の実RGB・距離・分類・合否が一致。
・PanelとShakeの完成MP4が旧新でbyte一致。
・各完成MP4と、対応する厳密再合成MP4もbyte一致。
・保存内容と表示計画を別processで再読して一致。

23種類のRGBA比較を「90種類を個別に復号した」とは記録しない。
一方、全90出力のPNG byte確認と対応表があるため、
重複画像の復号を省いたことを未検査の画像省略とも扱わない。

完成MP4の旧新共通SHA：

Panel
0a030a3b88fc883c0ec4212dd00b4c599b2133917c192a1c98968bd7e3fc42cb

Shake
aff15c4832d775b563419adbd255a3d502fc083dc7d78a48987dbb4e0dfe56be

### 5. 性能比較の測定境界は揃っている

今回の測定は、適用検査の開始から、
保存・周辺描画・完了確認・HTTP全body取得まで。

描画環境の準備をAfterだけ測定外へ出していない。
既存サービスの起動前からの総時間や、
本人のブラウザーでの操作時間とは区別する。
```
             Before       After        短縮量       短縮率
```

Panel             62.871秒     55.527秒      7.343秒      約11.7%
Shake            198.450秒    142.416秒     56.034秒      約28.2%

差と比率は丸め前の記録値から計算したものとして保持する。

旧新で、新規PNG数はPanel 10、Shake 64、
cache再利用数はPanel 2、Shake 14のまま。

字幕画像用ブラウザー起動は10→4、64→4。
新方式の4起動は、適用検査と周辺描画それぞれに
通常・再現確認の独立環境を持つ結果として扱う。
全ての子processの総数が4という意味ではない。

主合成・厳密再合成・有限状態QCは維持されている。
準備と新規作画の削減を、検査の省略で得た短縮にはしていない。

各入力のBefore一回・最終After一回の実測であり、
中間実装の測定も別に保持されている。
完全コールド試験、統計的benchmark、時間保証ではない。

完成媒体再利用は約0.61→0.62秒であり、
この部分の高速化は今回の成果に含めない。

### 6. 実証の操作と検査件数を広げない

実入口で使ったのは、固定自動指定へ戻る既存Resetである。
新しい意味判断や新しいoverrideを作った実証ではない。

Panel・Shakeの適用検査、保存要求、初回周辺描画、
媒体取得を通したことは受理するが、
任意の表現変更や全ての一件編集操作を今回実証したとはしない。

試験は、提出された26件、5件、実画像1件、
参照不一致拒否probe3件、既存関連負例5件の区分を保持する。

各runのskipや中間再実行は成功件数へ加算せず、
全既存試験を通したという報告にも変えない。

## instruction

P1はこの技術受理で閉じる。
追加の性能閾値、追加benchmark、旧検査の全量再実行、
新しい比較動画・人間採点は要求しない。

今回の結果から「一件後修正の待ち時間問題が全て解消した」
とはしない。特にShakeの初回取得は約142秒であり、
主合成・厳密再合成・有限状態QCの時間は残っている。
残る性能課題と、今回のP1完了を分ける。

元10回答、修正後7ポイント、Q3-2候補、Q4入力不足、
既存の利用者保存状態・媒体・ブラウザー制約は保持する。

この回答は、P2その他の高速化工事、品質修正、
新しい意味解析、正式採用、原版置換、ショート開発の
追加着工指示ではない。

監査回答を実際に受領できた時点で、
既存の「監査回答未受領」記録へ今回の受理を追記してよい。
過去のストリームエラーや送信記録は、その時点の履歴として残す。

受理記録の保存が必要な場合も、必要な文書差分だけにする。
実装・媒体・性能試験をやり直さず、
記録保存だけのために同じ完成監査を繰り返さない。
