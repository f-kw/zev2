# ZEV 目標定義書

v3.5 / 2026-07-17改定（無音・間の具体的な詰めを人間の手直し領分として明記）

## 1. この文書の位置づけ

本書はZEVの目標と関門の正本である。v2の原本ファイルはリポジトリへ導入されておらず、`docs/HANDOVER.md` §2に保存されたv2要約と`DECISIONS.md`の追記記録を基に、今回承認された変更を加えてv3として正本化した。

v2から変更したのは、第一・第二関門の手直し条項である。AI単独の境界精度ではなく、1配信につき人間へ提示する候補を上位5件へ絞り、その中から公開する3〜5本を仕上げられるかで測る。仕上がる動画量は合計10分程度とする。15分は合否基準ではなく、システムが人間へ強いる作業量の暴走を検知する上限ガードである。人間を計時せず、必要な品質のために自発的に長く使ったことを不合格にしない。再現率、初見データ原則、第三関門、評価・版管理の原則は変更しない。

## 2. 最終目標

**ファンと新規が確実に観る切り抜きを、毎配信・自力で・数分の手直しで出せる。**

- バズは物差しにしない。
- 完全自動を目標にしない。人間の短い手直しを含む一連の運用が成立することを目標にする。
- 迷ったときは「その作業は、人間の手直し時間を減らすか、選択眼を実績に近づけるか」で判断する。

## 3. 改善対象の3層

1. 選択の質: どの場面を切り抜くか。現在の主戦場。
2. 演出: 選んだ場面をどう見せるか。第一関門通過まで凍結。
3. 運用: 毎配信で無理なく使えるか。現状維持し、操作ログを捨てない。

## 4. 評価原則

- 教師は、堅実に観られている実在切り抜きとする。
- 実績との一致で測る。正解データを仮説やモデル出力へ寄せない。
- 数字、版数、生成系統を必ず記録し、一度に一変数だけ変える。
- 複数区間fixtureのLLM評価はruns 3以上とする。ただし上界確認など、目的を事前登録した単発実験は区別して記録する。
- 正解データと人間が手直しした最終境界の認定権は人間にある。
- 最終判定は、改善に使っていない配信者・ジャンルの初見データで行う。この原則は変更しない。
- 開発データ上の到達を、関門の正式通過と呼ばない。

## 5. 関門

### 第一関門: 自分で使える

開発者本人が、1配信から人間がまず見るべき**上位5候補だけ**を確認し、そのうち公開する3〜5本を、候補確認・境界調整・区間内編集の指示まで仕上げられること。全候補の処理は要求しない。仕上がる動画は合計10分程度を想定する。

ここで「仕上げる」とは、採用判断、開始・終了、必要な区間内カット、無音除去を**編集指示として保存するところまで**を指す。動画の書き出しは含めない。「区間内編集で公開候補」は仕上げ可能性の見込み判定であり、編集指示を保存するまでは仕上げ本数へ数えない。

区間内編集の指示は、「無音・言い淀みを詰める」「内部カットが必要」のように、必要性と種類が後続工程へ伝わる粒度でよい。人間へ複数の内部カット点を一つずつ指定させることは、実編集と同等の作業を確認段階で重ねるため要求しない。外側の開始・終了は人間が明示し、内部の具体的な切断位置は後続の編集工程で決める。

無音・間の具体的な詰めは人間の手直し領分とする。システムは「無音・言い淀みを詰める」という必要性と種類を保存するところまでを標準とし、層1の自動カットを標準処理へ昇格させない。これは、声VADで安全に短縮できた3件では劣化がなかった一方、対象が全58区間中3件・1素材に集中し、自動化の適用範囲が狭かった実測に基づく。間の多い素材型または非発話シグナル課題の起動時に再検討できる。

15分は、人間へ持ち込む作業量が暴走していないかを検知する上限ガードである。人間の実作業時間は通常測らず、15分を超えたかどうかで合否を決めない。人間が負担過多と感じた場合は、原因A「候補・境界・文脈・UIの不足によりシステムから強制された修正」と、原因B「人間が品質や好みのため自発的に追加した編集」を分けて振り返る。改善対象は原因Aであり、原因Bをシステム失敗へ数えない。

### 第二関門: 実績と並ぶ

次の両方を満たすこと。

1. 実績区間の再現率6割。
2. 1配信につき人間への提示を上位5候補へ抑え、その中から公開する3〜5本を編集指示まで仕上げられること。仕上がる動画は合計10分程度を想定する。

15分は第一関門と同じく作業量暴走の上限ガードであり、合否の計測値ではない。全候補の確認・処理は要求せず、人間が品質上必要と判断した追加時間を制限しない。第二関門で測る手直し性能は、時間そのものではなく、システムに強制された修正の量とする。

仕上げ完了の終点と区間内編集指示の粒度は第一関門と同じで、動画の書き出しは含めない。

旧v2の「AIが単独で境界ずれ平均±3秒」は合格条項から外す。境界ずれ自体はモデル診断と将来改善の参考値として保存し続ける。

### 第三関門: 他人に出せる

改善に使っていない配信者・ジャンルの初見データと、開発者以外の利用者で、第二関門と同じ水準を維持すること。

## 6. v3改定理由

2素材38正解の判断材料上界診断では、開始・終了の両境界をテキストだけで判断できる正解は4/38だった。boundary-v001も±3秒成功が固有1正解に集中し、第二素材では0件だった。これにより、テキスト入力だけで実在切り抜きの境界をAI単独±3秒へ揃えることには構造的な天井があると判断した。

一方、テーマからv012までの接続は、限定開発データで高い到達を維持した。したがって、広めの成立区間を外さず提示し、人間が音・映像・間合いを見て境界を詰める役割分担へ変更する。これは最終目標の「数分の手直し」を、人間へ持ち込む候補数と動画規模を抑える運用仕様へ変える改定であり、完全自動化からの後退ではない。

初回手直しでは、1候補の内容判断に約3分かかった。24候補すべてを同じ深さで確認すると約72分となり、最終目標に合わない。したがって候補を先に順位付けし、人間が上位5件だけを確認して3〜5本を仕上げる運用を関門の単位に固定した。

改定根拠:

- 判断材料上界診断: `evals/clip_composition/reports/theme-composition-connection/20260713-boundary-text-judgability-diagnosis-v001.md`。両境界をテキストだけで判断可能だった正解は4/38。
- 手直し基準: `evals/clip_composition/reports/human-boundary-trim/human-boundary-trim-trial-v001-baseline-result-20260713.md`。絞り込み・単語境界スナップなしでは約3分/件、24候補へ外挿して約72分/配信。

## 7. 手直しデータの扱い

- 手直し前の仮区間、最終境界、採否、区間内編集の必要性と種類を保存する。人間に内部カット点の列挙を要求しない。人間の所要時間や操作履歴は、個別に計測を承認された試験でない限り保存しない。
- 強制修正量は、AI候補の採用数、AI開始・終了の無修正採用数、境界修正回数、開始・終了それぞれの修正量、追加候補・追加文脈の要求件数を別々に記録する。独自の係数、重み付き合成値、単一スコアは作らない。
- 人間が自発的に選んだ内部カット、演出追加、品質向上のための延長は原因Bとして別記し、原因Aの強制修正量へ混ぜない。
- 人間が公開可能と認定した最終境界は、既存fixtureを上書きせず、由来を持つ別の正解データとして保存する。
- 蓄積データは、テキストで再現できる境界だけを限定自動化する将来案と、boundary-v002以降の教師候補に使える。
- 操作ログから自動化案を作る場合も、dev/test分割と初見データ原則を維持する。

## 8. 上限ガードの運用と改定手続き

- 実行部隊は、1配信につき上位5件を超える候補を一度に人間へ提示しない。追加候補が必要な場合は、上位5件の結果を報告し、追加件数と理由を申告して人間の許可を得る。
- 完成動画合計10分程度は出力規模の目安、15分は人間作業量の暴走を検知する上限ガードである。人間側の時計を常時動かさず、超過を不合格にしない。負担過多が観測された場合だけ、原因Aと原因Bを人間が振り返り、原因Aの修正回数・修正量を次の改善対象にする。
- 再現率6割、上位5件、公開3〜5本、完成動画規模の目安、初見データ原則、第三関門を変更する場合は、別の大きな方針転換として事前理由と影響を記録し、本書、`DECISIONS.md`、`docs/HANDOVER.md`を同一コミットで更新する。
