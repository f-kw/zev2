## 1. プロジェクトとは何か

- **ZEV(リポジトリ名 zev2)**: STTで文字起こしした音声情報を基にAIが動画編集を行うシステム。開発者(kawafmm)個人のプロジェクトで、**この方式について特許を取得済み**。
- 最終ターゲット: **中堅Vtuberが自分の配信から切り抜き動画を自力で作れる**ようにする。
- 開発者は本業で業務用AIサービス(AI面接)を開発。「正解が定義できない領域では決裁者の合意をゴールにする」「プロンプトの直接確認による透明性」「基礎データ+顧客側の+α」等の知見を持ち、ZEVと相互輸入している。

## 2. 目標定義(確定済み・変更には慎重に)

正本は目標定義書v3.4。要点のみ:

- 最終目標: **「ファンと新規が確実に観る切り抜きを、毎配信・自力で・数分の手直しで出せる」**。バズは物差しにしない。
- 3層: 第1層=選択の質(**現在の主戦場**)、第2層=演出(凍結中)、第3層=運用(現状維持)。
- 評価原則: 実績との一致で測る / 教師は堅実に観られている切り抜き / 判定は数字・版数管理・一度に一変数 / **最終判定は初見データ(変更禁止)**。
- 運用規律: 生成系統の明記必須 / 複数区間fixtureはruns 3以上 / 正解データの最終認定権は人間。
- 関門: 第一「自分で使える」→第二「実績と並ぶ(再現率6割・1配信につき人間へ見せるのは上位5件、その中から公開3〜5本を編集指示まで仕上げる)」→第三「他人に出せる(初見データで同水準)」。仕上がる動画合計10分程度は規模目安、15分は作業量暴走を検知する上限ガードであり合否基準ではない。負担過多時は、システムに強制された修正（原因A）と、人間が品質のため自発的に追加した編集（原因B）を分離する。仕上げ完了は採否、外側境界、区間内編集の必要性と種類を保存した時点で、動画書き出しと内部カット点の列挙は含めない。旧v2のAI単独境界±3秒は合格条項から外し、診断値としてのみ残す。**現在地: 正式初見素材DmWu0jVQfTEで公開候補4/5、AI境界の無修正採用は開始4/4・終了3/4。相談役支持とkawafmmの最終判断により第一関門を正式達成。次は選択品質を変えず実運用原価を下げる段階**。
- 迷ったら: 「その作業は、人間の手直し時間を減らすか、選択眼を実績に近づけるか」。

- 外部記憶4点: 目標定義書v3 / DECISIONS.md(追記式、「凍結・保留中」節のみ更新式) / システム構成PDF v2 / 本資料。

- **人間作業量の事前申告義務**: 人間へ確認・選択・視聴・境界調整を依頼する前に、件数×1件あたり推定時間と合計に加え、独立に答える総判定数、1セッションの判定数、予定セッション数、分割順を申告する。1回は5判定前後を上限とし、正解認定・関門判定ほどさらに必要最小限へ絞る。30分超の見込みは警告と削減案を先に出す。見積りは実行部隊が持ち込む量の制約であり、人間へタイマーを課さない。実測は個別承認時だけ。作業なしの場合も0件・0分と書く。詳細は`DECISIONS.md`「人間資源の原則」と`docs/WORK_INSTRUCTION_TEMPLATE.md`を正本とする。

## 4. 本体システム(zev2)の概要

- pnpm workspace: shared / backend(Express) / client(Vue3) / runner(AIエージェント) / scripts / runtime(state.json+artifacts)。
- 7工程: prepare_video → run_stt → propose_clip_themes → build_clip_composition → create_edit_plan → apply_adjustment → render_video。人間確認ゲート3箇所。
- 設計原理: **「LLMは意味判断のみ、数値・配置はルールで決定的に。決定ログは残す」**。
- 重要: 現行のテーマ提案・構成(区間決定)は**ルール処理**(LLM不使用)。LLM使用は create_edit_plan(Gemini)とWeb Geminiレビューのみ。**区間選択・テーマ生成のLLM化は評価環境で開発中の新機能**。
- リファクタ状況: R-1・R-2完了。R-3〜R-5保留。R-7(Cookie強化)は外部公開の前提条件。

## 5. 評価環境(evals/clip_composition/)— 現在の主戦場

- 本体から隔離。依存は評価環境→runner/src/steps の一方向のみ。UI/API/DB化はしない(意図的)。
- 凍結ガード: fixture凍結には人間確認+固定テーマが必須。未確認では書き込み自体が失敗する。
- 実行系: run_eval(ルール) / build_prompt_payload(LLM入力生成、リーク検査付き) / run_web_gemini_prompt(Web Gemini自動実行) / score_prompt_output(採点、数値創作ガード付き) / compare_prompt_results。
- 生成系統: **baseline-rule** / **llm-vNNN** / **theme-llm-vNNN** / other-*。result.jsonに必須記録。2026-07-10以後の新規LLM採点結果は、実モデル名を付けた `llm-v012@gemini-web-flash` 形式。既存result.jsonは変更しない。
- 採点思想: 合成スコアを作らず、差分・一致数を人間可読で並べる。非対称採点(期待区間外の選択は即減点しない=未ラベルの可能性)。unresolved区間は採点対象外(excludedRanges)。
- 製造パイプライン(**手順書化済み**: FIXTURE_MANUFACTURING_RUNBOOK.md): 取得→自前STT(単語時刻。分割応答は抽出音声の厳密なチャンク境界へ正規化し、生応答と補正件数を保存)→DP大域照合→素材ブロック再構成(飛び10秒以上が境界)→確認パッケージ→人間確認→固定テーマ(人間が逆算)→凍結。
- 重要な定義: expectedCutsの境界=素材対応の切り替わり点。同一素材内の詰めはinternalGapMs注記。品質等級=素材ブロック粒度(±1秒測定限界)/高精度サンプル。人間確認は「当時の手段の解像度における事実」として履歴管理。
