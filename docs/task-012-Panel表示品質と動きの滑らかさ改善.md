## 作業A — Panelのセンタリングを必須品質として成立させる

### 範囲

- 背景板に対して字幕が綺麗にセンタリングされていないという、POINT 2とPOINT 4に共通する違和感を解消する。
- 実装着手が認められた段階で、実際に描画される文字と背景の配置関係を調べ、ずれの原因と修正の根拠を記録する。計測方法や実装手法はこの文書で先決めしない。
- 独自の係数、根拠のない位置補正、特定の字幕だけを見た場当たり的な調整でセンタリングが成立した扱いにしない。

### 受入観点

- Panelの背景と字幕が、綺麗にセンタリングされて見えることを必須品質条件とする。
- 対象の配置がなぜ成立するかを、調査結果と修正内容から説明できる。
- 修正後の代表箇所を短いPoint Reviewで確認する。背景の意匠やフェードの好みと混ぜず、センタリングの修正を判断できる単位で示す。
- 「目立ちすぎないこと」をPanelの固定制約として追加しない。

現在の状態: **未調査・未実装・修正後の確認未実施**。

## 作業B — 色違いだけに留まらない背景バリエーションを用意する

### 範囲

- Panelの背景に、画像・テクスチャ・意匠そのものが異なる種類のバリエーションを用意する。
- 色違いだけを追加して、この要求を満たした扱いにしない。
- 背景の違いを活かしながら、作業Aのセンタリングを満たし、字幕を読める状態にする。必要な場面で強く目立たせることは許容されている。
- 素材の案・種類数・入手先・作成手段は、この整理で先行確定しない。新素材取得や生成、API利用・費用が必要になる場合の権限は増やさない。

### 受入観点

- 背景の違いが、画像・テクスチャ・意匠の違いとして見て分かる。
- 追加した背景でも、字幕の読みやすさとセンタリングが成立する。
- 別版の代表箇所を短いPoint Reviewで提示し、どの背景について何を確認するかを明確にする。選択位置全般や全編の使い分けの合格へ広げない。

現在の状態: **素材・実装案未確定、未実装・修正後の確認未実施**。

## 作業C — 原因を特定し、動きの滑らかさを改善する

### 帰属調査と範囲

- 本人の不満は「拡大縮小が荒く、カクカクして見えること」。機能の強さや目立ち方を弱める要求ではない。
- POINT 3はBounce / Shake / Pulse等を同じ短い区間で見た回答である。原因となるpresetやスケール変化は未確定であり、人間の発言を特定presetだけへ割り当てない。調査前に特定presetを原因と認定したり、原因候補から除外したりしない。
- 実装着手が認められた段階で、保存された対象・時刻・描画状態と実装上の変化を対応させ、どの動作がカクつきに結び付くかを調べる。人間の原文と、実装側が特定した原因を区別して記録する。
- 必要に応じて補間、中間状態数、easing / motion curve、frameごとの変化量などを検討する。これらは調査観点であり、採用する手法・値・係数をこの文書で確定しない。
- 原因が確定した範囲を修正し、動きを弱くしたり目立たなくしたりして問題を隠さない。

### 受入観点

- どの動作をどの根拠で修正対象にしたかが明確で、人間が特定presetを指摘したという記録に置き換わっていない。
- 拡大縮小を含む対象の動きが、自然に滑らかに見える。
- 本人が高く評価した動きの機能と表現力が保たれる。
- 修正後の代表箇所を短いPoint Reviewで確認する。一つの問いから修正の成否を帰属できる単位で示し、複数演出をまとめた回答を個々の演出へ機械的に配布しない。

現在の状態: **原因presetと変化箇所の帰属未調査・修正未実装・修正後の確認未実施**。
