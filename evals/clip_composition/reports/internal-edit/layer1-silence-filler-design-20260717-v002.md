# 層1（音響発話不在+単語時刻）実装前設計 v002

作成日: 2026-07-17

状態: **設計提示・実装未承認**

人間作業: 現在0件・0分。次の依頼は設計採否1件、資料確認の目安3〜5分。タイマーは要求しない。

## 1. 目的と単変数

層1v001は単語時刻だけでは音響的な発話不在を見つけられず、カット指示0件だった。v002は入力へ**声ベースの発話不在区間**を追加する。外側境界、フィラー契約、400ms候補化、前後120ms保護、出力形式、レンダリング、保護優先は変えない。

笑い声検出、音量スパイク、境界精緻化、層2の意味間引きは含めない。

## 2. 診断根拠

実装前診断では、C分類30件の混合音量無音は0件、WebRTC VADの緩い設定と厳しい設定の双方で400ms以上の声なしが見えた箇所は18件だった。音量無音なし・声なしありも同じ18件で、BGM・ゲーム音が音量無音を隠す予想を確認した。

保護正解3件も3/3で声なしだったため、音響信号だけでは切らない。v001の保護規則を外すと、反応待ちとゲーム上の間を誤って消す。

## 3. 入力

1候補ごとに次を入力する。

- 確定済み外側境界。
- 元配信の音声。
- 現行の単語・文字タイムスタンプ、発話まとまり、話者情報。
- WebRTC VAD mode 0とmode 3から決定的に作った声なし区間。

教師切り抜き、expected、DP照合、人間ラベルは評価時だけ使い、候補生成へ渡さない。

## 4. 音響候補

1. 元配信音声を16kHz monoへ変換し、20ms単位でWebRTC VAD mode 0とmode 3を実行する。
2. 双方が「声なし」とした状態が400ms以上連続する区間だけを音響候補にする。
3. mode 3だけが声なしの区間は判定不能として保護する。結果を見た後に片方だけを採用しない。
4. FFmpegの混合音量無音が得られた場合は強い補助証拠として保存するが、今回の開発5fixtureでは0/33であり、必須条件にはしない。

これは声の不在を示すだけで、削除可否は示さない。

## 5. 単語時刻との二重根拠

音響候補の前後に、元の順序を保った入力内の単語が存在し、カット後も残る語列が入力語列の部分列になる場合だけ次へ進める。音響候補をまたいで一つの文字時刻が伸びているなど、前後の単語を一意に対応づけられない場合は判定不能として保護ログへ送る。

単語時刻を音響無音の証拠としては使わない。音響は声の不在位置、単語時刻は前後の本文・語順・話者・発話まとまりの確認に役割を分ける。

## 6. 保護規則

v001の保護をそのまま継承する。

- 話者不明、話者交代。
- 発話まとまり不明、発話まとまり境界。
- 外側境界に接する候補。
- 前後120msを残すと正の削除区間が残らない候補。
- 前後単語を入力内で一意に対応づけられない候補。

加えて、v001設計で保護した問い・依頼・挑発・宣言から回答・反応・ゲーム結果まで、オチ前の溜め、笑い・泣き・叫びの収束、末尾余韻を削除可とみなさない。v002の決定処理だけで意味保護を証明できない場合は切らず、理由を保存する。

保護正解3件はすべて音響ギャップを持つため、**音響候補になったことを保護解除の理由にしない**。

## 7. 出力

v001と同じ内部カット指示、保護ログ、残す元動画範囲を出す。各カット指示へ次の音響証拠を追加する。

- WebRTC VAD両設定の声なし開始・終了。
- 各設定の最長連続時間。
- 混合音量無音の有無。
- 前後の単語識別子・本文。
- 適用した前後120ms保護後の実削除開始・終了。

動画連結は既存の複数範囲レンダリングを使う。本体へは接続しない。

## 10. 手法の限界

- WebRTC VADはボーカル曲BGM、ゲーム内ボイスを人声と誤認し得る。
- 笑い、叫び、息の扱いは一定しない。v002では専用検出を追加しない。
- 混合音量はBGM・ゲーム音で無音を見失うため、主判定にできない。
- 音響上の声なしと、編集上不要な間は同義ではない。保護規則が安全性の中心である。
