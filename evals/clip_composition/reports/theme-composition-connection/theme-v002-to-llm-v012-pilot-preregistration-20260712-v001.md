# theme-llm-v002 → llm-v012 文脈パイロット事前登録

## 目的

hit済みテーマ候補を `llm-v012@gemini-web-flash` へ渡す条件付き接続評価で、テーマ生成時の窓だけを文脈にするか、前後5分を追加するかを本走前に比較する。

この文書を書いた時点ではパイロットを実走していない。差分を見てから残り候補の文脈条件を決め、決定理由を記録する。

## 三段階の成功基準

各run×候補を次の順で判定する。

1. **一致**: その候補が上流の正式範囲hit採点で重なった全expectedに選択区間が1ms以上重なり、それぞれの代表選択区間の開始差・終了差がともに±1000ms以内。
2. **到達**: 少なくとも1件の対象expectedと1ms以上重なるが、一致条件を満たさない。
3. **不達**: 対象expectedとの重なりが0件、または出力JSON・区間・必須理由・発話ID表現が契約を満たさず採点可能な出力にならない。

複数expectedへ重なる上流候補は、全件へ到達し全件の両境界が±1000ms以内のときだけ「一致」とする。1件だけ届いた場合は「到達」とする。

人間の正解にない選択区間は未ラベル候補の可能性があるため、それだけで三段階を降格させない。別欄へ件数と区間を残す。人間除外区間だけに重なる選択も別欄へ残し、到達には数えない。

## 3 runの候補単位集計

- **最良**: `一致 > 到達 > 不達` の順で、3 run中もっとも高い判定を表示する。
- **多数決**: 同じ判定が2 run以上ならその判定。3判定が1票ずつなら「多数決不成立」と表示し、別の係数や優先順位で決めない。
- run間で選択区間数または到達expected集合が変われば構造の揺れ、構造が同じで境界だけが変われば境界の揺れとして記録する。

## 比較する文脈

| 条件 | 文脈 | 変えないもの |
| --- | --- | --- |
| テーマ窓のみ | 上流テーマ候補を生成した保存済み入力窓の全発話 | 候補発話ID、テーマ文、v012、モデル、出力契約、採点器 |
| 窓±5分 | 同じ窓の開始より300000ms前から終了より300000ms後までのsource-only発話 | 同上 |

前後5分は、保存済みの完全な元配信STTを、テーマ生成と同じ決定的な文章結合規則で作る。切り抜き、expected、DP照合、素材ブロック、人間確認結果を入力へ使わない。

拡張文脈を追加しても候補発話IDは増やさない。追加発話は文脈として候補印なしで渡す。これにより、変更する変数を文脈量だけにする。

## 実走と報告

- 2条件×3候補×3 run = 18回。
- EdgeのWeb Geminiを使い、各結果保存後にタブを閉じる。
- すべてのモデル入力で漏洩検査を行う。
- 生成系統は `llm-v012@gemini-web-flash`、上流は `theme-llm-v002@gemini-web-flash`。
- 結果には「hit済みテーマ限定の条件付き成績」と明記する。
- 三段階分布、根拠範囲長に対する選択区間長、範囲内不達／範囲外選択／出力形式、構造または境界のrun間揺れを比較する。

## 本走文脈の決め方

結果を見た後の恣意的な選択を避けるため、次の順で比較する。重み付き合成値は作らない。

1. 候補単位の多数決で「一致」が多い条件。
2. 同数なら、多数決で「到達」が多い条件。
3. なお同数なら、候補単位の最良で「一致」が多い条件。
4. なお同数なら、候補単位の最良で「到達」が多い条件。
5. なお同数なら、構造の揺れが少ない条件。
6. すべて同じなら、追加文脈の効果が観測できなかったとして「テーマ窓のみ」を本走に採用する。
