# boundary-v001 実走前設計案

作成日: 2026-07-13

## 1. 目的

上流テーマ生成の広い根拠範囲は変更せず、`llm-v012@gemini-web-flash`が返した仮区間だけを、独立した境界専用段で精緻化する。

接続構成は次の3段とする。

1. theme-llm-v002: 見どころがある広い範囲を拾う。
2. llm-v012: テーマに属する仮の発話群・仮区間を作る。
3. boundary-v001: 仮区間の開始点と終了点だけを局所文脈から選び直す。

上流根拠範囲の絞り込み、テーマ候補の取捨、仮区間の分割・追加・削除はboundary-v001の仕事に含めない。

## 2. 先行診断の結論

2素材38 expectedCuts、76境界を、fixture用に切断された文字起こしではなく凍結前の元配信全域ローカルSTTで診断した。

| 分類 | 件数 | 割合 |
| --- | ---: | ---: |
| 現在の圧縮発話境界と完全一致 | 8/76 | 10.5% |
| 圧縮発話の途中 | 68/76 | 89.5% |
| 非発話区間 | 0/76 | 0.0% |

現在の圧縮発話の開始・終了だけを境界候補にすると、両境界±1秒の理論上界は6/38、±3秒は16/38、±5秒は24/38。圧縮発話IDだけでは第二関門の境界尺度を十分に表現できない。

一方、元配信全域ローカルSTTの未圧縮単語境界とは76/76境界が0ms一致し、両境界0msの表現可能性は38/38だった。したがってboundary-v001には単語タイムスタンプを必須入力として追加する。

非発話区間は0件だったため、boundary-v001では音量・笑い・無音などの非発話シグナルを追加しない。別fixtureで非発話境界が出たときにだけ再検討する。

注意: expectedCutsは単語対応を使った素材ブロック製造で作られているため、単語境界38/38は「ラベルを表現できる」という上界であり、モデルが意味的に正しい単語を選べることの証明ではない。

## 3. 固定するもの

- 対象素材: `nOEWCNc77MI_multiblock_material_v001`、`9dtwF5Exu5w_multiblock_material_v001`。
- 対象候補: connection-v001と同じ25候補。
- 上流テーマ出力: `theme-llm-v002@gemini-web-flash`の保存済み結果。
- 仮区間: connection-v001の`llm-v012@gemini-web-flash`保存済み75 run。
- boundaryモデル: `gemini-web-flash`。
- expectedCuts、除外区間、入力選定、テーマプロンプト、v012プロンプト、採点器の三段階・四段階定義。
- 生成系統: `boundary-v001@gemini-web-flash`。結果には上流系統として`theme-llm-v002@gemini-web-flash → llm-v012@gemini-web-flash`も記録する。

単変数は「v012の後ろに、単語境界IDを選ぶ境界専用段を追加すること」だけとする。

## 4. 入力契約

各v012 runの各仮区間について、次を入力する。

1. 仮区間の番号、開始・終了時刻、v012が使った圧縮発話ID、v012の理由。
2. 仮開始点の前後90秒にある圧縮発話と未圧縮単語タイムスタンプ。
3. 仮終了点の前後90秒にある圧縮発話と未圧縮単語タイムスタンプ。
4. 開始側と終了側の窓が重なる場合は重複単語を1件にまとめる。

90秒を選ぶ理由は、ユーザー指定の60〜90秒の上限であり、保存済みv012到達観測79件では、真の開始・終了がともに局所窓へ入る件数が±60秒で51件、±90秒で61件だったため。実走後に窓幅は動かさない。

真の両境界が±90秒へ入らない18観測は、boundary-v001の既知の入力上限として結果に明記する。1仮区間が4 expectedCutsへ重なる候補16は、2点選択では原理的に分割できないため、全3 runをboundary-v001の成否対象とWeb Gemini呼び出しから除外する。候補16が到達した8観測は全79観測の従表へ「構造的対象外」として表示するが、失敗には数えない。区間分割は別変数として将来課題へ登録する。

入力にexpectedCuts、切り抜き時刻、DP照合、人間確認メモを入れない。使用するのは元配信全域ローカルSTTと保存済みv012出力だけとし、全入力でリーク検査を行う。

## 5. 出力契約

モデルに数値時刻を生成させない。入力内に決定的に付与した単語境界IDだけを選ばせる。

```json
{
  "refinements": [
    {
      "provisionalCutIndex": 1,
      "startBoundaryPointId": "word-001234:start",
      "endBoundaryPointId": "word-001267:end",
      "startReason": "開始点を選んだ理由を1文",
      "endReason": "終了点を選んだ理由を1文"
    }
  ]
}
```

ルール側が境界IDを時刻へ変換し、次を検査して最終区間を組み立てる。

- 出力件数が入力された仮区間数と同じ。
- 仮区間番号が重複・欠落しない。
- 開始・終了境界IDが入力に存在する。
- 開始時刻が終了時刻より前。
- 理由が各1文存在する。
- 選択した境界IDに対応する単語と前後2語を、モデルの理由文と一緒に結果へ保存する。これにより、形式上は実在するが桁を誤って別の場所を指した事故を人間が事後確認できる。

仮区間の追加・削除・分割・結合は許可しない。これにより、テーマ選択・構造判断と境界判断を混ぜない。

観測上はv012到達79件のうち開始が早い73件、終了が遅い73件で、主な仕事は両側からの刈り込みである。ただし開始が遅い3件、終了が早い3件もあるため、ルールで「必ず内側へ動かす」とは強制しない。正しい単語境界が局所窓にあれば、外側への補正も選択可能にする。

## 6. 実走単位

- connection-v001の候補25件×既存3 run、合計75件を出発点として対応関係を保存する。
- 候補16の3 runを構造的対象外にする。残る72 runのうち、v012出力が形式成立し仮区間を持つ71件だけをWeb Geminiへ送る。
- 候補16以外でv012自体が形式不成立だった1件はboundary段を実行できないため、追加呼び出しをしない。
- 1件のv012出力に複数仮区間がある場合も、1回のboundary入力で仮区間数を維持したまま処理する。
- Web Geminiの結果保存後は、その処理で開いたタブを閉じる。

## 7. 採点と比較

主比較は、同じfixture・候補・run・正解区間のv012仮区間とboundary-v001後の区間を対応させる。結論に使う主表は、真の開始・終了境界がともに±90秒入力内で見える61観測とする。v012が到達した全79観測は従表にし、候補16の8観測を構造的対象外、残る71観測を採点対象（入力内61・入力外10）として並記する。

報告する指標:

1. 開始ずれ・終了ずれの符号付き実数値。
2. 絶対ずれの平均・中央値・P75・P90。
3. 各境界の±3秒内率・±5秒内率。
4. 両境界とも±3秒内、両境界とも±5秒内の件数。
5. 四段階: 一致±1000ms / 関門水準±3000ms / 到達 / 不達。
6. 共通到達観測での2境界絶対ずれ合計: 改善 / 同値 / 悪化。
7. 候補単位の多数決到達数と、境界段によって到達を失った件数。
8. 出力形式不成立と境界ID不正の件数。
9. 発話境界方式の両境界±3秒上界16/38に対し、単語境界方式が38正解のうち何件で実測上回ったか。これは候補・runをまたぐ最良観測として補助表示し、主結論の61観測とは混ぜない。

未ラベル区間を自動減点しない非対称採点は継続する。

## 8. 採否案

実走前の提案として、係数付き合成スコアは作らず、次を別々に判定する。

- 境界改善: v012で0件だった「両境界±3秒」の件数が増え、共通到達観測で改善件数が悪化件数を上回ること。
- 到達維持: 構造的対象外の候補16を除く24候補について、候補単位の多数決到達を確認すること。

両方を満たした場合のみboundary-v001を次段の候補とする。両境界±3秒が0件のまま、または成否対象24候補の到達が悪化した場合は採用しない。結論文は主表61観測を基準とし、全79観測の従表だけを根拠に採否を変えない。

この採否条件と追加3条件は2026-07-13に人間承認済み。入力生成・リーク検査・採点器固定後に実走へ進む。

## 9. 制約と既知の限界

- 2素材とも開発データであり、正式な第二関門判定には使わない。
- ±90秒で両正解境界が見えるのは既存到達79観測中61件。61件を主表、79件を従表にし、boundary-v001の失敗と入力不可視を分けて表示する。
- 候補16の8到達観測は2点だけを選ぶ境界段では解けないため、対象外ラベルを付けて成否から除外する。
- 単語境界0ms上界はfixture製造方式との整合を示すもので、意味選択能力の上界ではない。
- 非発話境界は今回0件なので、非発話シグナルを先回りで追加しない。
