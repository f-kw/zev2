# connection-v002 事前登録

## 変更する1点

接続入力と区間選択プロンプトを、同一契約の両端として同時に変更する。

- `candidateSpeechIds` / `isThemeCandidate`: 探索範囲の枠から、テーマ中心を示す照準へ変更。
- 周辺文脈: テーマ窓の前後各5分を継続し、候補印のない発話も境界探索空間として読む。
- プロンプト: `clip_composition_prompt_v013`。根拠範囲の端を写さず、中心を含む適切な区間を自分の境界判断で切る。
- 入力には `connectionContract.version=connection-v002` と役割を明記する。

入力構築だけ、またはプロンプトだけを独立変数とは数えない。意味契約を両端で一致させる1設計変更とする。

## 固定するもの

- 同じ25候補、各3 run。
- `gemini-web-flash`。
- テーマ窓前後各300000ms。
- 上流 `theme-llm-v002@gemini-web-flash` と `input-selection-v004`。
- 三段階採点。一致は対象expected全件へ到達し両境界±1000ms以内。
- 候補単位の最良と多数決。
- usedSpeechIdsの構文・start≦end・入力内端点実在検査。
- 非対称採点、漏洩検査、Geminiタブ終了。

## 主比較

connection-v001の一致0/75、到達以上73/75、完全写し65/75、範囲内別場面事故0を比較元として固定する。

1. 一致runと到達以上runの変化。改善と取りこぼしのトレードオフを分ける。
2. 完全な写しの変化。
3. 形式成立だが対象expectedへ1件も到達しない「範囲内で別場面を選ぶ事故」の件数。

## 撤退条件

独自の割合閾値は置かない。比較元では25/25候補が3run多数決で到達以上だったため、次の両方を満たしたら棄却する。

- connection-v002で多数決到達以上の候補が25未満になる。
- 一致runが0のまま。

これは、候補単位で観測できる最小の明確な到達悪化である。該当時はv012+写し許容の設計へ戻る。
