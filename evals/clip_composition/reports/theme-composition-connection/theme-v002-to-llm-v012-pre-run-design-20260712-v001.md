# theme-llm-v002 → llm-v012 接続評価 実走前設計

## この試験で見ること

`input-selection-v004` で入力を選び、`theme-llm-v002@gemini-web-flash` が正解区間に重なる根拠を出したテーマだけを、`llm-v012@gemini-web-flash` へ渡す。上流で見つけたテーマが、最終的な切り抜き区間へ変換された後も実績区間と重なるかを測る。

これはhit済みテーマに条件を絞った接続評価であり、全候補を通したend-to-end性能とは呼ばない。

この文書の時点ではWeb Geminiを実走していない。

## 対象の固定

正式範囲hit採点で `hitExpectedIndexes` が1件以上ある候補をすべて対象にする。正解を丸ごと含む「過広範囲」も範囲hitには含まれているため除かない。

| --- | ---: | ---: |
| `nOEWCNc77MI_multiblock_material_v001` | 13候補 | 12/13 |
| `9dtwF5Exu5w_multiblock_material_v001` | 12候補 | 15/25 |
| 合計 | 25候補 | 27件 |

## テーマを区間選択入力へ変換する規則

### テーマの説明

- タイトルは上流候補のタイトルをそのまま使う。
- 要約と切り抜ける理由には、上流候補の理由文をそのまま使う。上流に存在しない新しい要約を生成しない。
- 場面の選び方には、全候補共通で「提示された候補発話範囲の中から、テーマが単独で成立する最小区間を選ぶ。」と渡す。正解ごとの指示は作らない。

### 広い根拠範囲の扱い

1. 上流テーマ候補が記録した根拠発話IDだけを展開する。数値、数値文字列、`375-376` のような連続表記を受け付ける。
2. 複数の表記の間にある、明示されていない発話IDは補わない。たとえば `375-376,381-390` から377〜380を追加しない。
3. 候補発話IDは、展開した根拠発話IDの重複を除いた和集合とする。
4. 前後の文脈には、その候補を生成したテーマ入力窓の全文をそのまま再利用する。新しい前後秒数を決めない。根拠発話だけを候補印あり、同じ窓のそれ以外を候補印なしにする。
5. 複数の根拠範囲がある場合は別々の発話まとまりとして保持し、範囲間の空白を埋めない。
6. 上流候補が転記した開始・終了時刻から発話IDを推測しない。根拠発話IDを正本にして、保存済みのsource-only入力から時刻と本文を復元する。
7. 根拠IDが同じ元動画の入力窓に存在しない、同じIDで時刻か本文が食い違う、切り抜き・固定テーマ・正解由来情報が混入した場合は実走前に停止する。

特に別素材の候補16は、約283秒の根拠が正解10〜13にまたがる。正解を見て4つへ切らず、明示された疎な発話ID `375-376,381-390` をそのまま候補として渡す。複数区間に分けられるかは `llm-v012` 自身に判断させる。

## 固定するもの

- 区間選択プロンプト: `clip_composition_prompt_v012`
- 実モデル: `gemini-web-flash`
- 生成系統: `llm-v012@gemini-web-flash`
- 上流系統: `theme-llm-v002@gemini-web-flash`
- 入力選定: `input-selection-v004`、チャット流速上位100分
- テーマ生成時の入力窓と窓分割: 保存済みのものを再利用
- Gemini操作: Edgeを使用し、各結果の保存後にタブを閉じる
- 既存fixture、expectedCuts、除外区間は変更しない

既存の凍結fixture用入力生成は、人間が逆算した固定テーマと切り抜き由来の文字起こしを読むため今回には使わない。接続評価専用の最小変換処理を `evals/clip_composition/` 内へ追加し、出力は `outputs/theme-composition-connection/` に隔離する。

## 実走回数

複数区間fixtureは3 run以上という既存規律を維持する。25候補をそれぞれ独立に3回実走し、合計75回のWeb Gemini呼び出しとする。run間の出力を和集合にして成績を膨らませず、runごとの結果と揺れを別々に表示する。

## 採点

正解はモデル入力へ渡さず、結果保存後の採点だけで読む。

- 各候補が上流で重なった正解区間と、区間選択後の結果を対応させる。
- 同じ正解へ複数の選択区間が重なる場合は、既存採点と同じく、重なりが最大のもの、開始差が小さいもの、終了差が小さいものの順で代表を決める。
- 人間が除外した区間だけに重なる選択は採点対象外として別記する。
- どの凍結正解にも重ならない選択は、未ラベルの可能性があるため即減点せず「未ラベル選択」として件数と区間を出す。
- 合成スコアは作らない。

主に表示するのは、上流で届いた正解数、区間選択後も重なった正解数、接続保持率、全正解に対する到達数、完全一致／重なり／欠落、開始・終了の差、正常完了候補数、未ラベル選択数、除外区間選択数、3 run間の構造差である。

## リーク防止

- 実走対象一覧には候補番号だけを置く。正解番号、正解時刻、範囲hit分類をモデル入力生成側へ渡さない。
- 接続用入力生成は、生の上流テーマ結果、保存済みsource-only窓、候補番号一覧だけを読む。凍結正解、人間の固定テーマ、DP照合、素材ブロックを読まない。
- 採点は、全Gemini出力が保存された後の別工程で初めて凍結正解を読む。
- 実走前検査で、25候補すべての根拠IDの存在・一意復元、source-only、禁止情報不在、v012プロンプトの固定、3 run、タブ終了設定を確認する。
