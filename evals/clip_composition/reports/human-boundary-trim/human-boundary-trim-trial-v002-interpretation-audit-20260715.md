## 結論

「手直しコストは関門水準に到達し、律速はランキングの素材間安定性へ移った」という結論は、現存する正本からは確定できない。

理由は次の2点。

1. 7分57秒・4分18秒・12分15秒の原記録がなく、この試験は時間を測らない契約へ変更済みだった。
2. B素材の正式な公開本数は2本で、提示された3本と一致しない。

数字を無効化することと、「ランキングが次の改善候補かもしれない」という仮説を捨てることは別である。第二素材の机上診断は行ったが、既存ラベルだけではランキング失敗と候補群の薄さを二択にできなかった。

## 1. 時間と公開本数の出所監査

| 提示された値 | 正本・履歴で確認できたこと | 扱い |
|---|---|---|
| B素材 7分57秒 | 現作業木とGit履歴に原記録なし | 採用しない |
| 第二素材 4分18秒 | 現作業木とGit履歴に原記録なし | 採用しない |

| B素材 公開3本 | UI v003正式結果は公開2・選ばない2・文脈不明1 | 矛盾するため採用しない |
| 第二素材 公開1本 | UI v003正式結果と一致 | 1本だけ維持 |

commit `1ac91f99`で、人間の直接指示「時間を測るな」に従って手直し確認v002から時間測定を撤去した。正式結果にも「操作時間を記録していない」「15分条項を判定していない」と明記されている。

旧UIの10回答は`progress-invalid-unusable-ui.json`へ隔離され、`useForScoring: false`である。旧結果にも今回の3つの時間値は残っておらず、正式結果の代わりに使えない。

B素材についてリポジトリ内に存在する別の「3」は、candidate-ranking-v002上位5の**既知hit 3件**である。この3件はcandidate 32・37・46だが、UI v003で人間が公開としたのは32・46、37は「選ばない」。既知hitは「実在切り抜きの区間と候補の根拠範囲が重なる」という評価ラベルであり、人間の公開判断ではない。数が一致するため混同の一例は考えられるが、提示された3本の出所自体は未確定である。

したがって、次は正本へ記録しない。

- B素材が時間・本数とも関門条件を満たした
- 2素材合計12分15秒だった
- 手直しコスト問題が解消した
- 第一関門を素材1本で通過した

7分57秒・4分18秒が別途ストップウォッチで測った人間申告なら、新しい証拠として受け取れる。その場合は、計測方法、B素材の3本目のcandidate ID、後述する「候補7」が確認順か候補IDかを明示し、UI v003の機械計測値ではなく別の人間申告として保存する。

その追加情報が揃った場合、提示文の読み方自体は妥当である。B素材は15分以内かつ3本で条件内、第二素材は15分以内だが1本で本数未達となる。ただし関門の計測単位は配信ごとなので、2素材合計12分15秒は作業量の参考値であり、配信単位の合否を置き換える値ではない。

## 2. 「候補7」の由来と根拠範囲

手直し確認v002の対象10件にcandidate ID 7はない。対応し得るのは、確認順7番目のcandidate 57である。

| 項目 | 内容 |
|---|---|
| fixture | `9dtwF5Exu5w_multiblock_material_v001` |
| candidate | 57 |
| ranking | 2位 |
| 題名 | 劇的勝利に大絶叫し涙を流すマリン船長 |
| 仮区間 | 11,010,002–11,106,471ms |
| UI v003人間区間 | 11,010,002–11,121,986ms |
| 正式判断 | 公開する |

仮開始と人間開始は同じ11,010,002msである。正式結果、旧無効結果、Git履歴のどこにも「開始位置が対象と無関係」「唯一の中断理由」という記録はない。そのため、この一言を正式な失敗理由としては採用しない。

一方、根拠発話の範囲には別の構造上の弱点候補がある。同じtheme生成窓で、次の2候補が別々に出力されていた。

| candidate | 時刻 | 内容 | 発話ID |
|---:|---:|---|---|
| 56 | 10,848,424–11,005,829ms | スクイズを巡る葛藤とバント職人への信頼 | 1244–1259 |
| 57 | 11,010,002–11,106,471ms | 長い絶叫、涙、安堵、勝利後の反応 | 1260–1263 |

両者の間は4,173msの無発話区間である。根拠発話上は、candidate 56が直前の葛藤、candidate 57が絶叫・涙・勝利確認を持つ。candidate-ranking-v002は時刻やtranscript本文ではなく題名・理由だけを見て反応側を上位化し、手直しUIはその根拠範囲を仮区間へ直接使った。

ただし映像はこの机上診断で確認していない。ゲーム上の決着が4,173msの無発話区間に映っている可能性もあるため、「themeが勝負そのものと反応を分割した」「公開に必要な前振りが失われた」とは確定しない。確定できるのは、candidate 57の入力にcandidate 56の葛藤発話が含まれないことまでである。

処理の流れは次のとおり。

`根拠発話上で葛藤候補と反応候補が別々に出力 → 題名・理由だけで反応候補を上位化 → 反応候補の根拠範囲をUIの仮区間にする`

candidate 57はテーマ正式採点でrange-hitなしのoff-topicだったため、`llm-v012`の接続実走対象ではない。したがって、この候補の入力範囲を「v012+写し許容の弱点が実地で出た」とは記録しない。直接確認できるのは、反応候補だけの根拠発話が手直しUIの仮区間になったことまでで、文脈不足の原因確定には映像確認が別途必要である。
