# candidate-ranking-v001 机上検証・実装前設計

登録日: 2026-07-13

## 1. 目的

1配信から生成されたテーマ候補を「人間がまず見るべき順」に並べ、上位5候補だけの確認で公開する3〜5本を選べる状態を作る。全候補を人間へ見せない。

## 2. 母集団

- B素材: input-selection-v004で生成済みの全89候補
- 第二素材: input-selection-v004で生成済みの全60候補

接続評価の24候補は、expected区間へhitした候補を正解参照で抽出した集合なので、ランキング母集団には使わない。24候補だけの順位付けは本番に存在しない情報を使うリークになる。

## 3. 採点

各素材で候補を信号ごとに単独順位付けし、上位5候補について次を出す。

1. 全expectedのRecall@5: 上位5候補の根拠範囲と重なるexpected数 / 全expected数
2. 入力内expectedのRecall@5: 上位5候補と重なる入力内expected数 / 入力内expected数
3. Precision@5: expectedへ1件以上重なる上位候補数 / 5
4. 上位5が覆ったexpected番号

expectedは採点だけに使い、候補特徴の計算には使わない。結果を見て上位件数5を変更しない。

## 4. 単独で比較する信号

合成スコアと係数は作らない。次を別々に順位付けする。

- チャット流速・ピーク: 候補根拠範囲と重なる1分区間の配信内平均比の最大値。高い順。
- チャット流速・区間平均: 候補根拠範囲と重なる1分区間の配信内平均比を、重なった時間で平均。高い順。
- 根拠範囲長: 全根拠範囲の合計。短い順と長い順を両方出し、結果を見て向きを後付けしない。
- 笑い表記密度: 候補根拠範囲内の元配信STTで、文字`笑`または連続する半角`w`/`W`2文字以上を1表記として数え、対象文字数で割る。高い順。2種類へ重みは付けない。
- 生成順: 既存出力順を比較基準として保存する。

テーマ生成のreasonは自然言語で、現時点では大小関係を持たない。文字数など根拠のない代理値へ変換しない。機械信号で上位5が不十分な場合に限り、reasonだけを読む意味判断段を別の単変数として設計する。

## 5. 同点

同値は候補番号の昇順で決定的に並べる。同時に5位と同値の候補数を記録し、同点群が残り枠より多い信号は「上位5が一意に決まらない」と明記する。同点順を能力として解釈しない。

## 6. 採否

2素材だけなので恒久標準は決めない。

- 両素材で生成順より全expected Recall@5が悪化しない信号: candidate-ranking-v001の実走候補。
- 一方だけ改善または同値: 仮説として併記し、人間判断。
- 両方で悪化: 単独信号として棄却。
- 5位同点が大きく上位5を一意に作れない: 主信号にはしない。

採用候補がない場合、reasonの意味判断段を次の単変数として設計する。複数信号の合成は、各単独信号の結果を報告して人間承認を得るまで行わない。
