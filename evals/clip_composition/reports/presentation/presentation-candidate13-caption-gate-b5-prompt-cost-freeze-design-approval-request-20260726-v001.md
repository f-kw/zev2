## 2. 本来の目的

B5の目的はGeminiを早く呼ぶことではない。

B3の正式入力とB4の表示計画契約の間に、次を後から動かせない形で置くことである。

1. Geminiに見せる情報。
2. Geminiへ依頼する仕事。
3. APIへ送る正確なbyte列。
4. 使用モデルと実行条件。
5. 入力tokenの機械計測と一回分の費用上限。
6. 正解情報を見せていないことの検査。
7. 一回だけ送信し、無効回答を修復・再送しない停止契約。
8. B6が保存する生回答と実行来歴の形式。

これをGemini回答の取得後に決めると、回答に合わせてprompt・受入条件・費用条件を動かせる。B5をB6より先に独立させるのは、この過適合経路を閉じるためである。
