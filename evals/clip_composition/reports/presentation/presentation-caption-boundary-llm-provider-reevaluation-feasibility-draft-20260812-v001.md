# 字幕境界選択LLM provider再評価 実現性調査下書き v001

## 1. 目的

本運用の拡大前に、同じ字幕境界選択仕事を複数providerへ与え、単価だけでなく、受入schemaへの適合と人間が読む字幕の質を実測比較する。現行GeminiとGPT-5.6 Luna候補を比較対象とする在庫論点の下ごしらえである。

本書は読み取り専用調査の下書きであり、API接続・通信・単価確定・実装を含まない。

## 2. 現物で確認できた比較基盤

- ZEVGが保持する意味字幕を、providerへ見せる境界片とIDへ変換するsource package契約がある。
- providerへ見せる情報はcaption本文を境界片として一度だけ、境界ID、style上限、仕事本文へ限定する設計である。
- provider回答はcue終端と行末のID選択だけで、本文と時刻は機械復元する。
- provider回答の暗黙正規化、fence除去、修復、silent fallbackを行わない受入経路がある。
- 生回答、provider envelope、usage、選択結果を別々に保存する設計がある。
- 現行B5/B6実装はGemini Developer APIのrequest・response形状を所有しており、第二providerのtransportやenvelopeはまだ実在しない。

## 3. 未成立・未確認

- GPT-5.6 Lunaの正式モデルID、利用可能endpoint、最新単価は通信0の本調査では未確認である。
- provider横断の共通transport契約は存在しない。
- ZEVO字幕品質v002の正式B6入力・回答pairは、現工程がLゲートで停止したためまだ新規生成されていない。
- provider差だけを比較できる人間認定fixture集合と採点票は未設計である。

## 4. 最小比較単位の案

比較時は、同じsource package byte、同じ仕事本文、同じstyle上限、同じ最大出力上限を各providerへ一回ずつ送る。provider固有のtransport envelopeは分け、providerへ見える意味入力は同一にする。

各回答について次を機械測定する。

1. strict JSON schema適合。
2. caption・境界ID・順序の全量閉包。
3. 一行で収まるcueを改行していないか。
4. 既知の不自然改行6境界を再選択していないか。
5. 入力token、出力token、list price換算費用、応答時間。

人間確認は同じ確認ページでprovider名を隠し、自然な意味小単位、前方文字の残留、改行の自然さだけを比較する。モデル名当てや一般的な好みは評価へ混ぜない。

## 5. 教師データの扱い

正式比較には、ZEVO字幕品質v002で保存される入力・生回答・受入結果・人間採否を一組の教師データとして使う。過去の意味選択Gemini回答は仕事が異なるため、そのまま字幕境界選択の品質教師とは扱わない。

選択・修正履歴は、どの境界が採用・差し戻しされたかと理由を版付きで保持し、将来のstyle別選択規則の蒸留材料にする。

## 6. 実装前に必要な設計判断

- 第二providerの正式実在性・単価・endpointを公式情報で照合する。
- API transportを共通化するか、provider別adapterを別成果物として保持するかを比較する。
- provider固有メタデータを意味入力へ混ぜず保存だけに留めるschemaを固定する。
- 一回あたりと全比較の支出上限、再試行0、raw先行保存を固定する。
- 効果が確認できなかった場合に、サブスク内エージェントまたは決定的機械処理へ戻る停止条件を固定する。

## 7. 人間作業見込み

比較対象を2 provider、同じfixtureを6件と仮定する場合、人間が見るのは匿名化した6組の二択と必要時の部分修正である。件数や時間は正式fixture確定前なので未確認であり、独自係数で見積もらない。

## 8. 結論

同一意味入力と機械受入検査を共用する比較は構造上可能である。ただし第二providerのtransport、正式モデル・単価、匿名比較fixtureは未実在であり、現時点で実走可能とは主張しない。ZEVO字幕品質v002の正式入力・回答pair成立後に、別契約・別承認で比較工事へ進むのが最短である。
