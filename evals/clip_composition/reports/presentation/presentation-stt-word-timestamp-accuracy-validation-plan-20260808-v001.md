## 1. 目的

STT単語時刻を、次の三用途へどこまで使えるかを分けて測る。

1. 配信全文から遠距離の意味サポート場面を探し、元位置を復元する用途。
2. 採用区間の開始・終了候補を人間へ示す用途。
3. 音声・映像を実際に切る厳密境界として使う用途。

粗い探索に十分でも、語尾を切らない厳密境界には不十分な場合がある。この三用途を一つの「精度」で合否にしない。

### ZEV設計理論メモv1との接続

- **(3)** 遠距離接続では基準点の配信内位置が必要なので、全文の大域時刻がずれないことを測る。
- **(5)** 面白さの符号は着地まで閉じたかに依存するため、語尾・反応終端の欠落を平均誤差に埋めない。
- **(7)** ミニドキュメンタリーの因果順を組むには、各segmentの開始・終了と字幕来歴を同じ時刻軸で復元できる必要がある。

## 3. 事実・推測・未確認

### 事実

- 1素材4点では、chunk境界由来の秒単位ドリフトは観測されなかった。
- qdczJpv8RCcのmanifest上、chunk境界で捨てた・丸めた単語は0件である。
- 文字粒度の短い時刻割当が実際の発声を覆わない例が、人間聴取で少なくとも1件ある。
- RMSの最大立上りやVADの声なしは、BGM・ゲーム音・息・笑いを含むため単語境界の正解そのものではない。

### 推測

- 大域時刻は遠距離探索の位置復元に使える可能性が高い一方、局所の開始・終了には誤差の裾と短時間tokenの別検証が必要である。
- 開始時刻と終了時刻、通常語と促音等の短時間token、chunk中央とchunk境界付近で誤差分布が異なる可能性がある。
- B工程では遠距離候補の探索より、採用後の切断境界でSTT誤差が品質事故になりやすい。

### 未確認

- 単語開始・終了それぞれの誤差分布、中央値、P90、最大値。
- 語尾欠け・語頭欠けの頻度と、token表示時間との関係。
- 配信者、話速、BGM、笑い、複数話者、chunk位置による差。
- STT時刻だけで実切断してよい条件。合格閾値は未設定である。

## 4. 検証母集団の作り方

正解位置を見て都合のよい点だけを選ばない。まず機械が次の層を全件列挙し、採用IDを版付きで固定する。

| 層 | 選定根拠 | 主に分かること |
|---|---|---|
| chunk境界 | 各30秒chunkの先頭・末尾に最も近いword | 累積ずれ・chunk接続事故 |
| chunk中央 | 境界から離れたword | chunk境界層との対照 |
| 短時間token | 保存時刻幅の短い順。既知20ms例を含む | 語頭・語尾の未被覆リスク |
| 発話まとまり終端 | 句読点、発話ID終端、話者切替直前 | 完成区間の終端品質 |
| 連続発話内部 | 前後gapがない文字 | 文字間分配の誤差 |
| 音響の複雑な箇所 | BGM、笑い、ゲーム内音声、重なり発話の既存証拠 | VAD/RMS補助の限界 |
| A/B実使用点 | 層1候補、遠距離候補、既存完成物のsegment端 | 製品上の実害へ直結する精度 |

件数は結果を見て決めず、列挙後に人間作業量と素材偏りを示してkawafmmが固定する。1回の人間確認は既存規律どおり最大5件前後とする。

## 5. 正解の作り方

1. 元媒体とword-timestampsのSHAを固定する。
2. 対象語の前後を十分含む短い音声付き動画と、波形・字幕文脈を機械生成する。
3. 人間には最初にSTT線を隠した媒体を提示し、聞こえ始め・聞こえ終わりを選ばせる。判別不能も正式選択肢にする。
4. 回答後にSTT開始・終了線を重ね、差を機械計算する。
5. VAD、RMS、STTのいずれも人間正解へ自動昇格させない。人間が確定した点を別の版付き正解候補として保存する。
6. 人間へ時刻の手入力や動画探索を要求せず、候補と前後文脈を機械が先に用意する。

## 6. 保存する測定値

- 開始残差 = STT開始 − 人間開始。
- 終了残差 = STT終了 − 人間終了。
- 絶対残差、符号、token表示時間、前後gap、chunk内位置。
- 実音声全体をSTT区間が覆ったか。平均が小さくても語尾欠けは別件数で表示する。
- 素材別・層別の件数、中央値、nearest-rank P90、最大値。開始と終了を混ぜない。
- 人間の`判別不能`件数。除外して精度を良く見せず、分母と理由を残す。
- A用途（候補提示）、B用途（遠距離位置復元）、実切断用途を別表にする。

独自係数や合成scoreを作らない。合否閾値は測定前に捏造せず、実測分布と完成物の人間所見を見てkawafmmが別途裁定する。

## 7. 判定の分岐

| 実測結果 | 設計へ返す内容 |
|---|---|
| 大域は安定、局所終端だけ不安定 | 全文探索にはSTTを使い、切断点は音響補助+人間確認へ分離 |
| chunk境界だけ偏る | chunk接続処理を原因候補として診断し、局所補正を全時刻へ広げない |
| 短時間tokenへ欠けが集中 | token時間の閾値を即採用せず、候補提示の注意情報と別評価を設計 |
| 素材・話者で分布が変わる | 一つの全体値で合格させず、適用条件または確認要否を素材型で分ける |
| 実切断にも十分 | 人間確認を減らせる範囲だけを、版付き契約として別承認へ出す |
