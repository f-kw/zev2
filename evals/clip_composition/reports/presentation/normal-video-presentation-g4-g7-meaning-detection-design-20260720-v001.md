# 通常動画版 G4〜G7 意味検出 設計 v001

日付: 2026-07-20

状態: **人間承認済み。元配信側入力の読み取り棚卸しで停止中。実装、入力生成、dry-run、LLM実走、比較媒体生成は未承認。**

## 0. 目的と限界

通常動画の演出文法第2版で認定したG4〜G7について、未編集の元場面から次の意味情報だけを作る。

- G4: 強調を検討すべき発話・反応と、映像だけで十分なため追加演出を抑える場面。
- G5: コメント、ナレーション、歌詞等の情報種別。
- G6: 複数人が話す場面での発話と話者の対応。
- G7: 発話だけでは参照先が分かりにくい箇所と、対応が確認できる補足素材。

この段階では、文字の大きさ、色、背景板、顔アップ、効果音等を選ばない。意味の印だけを出し、具体的な見た目はstyleプリセットへ渡す。

凍結正解は5件、抑制例は1件しかない。この評価は**入力から出力、形式検査、採点までが接続できるかと、重大な契約違反がないかを見る煙試験**に限る。一般精度、版の優劣、標準採用を主張しない。

## 2. 入力契約

### 2.1 生成側へ渡してよいもの

- 未編集の元配信または元候補場面へのファイル参照。
- 元配信単体から作った発話ID、開始・終了時刻、本文。
- 取得済みの場合だけ、話者IDと情報種別。無い値を推測で補わない。
- 採用候補の題名・テーマ理由・根拠発話ID。
- 利用可能な既存素材のID、出所、人物・作品等の別名。利用できない素材を一覧へ入れない。
- 入力生成に使った各上流版と生成系統。

### 2.2 渡してはいけないもの

- 教師切り抜き動画。既存のテロップ、ズーム、SE等が答えを漏らすため。
- GT-01〜05のID、正解時刻、正解ラベル、人間メモ。
- expected、切り抜きとの照合結果、採点結果。
- 人間が選んだstyleや、正解演出の見た目。

教師時刻を元配信時刻へ対応付ける処理は採点側だけで行う。confirmed対応が無い、または対応誤差を確定できない場合、その正解は`unscorable_source_mapping`として分離し、生成入力へ教師動画を代用しない。

### 2.3 入力の意味

入力は次の4部分に分ける。

1. 候補識別情報: 候補ID、元配信ID、元場面のファイル参照。
2. 発話台帳: 発話ID、本文、時刻、取得済みの話者ID・情報種別。
3. 上流の意味判断: テーマ題名・理由・根拠発話IDと生成系統。
4. 利用可能素材台帳: 素材ID、出所、参照対象の別名。

時刻はモデルに生成させない。モデルは入力に実在する発話ID・素材IDだけを返し、時刻範囲はルール側が再構成する。

## 3. 既存意味判断の再利用

### 3.1 固定する由来

G4へ再利用する既定入力は、`input-selection-v004`で選んだ元配信範囲を`theme-llm-v002@gemini-web-flash`へ渡して作った候補の`title`、`reason`、根拠発話IDである。人間へ見せる候補は`candidate-ranking-v002@gemini-web-flash`で選ぶが、その順位や順位理由をG4の正解代用にはしない。候補場面を区間へ接続した入力を使う場合は、標準接続`connection-v001`と`llm-v012@gemini-web-flash`（テーマ根拠範囲の写し許容）も同じ由来欄へ記録する。

理由は次の通り。

- テーマ理由は元配信単体から作られ、候補の内容と直接対応している。
- 順位理由は確認順を決める別目的の再記述で、局所発話IDを持たない。
- 既存理由だけではG4の正確な発火発話と「映像だけで十分」の抑制は確定できない。

したがって既存理由は**候補単位の意味の下書き**として再利用し、G4検出段は未編集映像と発話台帳から対象発話IDを局所化する。既存理由に強い反応が書かれていない場合も、入力に無い反応を創作しない。

### 3.2 上流版変更時の扱い

実走記録には、入力選定版、テーマ生成版とモデル、候補順位付け版とモデル、接続版、区間選択版とモデルを必須記録する。既定系統は`input-selection-v004`→`theme-llm-v002@gemini-web-flash`→`candidate-ranking-v002@gemini-web-flash`→`connection-v001`→`llm-v012@gemini-web-flash`である。途中の版が変わった場合は、その下流にあるG4入力と検出結果を同じ互換群へ混ぜない。旧教師等で一部の系統が適用されない場合は`not_applicable`と理由を記録し、近い版を推測して補わない。

## 4. G4〜G7の処理分担

### G4 強調候補・抑制

意味モデルが判断する。対象は、重要発話、間違いへの気づき、発見、強い感情の4種類だけ。入力に実在する発話IDを最小限のまとまりで返し、なぜ候補かを1文で説明する。

未編集映像だけで感情が十分伝わると判断できる場合は`抑制`を返せる。映像を入力できない場合、抑制を推測せず`判断不能`にする。強調方法は出力しない。

### G5 情報種別

取得済みの情報種別を決定的に写す。コメント、ナレーション、歌詞等の区分が入力に無い場合、本文の口調だけで推測せず`観測不能`にする。見た目は出力しない。

### G6 話者識別

入力に複数の実在話者IDがある場面だけ、発話IDと話者IDを決定的に対応付ける。単独話者、話者IDなし、話者が曖昧な場合は発火させない。人物名をモデルに創作させず、入力の話者IDだけを使う。

### G7 補足素材候補

意味モデルが、発話だけでは参照先が分かりにくい人物、元ネタ、過去場面等を発話IDで示す。補足素材は利用可能素材台帳に実在し、参照対象との対応根拠を説明できる場合だけ素材IDを返す。対応に確信がない場合は`付けない`。新規画像生成や外部素材探索へ自動移行しない。

## 5. 出力契約

出力はG4・G7の意味モデル結果と、G5・G6の決定処理を同じ論理計画へ統合する。

```json
{
  "schemaVersion": "presentation-meaning-output-v001",
  "sourceCompatibility": {
    "themeGenerationSystem": "実走時の版@モデル",
    "candidateRankingSystem": "実走時の版@モデル"
  },
  "marks": [
    {
      "markId": "入力内で一意なID",
      "grammarId": "G4|G5|G6|G7",
      "decision": "mark|suppress|abstain|not_observable",
      "targetAtomIds": ["入力に実在する発話ID"],
      "evidenceAtomIds": ["入力に実在する発話ID"],
      "reason": "入力だけに基づく1文",
      "triggerType": "G4の場合だけ文法第2版の4種類",
      "informationType": "G5の場合だけ入力に存在する種別",
      "speakerBindings": [],
      "assetId": "G7で対応確実な既存素材がある場合だけ"
    }
  ]
}
```

形式検査は次を拒否する。

- 入力に無い発話ID、話者ID、素材ID。
- 同じ`markId`の重複。
- 対象発話が空の`mark`または`suppress`。
- G6で単独話者しかない入力への発火。
- G7で素材不在・対応根拠なしなのに素材IDを付ける出力。
- 時刻、座標、文字サイズ、色、効果音名等、意味検出の範囲外の生成。

`abstain`と`not_observable`は失敗形式でなく、低確信・入力不足を正直に残す正式出力とする。

## 6. プロンプト設計

意味モデルへ問うのはG4とG7だけとする。G5・G6は入力にある構造化情報をルール側で写し、LLMに再推測させない。

凍結5件のうち、意味モデル自体の煙試験はG4肯定・G4抑制・G7の3件だけである。G5・G6の2件は、既存の情報種別・話者対応を失わず論理計画へ運ぶ配管検査であり、モデル能力の検査ではない。将来の結果報告も「意味判断3件」と「決定的な配管2件」を別表にし、合算した`5/5`をモデル成績として掲げない。

プロンプトは`presentation_meaning_detection_prompt_v001.md`へ保存する。具体的な教師例や正解時刻を含めず、次の順で指示する。

1. 入力外の出来事、人物、素材を創作しない。
2. G4は4種類の意味候補を発話IDへ局所化する。見た目を選ばない。
3. G4抑制は未編集映像で十分伝わる場合だけ。分からなければ判断不能。
4. G7は参照対象と既存素材の対応に確信がある場合だけ付ける。
5. 入力に実在するIDだけを返す。

## 7. 発火点と区間の採点条件

### 7.1 元配信座標への対応付け

採点前に、教師動画上の正解を元配信座標へ対応付けた別ファイルを凍結する。対応には人間確認済みのconfirmedペアだけを使う。対応が無い正解、または一点の対応を確定できない正解は採点不能とし、推測した前後幅で救わない。

### 7.2 一点時刻GT-01〜03

許容幅は**0ms**とする。これは映像編集の精度を0msで求める意味ではなく、正解データに存在しない採点窓を追加しないための契約である。

モデルが返した発話IDからルール側が対象範囲`[開始, 終了)`を再構成し、人間確認済み発火点がその範囲内にある場合だけ`発火点到達`とする。点が発話間の非発話位置にあり、入力IDで表現できない場合は`unscorable_input_granularity`とし、許容幅を広げない。

対象範囲を広く返すだけで到達できる交絡があるため、対象範囲長と発火点から両端までの距離を必ず並記する。ただしN=5の煙試験では独自の最大長を合否条件にしない。

範囲過大の記述分類は実走前から次で固定する。人間確認済み発火点を含む**最小の既存入力単位**（候補場面または発話まとまり）を基準にし、出力がその単位の外側にある発話IDまで含む場合を`overbroad_crosses_input_unit`、単位内に収まる場合を`localized_within_input_unit`、対応する入力単位自体を確定できない場合を`unclassifiable_input_unit`と記録する。これは到達と別欄の説明分類で、合否を変えない。新しい発話数や秒数の係数は作らず、発話数、範囲長、発火点から両端までの距離を生値で併記する。

### 7.3 区間GT-04・05

- G5: 人間認定区間と正の長さで重なる発話が正しい情報種別として出力され、対比区間を同じ情報種別へ誤分類しないこと。
- G6: 人間認定区間と正の長さで重なる発話に、入力に実在する複数の異なる話者IDが対応付くこと。

境界接触だけは重なりに数えない。前後許容幅は加えない。

### 7.4 文法別の判定

- G4肯定: 正しいG4種別で発火点到達。
- G4抑制: `suppress`で発火点到達。文字・SE等を出さない契約を維持。
- G5: 区間到達と情報種別の対比成立。
- G6: 区間到達と複数話者対応成立。
- G7: 発火点到達、参照対象、実在素材ID、対応根拠が揃う。

形式不成立、未検出、判断不能、観測不能、採点不能を別々に数え、合成点を作らない。
