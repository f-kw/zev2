## 1. 結論

現行taskは、行末の物理条件と回答の全量閉包を定義している一方、cue終端の中心概念である「意味の小単位」を名前で呼ぶだけで、良い終端と悪い終端を区別する判断基準を一つも定義していない。system instructionは「判断できない場合」を無条件にabstain可能としている。この二点を合わせると、モデルが「客観基準がないので棄権する」のは現行指示に適合する。

v021の中心候補は次の三点である。

1. cueは「発話の意味が一区切りつき、それだけで意味を読める短いまとまり」と定義する。
2. 語・固有名詞・反復語・一続きの文節の途中を、cue終端にも行末にも選ばない。
3. 基準を満たす選択が一つ以上存在するときは回答し、abstainを入力欠落・入力矛盾に限定する。

ただし本書では候補を確定しない。§5のチェック欄をkawafmmが選んだ後にだけ、v021の正式文面へ進む。

## 4. 判断基準候補

以下は裁定用の候補であり、v021の正式文面ではない。

### C1 意味の一区切り

候補文:

> cueは、直前から続く発話がそれだけで意味を読める短いまとまりになり、その末尾で発話の意味が一区切りつくように分けてください。

- 効果: D3が申告した「客観基準不足」へ直接答える。
- 保持するもの: 一文字ずつにも長文一括にもならないという人間認定済み目標。
- 新しい係数: なし。
- 分類: AIへ必要。機械検査だけでは代替不能。

### C2 語・文節内を切らない

候補文:

> cue終端と行末は、語、固有名詞、反復語、読みとして一続きの文節の途中には置かないでください。

- 効果: 既知5類型から素材固有文字列を外して一般化した原則。
- providerへ送らないもの: 既知5類型の実文字列、既知6境界、期待回答。
- 機械との分業: 既知6境界の再選択は従来どおりローカル検査が最終拒否する。
- 分類: AIへ必要。既知例以外の語中切断を抑える。

### C3 極端な分割を避ける

候補文:

> 一文字だけを独立したcueにしたり、複数の意味の区切りを一つの長いcueへまとめたりしないでください。

- 効果: 「一文字ずつ／長文一括にしない」を明文化する。
- 注意: 発話上、一文字だけで意味が成立する例を一律に拒否し得る。例外を表す契約が現時点ではない。
- 新しい数値: なし。
- 分類: AIへ渡せるが、C1で十分かをkawafmmが選ぶ必要がある。

### C4 必要な改行だけを自然な位置へ置く

候補文:

> cue終端を意味の基準で先に決め、そのcueが一行に収まらない場合だけ、語や一続きの文節の途中を避けて行末を選んでください。必要な行末候補が複数ある場合は、二行の幅が大きく偏らない候補を選んでください。

- 効果: 意味cueと行折りを混同せず、H4・H5のうちAIが判断する部分だけを伝える。
- 省くもの: 「ページ数最少」はcueを不当に長くするためAI基準へ持ち込まない。「決定的境界順」は生成AIの選択基準にせず、ローカルの決定的処理が所有する。
- 分類: 一部は現行taskと機械検査に既在。自然な行末・幅の釣り合いだけが追加候補。

### C5 20ms級末尾文字

候補処理:

> provider taskへは追加しない。時刻を見せない設計を維持し、ローカルの正frame・物理配置・時間写像検査が所有する。

- 理由: provider入力に時刻は存在しない。「20ms」を書いても判定材料がない。
- H1/C3により、一文字単独化を避ける一般的傾向だけを伝えられる。
- 分類: 機械側のみ。

### C6 abstainの限定

候補文:

> 入力に必要なcaption、境界ID、境界片、styleLimitsが欠落または相互矛盾し、本文・順序・全量使用・行幅の条件を同時に満たす選択が一つも作れない場合だけ、statusをabstainedにしてください。条件を満たす選択が一つ以上ある場合はcompleteを返してください。候補が複数あることや判断が難しいことだけを理由にabstainedを返さないでください。

- 効果: 「基準未定義でも棄権すれば正解」という現構造を閉じる。
- schema変更: なし。二状態は維持する。
- 分類: AIへ必要。ローカル検査はabstainedを正しく記録できるが、棄権理由の範囲はtaskでしか限定できない。

## 6. D2「選択できた場合」の診断品質

### 6.1 診断方法

D2の生回答はtop-level `status:"success"`であり、正式schemaの`complete|abstained`に一致しない。そのため、次の二段を混ぜずに検査した。

1. 生回答をそのままproduction受入へ渡す: `CUE_PROVIDER_RESPONSE_INVALID`で拒否。これは正式結果である。
2. 内容品質だけを見る診断として、`/status`一項目だけを`success`から`complete`へ写す。他の変更0件。診断用写像結果を正式selection・描画へ流用しない。

### 6.2 結果

| 診断写像後のresponse schema | 合格 |
| caption集合・境界ID・順序・全atom閉包 | 全て合格 |
| 論理幅 | 合格 |
| 決定的本文再構築 | 合格 |
| 既知6境界の非再選択 | 6/6合格。cue終端・行末の双方で選択0件 |
| 物理配置 | 不合格。3番目のcaptionの2番目のcueで、選択に一致する実描画上の一行候補なし |
| 時間写像 | 物理配置不合格のため未実行 |

### 6.3 観測の意味

- 肯定できること: 3 caption全量を27 cueへ分け、既知6境界を再選択せず、本文・順序・論理幅を守る選択を生成できた。

- 正式流用: 禁止。D2回答・診断写像のどちらもselection・plan・描画へ流さない。
