どちらも自動切断しない。人間は「切る / 残す」を選び、必要な場合だけ発話全文内の文字位置で端点を直す。最後に「この区間列で完成 / 追加編集が必要」を選ぶ。追加編集が必要なら、未解決のまま停止し、空の未解決一覧を偽装しない。

画面は次を満たす。

- 時刻の手入力なし
- 時間計測なし
- 選択と再生を分離
- すべての回答をいつでも取消・修正可能
- HH:MM:SS.mmm表示
- 元候補、発話間1の前後、発話間2の前後、現在の編集結果という4種類を必須再生にする
- 再生中に手動で終点へ移動しても完了扱いにせず、再生ボタンからのやり直しを求める
- 切る/残すまたは文字端点を変えた場合は編集後再生だけを失効させ、現在の編集結果を再確認させる
- 3判断、正順の最終区間列、4種類の必須再生がそろうまで、結果欄を表示せずコピーも許可しない
- 結果はサーバーへ自動保存せず、最後にコピー

## 4. 監査で塞いだ問題

人間へ渡す前の独立監査で次を修正した。

- 一式を別候補へ自己整合的に差し替えても通る問題を、事前固定した資料hashを信頼根にして停止
- 申告されたJSON値だけを検査し、実ファイルbyteを読まない問題を、workspace内の通常ファイルを1回だけ読む正式入口へ変更
- 取得1080p映像と結合後映像の再エンコードを見逃す問題を、全映像packetの時刻・内容・codec情報照合へ変更
- Edgeという名称だけで通る問題を、ブラウザ版、UA内Edge版、固定URL、固定媒体hash、seek、再生進行まで照合
- コピー結果が正式保存契約と異なる仮形式だった問題を修正し、実DOM相当のコピー結果を正式validatorへ通す検査を追加
- STT最終チャンクだけが短い正常形を、途中欠落と誤判定しないよう修正
- 確認ページ生成時だけ信頼根を迂回する問題を、固定成果物一覧から4資料、実行媒体、STT三資料まで実byteでたどる入口へ統一
- 元候補・局所2件・編集結果の必須再生ゲートを追加し、手動seekを完走と数えず、回答変更後は編集結果だけを再視聴させる
- コピー用hash計算中の回答変更で古い結果がclipboardへ渡る競合を拒否
- workspace内を指す場合も含め、途中directoryから末端までsymbolic linkを拒否
- 資料間18本の参照を1本ずつ壊して検出し、元編集案と確認候補の題名も同一候補へ束縛
- 「端点を変更した」という申告と実際に変えた左右端点数を一致させ、位置探索0/1/2回を実値から算出
- 人間へ配るサーバーが任意のHTML・動画を受けられる問題を、固定済み確認画面と固定実行媒体だけを配信する正式入口へ変更
- 正式配信先を`127.0.0.1:4318`へ固定し、外部公開host、別port、別HTML、別動画、別成果物一覧の指定を拒否
- 検査と読込の間にファイルや親directoryを差し替える競合を、symbolic linkをたどらない同一file handle、読込前後の実体照合、配信中のhandle保持で拒否
- 正式保存直前にも実行媒体とSTT三資料の実byteを再照合し、人間視聴後の差替えを合格にしない
- 読み取り専用配信テストの一時directoryを、待受成功・失敗の両方で必ず削除

この補強は人間の判断内容を増やしていない。確認対象の同一性と、結果保存時のすり替え防止だけを強めた。
