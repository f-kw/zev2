# 演出のお手本採集 記録設計 v001

作成日: 2026-07-18

## 目的

実在の切り抜きで、どの出来事に対してどの演出が使われているかを少数の観察から外部化する。現段階では演出の良否を採点せず、実装・自動判定・重み付けも行わない。

採集が5〜10本に達した時点で、人間の経験知から事前登録した14仮説の検証結果と、そこに収まらない新規観測を「その条件を満たすか」というYES/NOの文法チェックリストへ編み、演出評価の設計へ進む。白紙から文法を起こす作業にはしない。層2（意味的間引き）の正解整備は、その副産物がどれだけ貯まったかを見てから再判断する。

人間の現時点の観察では、演出の中心は派手な特殊効果ではなく、発話を美しく楽しく読ませるテロップ設計にある。採集では、発話の区切り、表示タイミング、改行、書体、縁取り、背景板、意味に応じた表示型の切り替えを第一観点にする。ズーム、SE、挿入画像等は気づいた場合に従来どおり記録するが、数を集めるために探し回らない。この優先順位も教師5〜10本で検証する仮説であり、派手な演出が重要でないと先に確定はしない。

## 正本と記入方法

- 正本: `../../outputs/presentation/exemplar-collection-v001/collection.md`
- 人間へ新規動画を提示するときは、提示文に「次はN本目 / 動画ID / 正本は現在M本K観測」を明記する。
- 人間の視聴メモを受領したときは、転記前に同じ3点を復唱し、「この回答を転記すると何本・何観測になるか」を会話上で明示する。動画ID、本数、観測数のいずれかが正本と一致しなければ転記を停止する。
- 1回の視聴を複数動画へ数えない。人間の自由文を複数の記録行へ整理する場合も、動画本数と、元の申告項目数と、正規化後の直接観測行数を分けて残す。
- 全観測に観測者を記録する。人間が直接見つけたものは「人間」、Geminiが検出しただけのものは「AI（モデル名）」、Geminiの指摘を人間が映像で認定したものは「人間（Gemini補助）」とする。
- 文法とstyleの蒸留へ使用できるのは「人間」と「人間（Gemini補助）」だけ。AI補助観測の本数・件数を人間正本の合計へ加えない。
- 新規教師は必ず人間が先に視聴する。候補選定後から人間観測を受領するまで、同じ動画をGeminiへ解析させない。AIの指摘が人間の自由観察を誘導する汚染を防ぐためである。
- Gemini補助観測を行う場合は、人間観測を正本へ固定した後に、既存メモとの差分だけを最大5件で人間へ諮る。
- 1本の切り抜きにつき、気づいた演出の発火点を1行ずつ記す。
- 時刻は切り抜き動画内の `HH:MM:SS`。フレーム単位の入力は求めない。
- 人間はMarkdownを直接編集しなくてもよい。会話へメモを返せば、実行部隊が正本へ転記する。
- 全演出を漏れなく数える作業にはしない。普段どおり観て、目についたものだけを残す。
- 最初に見るのは、テロップが発話をどう区切り、いつ、どんな見た目で提示しているか。特殊効果は目についた場合だけでよい。
- 「演出が一つもない」と判断した場合は、視聴済み欄に印を付け、発火点表へ `なし` と1行だけ記録する。

## 最小記録形式

| 項目 | 書く内容 |
|---|---|
| 発火時刻 | 演出が始まったおおよその切り抜き内時刻 |
| 種類 | ズーム / SE / テロップ強調 / 挿入画像 / 画面効果 / カット切替 / BGM / その他 |
| 発火の文脈 | 何が起きた瞬間に使われたか。例: 言い間違いに本人が気づいた瞬間 |
| 強度 | 弱 / 中 / 強。数値化・合成スコア化はしない |
| メモ | 重なった演出や、気になった点がある場合だけ |

強度の目安は次の三つだけとする。

- 弱: 内容を邪魔せず補助している。
- 中: 演出が明確に知覚できる。
- 強: 一時的に視線や注意の中心になる。

これは作品間の優劣ではなく、同じ演出を再現するときの大きさを区別するための記述である。

## 検証待ち仮説（実例観察とは分離）

2026-07-18に、人間（kawafmm）の経験知として次の14項目が提示された。これは教師切り抜きから採集した事実ではなく、今後の実例で確かめる設計仮説として別管理する。正式な状態・観測の紐づけは採集正本の`H01`〜`H14`を正とする。「基本文法 / 意味別の型 / 強調 / 画面構成」の4層整理は**仮説の一次分類（蒸留の下書き）**であり、確定文法ではない。

1. 発話をテロップとして表示する。
2. 一度に見せる単位は、意味を読める範囲で短くする。一文字ずつにはせず、長い一文をそのまま出さない。
3. 文字サイズは動画内で一定にする。長い発話だけ自動で小さくしない。
4. その一定サイズを可能な限り大きくし、使える横幅を十分に使う。
5. 横幅へ収まらない場合は文字を縮めず、意味の切れ目で適切に改行する。
6. 対応する発話に合わせ、読めるタイミングで小気味よく表示を切り替える。
7. 読みやすく美しいフォントを用い、枠線・縁取りで背景から文字を分離する。
8. 配信者がリスナーのコメントを読み上げる場面では、通常の発話テロップと区別する。コメント本文を背景板（座布団）に載せ、未設定状態のプロフィールアイコンを添え、コメント欄の一項目に見える形で、読み上げに合うタイミングに表示する。
9. 弱々しい発話には、弱々しさが伝わるフォント表現を対応させる。基本の文字サイズ一定という契約は維持し、弱さを字体・太さ・輪郭・色などの何で表現するかは教師実例を見てから決める。
10. しっかり内容のあるトークでは、背景板（座布団）をトークの継続中は常時表示し、その上のテキストだけを発話に合わせて切り替えていく方式を、通常テロップのバリエーションとして持つ。リスナーコメント用のアイコン付き表示とは別の型にする。
11. 配信者が重要なことを言う瞬間、自分の間違いに気づいた瞬間、または何かを発見した瞬間には、配信者の顔（アバターを含む）へ寄ってアップにする。
12. ショート動画では、縦画面を横長の上・中央・下の3領域が積み重なった構成として使うバリエーションを持つ。中央へ本編映像を置き、上と下は補足情報やサムネイルの表示領域として使う。
13. 3領域レイアウトの一型として、上段へ動画のタイトル、中央へ本編映像、下段へ発話テロップを表示する構成を持つ。
14. タイトルを見せる時、または重要な出来事が起きた瞬間には、通常の画面領域や映像表示を一時的に上書きし、画面全体を使って可能な限り大きい文字のテロップを表示する型を持つ。

数値の文字サイズ、表示時間、1行文字数、縁取り幅、背景板とアイコンの寸法、顔アップの倍率と継続時間、ショート画面3領域の比率、上段タイトルと下段テロップの占有範囲、全画面強調の文字数と継続時間はまだ置かない。教師実例から観測できる範囲を確認した後、独自係数を使わず判定可能なYES/NOへ落とす。「美しい」「小気味よい」「弱々しい」「しっかり内容のあるトーク」「重要なこと」は現時点では人間の品質語であり、そのまま機械基準にしない。コメント読み上げ、弱々しい発話、内容のあるトーク、気づきの瞬間、上下へ表示する情報の選択、全画面強調の発火をどの情報から判定できるかも未確認であり、演出の見た目と検出方法を混ぜて実装しない。

教師視聴メモを受領したら、動画別の発火点を先に保存し、該当する仮説へ動画IDと時刻付きの裏付け観測または反例観測を紐づける。裏付けが得られた仮説は「裏付け済み」へ昇格し、反例が得られた仮説は元の文を消さず「修正待ち」として履歴を残す。14項目に当てはまらない観測も捨てず、蒸留時の新規候補にする。

## 蒸留時の宿題（今は解かない）

次の未整理点は、5〜10本の観察が揃った時点で仮説の検証結果と一緒に解く。現段階で条件・順位・既定値を独自に置かない。

- 判定条件: 「重要なこと」「弱々しい発話」「内容のあるトーク」「コメント読み上げ」などを、何を見て判定するか。
- 優先順位: 複数の発火条件が同時に成立した場合、どの表現を優先または併用するか。
- フォールバック契約: 判定不能または確信度が低い場合に、どの基本表示へ戻すか。
- 統一規則: 1本の動画内で書体・背景板・強調型が無秩序に増えないよう、何を固定するか。

## 層2の副産物

話が飛んでいる、不要部分が抜かれている、離れた場面が接続されていると気づいた場合だけ、別表へ次を記す。

| 項目 | 書く内容 |
|---|---|
| つながり目の時刻 | 切り抜き内のおおよその位置 |
| 飛ぶ前 | 直前に何を話していたか |
| 飛んだ後 | 直後に何へ移ったか |
| 気づいた根拠 | 音、映像、話の飛び、テロップなど。分からなければ空欄でよい |

この欄は任意であり、演出メモを残す条件にはしない。採集段階では、意味的間引きか単なる無音詰めかを人間へ判定させない。

## 次の門

視聴済みメモが5〜10本に達したら、実行部隊が次を行う。

1. `H01`〜`H14`ごとに、裏付け、反例、未観測を動画ID・時刻付きで集計する。
2. 14項目に収まらなかった新規観測を、個別動画名を条件へ埋め込まず抽象化する。
3. 仮説の検証結果、新規観測、蒸留時の宿題を、判定可能なYES/NOの文法チェックリスト案へ編む。
4. 観測数、反例、例外、まだ判断できない型を分けて報告する。
5. 実装やモデル実走を始めず、演出評価設計の承認を人間へ求める。
6. 任意の内部間引きメモの蓄積量を報告し、層2正解整備を再開するか人間判断へ戻す。
