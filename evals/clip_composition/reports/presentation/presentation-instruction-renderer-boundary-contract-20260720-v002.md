# ZEV演出指示書―レンダラー境界契約 v002

日付: 2026-07-20

状態: **話者欄契約改訂に伴うv002同期を2026-07-20に実装。指示書・解決パッケージ・検査器はv002、正式プリセット台帳と空素材台帳は承認済みv001を参照する。レンダラー実装・実走は未承認。**

## 1. 目的

ZEVの演出責任を「意味を決め、閉じた語彙の演出指示書として渡すところまで」に固定する。文字の形、配置、動き、合成等の視覚的実現は、契約で分離した自作レンダリングサブシステムが担う。

この分離により、ZEVの意味判断を保ったまま、将来レンダラーを自作実装、既製テンプレート、外部ツールのいずれかへ交換できるようにする。教師完成版と見た目品質を競うことは、ZEV演出の評価目標にしない。

本v002の対象形式は、今回文法を人間認定した**通常の横長動画**だけとする。縦型ショートへ同じ語彙・プリセットを暗黙に流用せず、ショート文法の認定後に共通部分と形式固有部分を固定して契約を版付き改訂する。

## 2. 責務境界

### ZEV側

- いつ演出を始めるか。
- 何の種類の演出か。
- どの発話、場面、話者、情報、参照先を対象にするか。
- どの登録済みプリセットを使うか。
- どの登録済み素材を使うか。
- 確信が低い、または必要素材が無い場合に、演出指示を出さない判断。

### レンダラー側

- 契約に適合した指示を、指定されたプリセットと素材で描画する。
- 指示を欠落させず、別の意味へ読み替えない。
- テロップや素材の重なり、画面外、欠落、音声欠落を受入検査で防ぐ。
- 実行した契約版、解決パッケージID/hash、レンダラー版、プリセット台帳版、素材台帳版を成果物へ記録する。

ZEVは座標、フォントサイズ、色、アニメーション曲線等の描画値を指示書へ直接書かない。レンダラーは発火点、種類、対象、プリセットID、素材参照を独自に変更・代替しない。

## 3. 演出指示書の最小項目

演出指示1件は、次の5項目を必須とする。

1. **発火点**: 元入力中の既存IDへ結び付いた開始点だけを表す。生のミリ秒をモデルに創作させない。
2. **種類**: 本契約で許可した演出種類。
3. **対象**: 発話、場面、話者、情報項目、参照先のいずれを扱うかと、その版付き既存ID。表示本文、改行等はこの参照先から解決でき、レンダラーに推測させない。`speech-caption`だけはG3の表示終了anchorも対象参照から解決する。対象参照には描画開始を重複して持たせず、描画開始の正本は発火点だけとする。対象となる発話・場面自体は発火点より前から始まっていてよい。
4. **プリセットID**: 版付きプリセット台帳に実在するID。
5. **素材参照**: 版付き素材台帳に実在するID。素材不要なら空配列。

追跡のため、指示書全体には契約版、指示書ID、対象形式、元入力の由来、解決パッケージIDとcanonical SHA-256、プリセット台帳版、素材台帳版を持たせる。各指示には一意な指示IDを持たせる。これらは意味項目を増やすためではなく、同じ指示を同じ入力へ再現するための外枠である。

初期アートを固定1種で始める場合も、プリセットIDは必須のまま定数として記録する。単一プリセットであることを理由に欄を削除したり、レンダラー内部の暗黙defaultへ置き換えたりしない。

### 3.1 解決パッケージ

発火atomと対象参照を本文・時刻・話者・表示anchorへ解決する`presentation-resolution-package-v002`を、指示書と同時にレンダラーへ渡す。指示書がpackage IDとcanonical hashで実体を固定し、レンダラーは別ID、別hash、別由来のpackageを使わない。package ID/hashの不一致は明示失敗とし、参照値を元入力や別台帳から推測補完しない。

未参照対象・未参照cueを拒否するため、この解決パッケージは**1つの指示書と対で生成する専用品**であり、複数指示書で使い回す汎用ライブラリではない。再利用したいという実装都合で未参照拒否を無断緩和せず、必要性を固定して契約版を改訂する。

### 3.2 元発話の話者欄

- source atomの話者欄は、欄なし、`null`、または同一source内だけで比較する空でない正規文字列とする。
- 固定台帳`presentation-source-speaker-non-identity-registry-v001`の`unknown`と`youtube-auto-caption`は、正式package生成器だけが完全一致で`null`へ写す。
- packageは使用したnormalizer版、台帳版、台帳canonical hash、写像前atom列hashを必須記録する。レンダラーと検査器はspeakerをtrim・文字列化・補完・再写像しない。
- 台帳外文字列は人物を保証しない不透明ラベルである。人物ID・表示名・アイコン対応は明示speaker targetを正本とし、source labelから暗黙生成しない。
- `information-item.speakerId`は同じpackage内の明示speaker targetを参照する外部キーであり、対応targetが無ければ不適合とする。

## 4. v002の閉語彙

網羅を狙わず、人間認定済みG1〜G7から直接導ける種類だけを受け付ける。

| 種類 | 根拠 | ZEVが決めること |
|---|---|---|
| `speech-caption` | G1〜G3 | 表示対象の発話、意味単位、発話進行上の発火点 |
| `emphasis-important-statement` | G4 | 重要発話の発火点と対象 |
| `emphasis-mistake-realization` | G4 | 間違いへの気づきの発火点と対象 |
| `emphasis-discovery` | G4 | 発見の発火点と対象 |
| `emphasis-strong-emotion` | G4 | 強い感情の発火点と対象 |
| `information-comment` | G5 | リスナーコメントとして扱う情報と対象発話 |
| `information-narration` | G5 | ナレーションとして扱う情報と対象発話 |
| `information-lyrics` | G5 | 歌詞として扱う情報と対象発話 |
| `speaker-identification` | G6 | 複数人場面の対象発話と話者 |
| `reference-supplement` | G7 | 補足が必要な参照先と、確信を持って対応できる既存素材 |

G2とG3は独立した見た目の種類ではなく、`speech-caption`の意味単位と発火点に対する検品規則として扱う。

対象種別は`caption-target`、`source-atom-range`、`speaker`、`information-item`、`reference-subject`に限る。`caption-target`は既存G1〜G3論理契約の表示本文、改行、表示終了anchorまで解決できる版付き参照であり、単なる発話IDではない。表示開始は発火点だけが持つ。素材役割は初版では`speaker-icon`、`reference-image`、`reference-video`に限る。BGM、SE、アイキャッチ、背景効果、構成層、独自画面再構成は初版へ入れない。

X投稿欄型表示は、G5の情報種別かG7の参照補足か、専用表示の新しい種類かが未確定である。人間A/Bで価値は観測したが、v002へ無断追加せず「契約語彙不足・層判定待ち」として保全する。

## 5. 種類別の表示終了責任

表示開始は全種類で発火点が正本。表示終了は次のどちらか一方だけが正本となり、レンダラーが独自に上書きしない。

| 種類 | 表示終了の正本 | レンダラーの扱い |
|---|---|---|
| `speech-caption` | 対象参照に含まれるG3の表示終了anchor | 対象参照どおりに終了する。プリセットによる延長・短縮は禁止。 |
| `emphasis-important-statement` / `emphasis-mistake-realization` / `emphasis-discovery` / `emphasis-strong-emotion` | 指定プリセットの版付き終了方針 | 発火点と対象を変えず、台帳に宣言された決定的な終了方針を適用する。 |
| `information-comment` / `information-narration` / `information-lyrics` | 指定プリセットの版付き終了方針 | 同上。 |
| `speaker-identification` | 指定プリセットの版付き終了方針 | 同上。 |
| `reference-supplement` | 指定プリセットの版付き終了方針 | 同上。 |

`speech-caption`の表示終了をプリセット側へ移す、または他種類の表示終了を対象参照側へ移す変更は境界越えであり、契約版の改訂を必須とする。

## 7. 適合条件

ZEV側の指示書は、次を満たさなければレンダラーへ渡さない。

- 契約版が完全一致する。
- 発火点と対象の全IDが元入力に実在する。
- 指示書が指定した解決パッケージID・canonical hash・元入力由来が実体と完全一致する。
- 種類と対象種別の組み合わせが閉語彙に適合する。
- プリセットIDが指定された台帳版に実在する。
- 素材参照が指定された台帳版に実在し、用途が種類と整合する。
- `speech-caption`の対象参照にG3の表示終了anchorが実在する。
- `speech-caption`以外では、指定プリセットがその種類の表示終了方針を持つ。
- G7は対応確信のある既存素材だけを参照する。
- 未知の種類、対象、プリセット、素材をフォールバックで推測変換しない。

現行G1〜G3検査器は`caption`部分の指示書検品として維持する。既存24/24合格はこの論理caption契約の合成テストであり、新しい5項目指示書の外枠を検査済みという意味ではない。旧形式を推測変換しない既存方針も維持し、後方互換分岐を追加しない。

## 8. 境界をまたぐ変更

次の変更は契約版の改訂を必須とする。

- 演出種類、対象種別、発火点表現、素材役割の追加・削除・意味変更。
- プリセットIDが意味する責務を、ZEV側とレンダラー側の間で移す変更。
- レンダラーが指示の発火点、種類、対象、プリセットID、素材参照を自動補正・置換する変更。
- 解決パッケージの意味、指示書との対生成、ID/hash照合、搬送責任を変更すること。
- 描画側の結果からZEV側の意味判断を暗黙に書き換える変更。

レンダラー内部の不具合修正や高速化で、同じ契約入力の意味を変えないものはレンダラー版だけを更新する。契約語彙を増やす場合は、厳密一致契約と同じく、別工程で必要な対象を固定し、人間が認定した後に版付きで改訂する。片側の実装都合で境界を無断変更しない。

## 9. 評価の帰属

品質観測は必ず次のいずれかへ分ける。

| 帰属 | 例 | 主な確認方法 |
|---|---|---|
| 指示書が悪い | 発火点、種類、対象、プリセット選択、素材参照が不適切 | G1〜G7検品、運用ログ、人間の採否・修正 |
| 描画が悪い | 重なり、画面外、欠落、指定プリセットと異なる描画、音声欠落 | レンダラー受入検査 |
| 契約語彙が足りない | 必要な専用表示を現行種類・対象・プリセットで表現できない | 未対応要求の由来付き記録、人間による語彙改訂判断 |

教師完成版との総合A/Bは、指示書、描画、語彙不足、内部編集、構成、音声処理の差を一度に含み、どこへ直すべきか帰属できないため中止する。公開物の実測では、`ZEV指示書の契約版・生成系統 + 解決パッケージID/hash + レンダラー版 + プリセット台帳版 + 素材台帳版`を一組として記録する。生成manifestには解決パッケージID/hash、指示ごとの要求プリセットID・台帳版、描画ルーティングが実際に解決したプリセットID・台帳版を残し、不一致・欠落をレンダラー受入失敗とする。
