# 通常動画版 G4〜G7 次期正解セット v002 可用性ゲート先行収集設計 v001

状態: **人間承認済み。G4第1段は強調あり4件・G4該当なし1件で完了。強調あり4件の発火点・元配信対応点を認定する第2段の人間確認待ち。正解凍結、検出器実装、LLM実走は未開始。**

## 1. 目的

v001では教師側の演出観測を先に凍結し、後から元配信入力を整備したため、意味検出を採点できる例が0件になった。v002では工程を逆転し、**本番と同じ候補入力、教師との対応、必要な構造化情報が利用可能だと確認できた場面だけを、その後に正解候補として人間へ提示する**。

既存GT-01〜05は変更・再探索しない。GT-04のG5配管1件は削除せず、v002で同じ配管契約を検査するときの既存例として畳む。

## 2. この評価が測るものと測れないもの

v002が測るのは、**現行上流候補が覆った場面の内側で、G4〜G7の演出判断を再現できるか**という条件付き成績である。候補入力の内側にある正解だけを作るため、配信全体に対する演出好機の再現率ではない。

構造的な盲点:

- 候補外にある強調好機は測れない。
- 候補外にある「強い場面だが演出を足さない」抑制好機も測れない。
- GT-01型の上流カバレッジ欠落は、v002の意味検出成績へ現れない。
- GT-02型の候補外抑制好機は、正確な元配信対応が得られてもv002の内側評価には入らない。

覆いの外は、テーマ生成・候補選択・接続を対象とする**上流カバレッジ評価**として分離する。意味検出の分母、G5/G6配管、上流カバレッジを合算した点数は作らない。

## 3. 収集前に固定する採点入力可用性ゲート

人間が演出正解を観察する前に、候補単位で次をmanifestへ固定する。1件でも欠けた候補は人間へ正解候補として出さない。

1. 本番と同じ元配信由来の候補入力が保存され、候補範囲と入力内容を再現できる。
2. 上流系統、モデル名、プロンプト版、run、候補IDが記録され、正解を見た再生成・best run選択をしない。
3. 教師切り抜きと元配信の対応が、候補提示前に実映像で人間確認済みである。DP単語照合だけの提案は通過扱いにしない。
4. 教師側の該当素材が、元配信候補のどの部分に対応するかを固定できる。内部詰め・順序入れ替え・複数素材は構造として保存する。
5. G5は情報種別、G6は人物別話者、G7は利用可能な既存素材と参照対象の対応を、正解候補提示前に入力として利用できる。
6. G4・G7の発火点、G5・G6の区間を、候補入力に存在するIDまたは媒体時刻で表現できる。
7. ゲート通過後に候補範囲、構造化情報、利用可能素材を広げない。欠損が判明したら`input_not_ready`として停止する。

ゲートの通過は演出正解の成立を意味しない。採点可能な入力が先に揃った、という準備状態だけを示す。

## 4. ラベル対象場面の選定規則

どの候補のどの範囲を人間へ見せるかは、G4/G7検出器や補助探索モデルの出力を見ずに次の順で固定する。

1. 評価対象の元配信と、実運用で人間へ渡される**正規の最終候補入力**を、演出ラベル作成前にsnapshotする。複数runから結果を見て選ばず、実運用で採用されたcanonical候補だけを対象にする。canonical候補が未定義なら収集を開始しない。
2. 可用性ゲートを通過したcanonical候補を、`sourceVideoId`、開始時刻、候補IDの順に並べる。
3. 並び順の候補を省略せず順番に人間へ提示する。title、reason、チャット流速、ランキング順位、既存GTとの近さ、G4/G7検出結果では並べ替えない。
4. 人間資源の原則に従い、1セッションは5候補前後で区切る。次セッションも同じ固定順の続きから始め、前セッションのラベル結果で飛ばしたり差し替えたりしない。
5. 人間へ見せる範囲は、検出器へ渡すcanonical候補入力そのものと、可用性ゲートで事前確認した対応教師素材だけとする。正解らしさを見て前後文脈を足さない。

上流候補そのものは条件付き評価の対象入力なので利用する。ただし、その内側から人間へ見せる場面を選ぶために、新しい意味探索モデルやランキングを使わない。これにより「検出器が見つけやすい場面だけを正解化する」循環を防ぐ。

## 5. 人間ラベル工程

### 5.1 第1段: 候補単位の観察

各canonical候補について、教師側の実際の演出と元配信側の場面を対で見せる。人間は次を選ぶ。

- G4: 強調候補がある / 強い場面だが追加演出を抑制している / 該当なし / 判断不能。
- G5: コメント、ナレーション、本人発話等、区別して運ぶ情報種別がある / 該当なし / 判断不能。
- G6: 複数人場面で人物別話者の表示が必要 / 該当なし / 判断不能。
- G7: 参照対象へ対応する利用可能な既存素材がある / 該当なし / 判断不能。

人間メモにないものを負例にしない既存の非対称原則を維持する。`該当なし`は提示した候補を人間が明示確認した場合だけ記録する。

### 5.2 第2段: 正解位置と構造の認定

第1段で該当ありになった候補だけを、別の少数セッションで精査する。モデルが発火点を提案してから人間が追認する方式にはしない。

- G4/G7の発火点は、人間が媒体を一時停止して「この瞬間」を指定し、時刻を手入力させず再生確認して確定する。
- G5/G6は、入力に存在する発話・情報区間を選択し、情報種別または人物を人間が認定する。
- G7は、既存素材IDと参照対象の対応が既に可用性ゲートを通っている場合だけ正解化する。確信がなければ付けない。

1セッション5件前後の上限を両段に適用する。対応候補生成v001の2/4件誤対応を踏まえ、教師と元配信の映像対応確認を他の問いへ埋め込まず、可用性ゲートの独立した人間認定として完了させておく。

## 6. 採点と報告

v002は次を別表で報告する。

- G4/G7: 入力内・人間認定済み正解に対する意味検出の煙試験。
- G5/G6: 人間認定済み構造化情報を失わず論理計画へ運ぶ決定的配管検査。
- 上流カバレッジ: 教師側で人間認定した演出好機が、候補入力へ入っていたか。v002の意味検出分母とは別。
- 入力準備: ゲート通過、対応不成立、構造化情報不足、素材不足の件数。

Nが小さい間は接続確認と重大欠陥の検出に限定し、一般精度、版比較、標準採用を主張しない。候補内だけの結果へ「配信全体の再現率」という名前を付けない。

GT-01は上流カバレッジ診断の既存1件として残す。対応成立かつ広いテーマ根拠範囲でも入力外だったため、将来の上流改版時に同じ固定条件で再確認できる。N=1なので単独で上流改版の採否を決めない。

## 7. GT-03の文書判定

GT-03の人間観測は「時間、場所、登場人物、状況を約2秒の静止画へ詰め込んだ文脈カード」である。現行G7は、発話だけでは参照先が分かりにくい人物・元ネタ・過去場面に対し、利用可能素材台帳に実在し対応を説明できる素材を選ぶ仕事である。新しい情報カードへ複数情報を組み直す仕事は含まない。

したがってGT-03は、現行G7ではなく**再構成層・文脈カード構成**に該当すると人間承認済みである。状態を`held_input_not_ready`から`not_applicable_current_G7`へ移すが、人間観測とGT由来は削除しない。再構成層の再開条件が将来定義されたときの正解候補として保全する。元配信候補5本の特定、取得、STT、素材台帳整備は現行G7のためには行わない。

## 8. v002の凍結条件

次のすべてが揃うまで正解セットv002と呼ばない。

- 候補snapshotとcanonical選択規則。
- 候補ごとの可用性ゲート結果。
- 教師と元配信の人間確認済み対応。
- G5/G6の構造化情報、G7の既存素材対応。
- 固定順で提示した人間観察結果。
- 第2段の発火点・区間・構造の人間認定。
- 生成系統、観測者、認定日、採点可能/不能理由。

凍結後に欠損が見つかった場合、正解へ入力を合わせず、当該件を採点不能へ分離する。
