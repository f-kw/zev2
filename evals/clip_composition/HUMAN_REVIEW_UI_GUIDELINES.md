# 人間確認UIの設計規則

更新日: 2026-07-15

## 目的

試験UIは、人間が判断材料を理解し、少ない操作で答え、その答えを間違えたら直せるようにするためのもの。評価処理の都合、将来の汎用化、記録機能の充実を人間へ押し付けない。

一回限りの確認画面でも、失敗と有効だった導線は次の画面へ引き継ぐ。生成スクリプト、実際のHTML、事前検査、無効化した旧結果を削除せず、再発防止の根拠として残す。

## 実装前に固定すること

1. 人間が答える問いを平易な一文で書く。
   - 「そのまま公開できるか」「現在の区間内を編集すれば使えるか」「別場面の文脈映像が見つかれば使える可能性があるか」を分ける。
   - 区間内編集を聞く場合は、連続境界調整、区間内カット、無音除去のどこまでを許すか先に固定する。別場面の文脈追加を区間内編集へ混ぜない。
2. 人間に見せる情報と、見せない情報を分ける。
3. 1件の操作を「見る→選ぶ→必要な補足を選ぶ→次へ」に限定する。
4. 計測、永続保存、履歴、汎用化など、問いへの回答に不要な機能は人間の明示指示なしに追加しない。
5. 人間作業量を事前申告する。
6. 候補カード数ではなく、独立に答える問いを判定数として数える。総判定数、1セッションの判定数、予定セッション数、分割順を実装前に固定する。
7. 1回の監査セッションは5判定前後を上限とし、正解データ認定・関門判定はさらに必要最小限へ絞る。総数が上限を超える場合は、日を分けるか優先順で上位だけを提示する。

## 表示

- ID、JSON、ミリ秒、内部の変数名を主表示にしない。
- 人間向けの時刻は固定幅の`HH:MM:SS`で表示する。内部のmsは保存と機械照合に限定する。
- STTを使う場合、1文字だけ、単語だけ、前後1語だけを孤立表示しない。意味を読める発話全文の中へ選択位置を埋め込む。
- 元の意味情報が増えていない表示変更を「文脈追加」と呼ばない。
- 動画、音声、題名、理由のうち、その問いに必要なものだけを同じ画面に置く。
- 主要な選択肢と次・前の操作は画面下へ固定し、動画や長い発話を見た後に探させない。

## 境界選択

- 人間へ時刻を入力させない。
- 開始は「始めたい言葉の最初」、終了は「最後に残す言葉の最後」と説明する。
- 内部で細かな時刻点を持つ場合も、発話全文を連続表示し、その全文内の文字時刻位置を選べるようにする。1文字だけの候補一覧は作らない。発話全体しか選べない方式も、長い発話では境界を決められないため使わない。
- 人間が単語途中を選ばない前提を使い、日本語の単語境界を機械が勝手に推測して選択肢を欠落させない。
- 選んだ開始・終了を文章中の区切りで表示し、選択範囲をすぐ再生できるようにする。
- 採用・不採用・保留の回答を、境界編集の解放条件にしない。判断前も判断後も同じ操作ができるようにする。
- AIの候補範囲を選択可能範囲の終端にしない。前後の元配信発話を最初から見せ、必要に応じて元配信の端まで追加できるようにする。
- AIの候補範囲と人間が選んだ範囲は別の表示にし、どちらを再生する操作かをボタン名と長さで明示する。
- 発話クリックで暗黙に再生を始めない。境界変更と再生は別操作にし、再生範囲と停止位置を事前に分かるようにする。

## 文脈と編集可能性

- 候補の直前・直後に必要情報がある場合、尺を連続して足すことでも文脈を補填できる可能性はある。ただし追加尺は視聴者の見るコストを増やし、見どころへ到達する前の離脱や候補自体が評価されないリスクを高める。単純延長を既定解にしない。
- 連続延長を使う場合は、「追加部分が判断に必要な新情報を持つか」と「その情報のために増える視聴尺」を別々に確認する。秒数の独自閾値や重み付けは置かない。
- とくにゲーム場面では、時間的に離れた宣言・フリ・過去の失敗などを短く接続しないと、反応の意味が伝わらない場合がある。隣接尺の追加と、離れた場面を短く接続する方法は別の構成として扱う。
- 一つの開始点と終了点だけでは、区間内カットや無音除去を表現できない。これらで救える可能性を「選ばない」へ潰さず、現在区間の編集種別として別に回答させる。
- 別場面の文脈を足せば使える可能性は、現在区間の編集とは別状態にする。必要な文脈映像が元配信内に実在するかは未確認なので、「文脈候補の探索が必要・存在不明」として保存し、公開可能件数やcallback成功数へ加算しない。
- 次の確認を段階化する場合、「そのまま使える / 現在区間の編集で使える / 隣接尺を足して文脈を補えば使える / 別場面の文脈が見つかれば使える可能性がある / 使えない / 判断材料不足」を分ける。選択肢は実施前に人間承認を得る。

## 回答と受け渡し

- 回答後も前の候補へ戻り、採否と補足選択を変更できるようにする。
- 確定で戻れなくなる遷移を作らない。
- サーバー保存を既定にしない。ブラウザ内の仮状態から、最後に人間が読める結果をコピーする方式を優先する。
- コピーがブラウザ権限で拒否された場合は、結果欄を自動選択し、通常のコピー操作で回収できる状態にする。
- UI操作中の状態は正式回答ではない。人間がチャットへ貼ったコピー結果を正式回答候補とする。
- 「次の候補」を押した直後は、次候補のAI案を再生する。これは候補移動の明示操作に伴う再生であり、発話位置を選んだだけで再生する挙動とは分ける。
- 1セッション分の判定が終わったら、そのセッションの人間可読な結果をコピーして終了する。次のバッチへ自動遷移せず、機械側の結果確認後に別セッションとして提示する。
- 1候補へ複数の独立した問いを置く場合は、それぞれを判定数へ数える。開始・終了の選択など編集操作は、判定数とは別の操作量として事前申告する。

## 実画面で必ず確認すること

1. 初期画面だけで問いが分かる。
2. 選択肢が画面下にあり、候補ごとの操作が少ない。
3. 境界の意味が発話全文から分かる。
4. 開始と終了を選び直せる。
5. 次へ進んだ後も戻って直せる。
6. 旧回答や正解情報が混入していない。
7. そのセッション全件後の結果が人間可読で、コピーまたは選択して回収できる。
8. 時間計測やサーバー保存など、指示されていない機能がない。
9. 未回答と「選ばない」の状態でも、境界を選び直せる。
10. AI候補の前後を増やせ、現在表示中の範囲外へ必要なだけ進める。
11. 再生ボタンだけを見て、AI範囲か人間範囲か、どれだけ再生するかが分かる。
12. 発話を選んだだけでは再生されない。
13. 閲覧前に、「そのまま公開」「現在区間の編集」「隣接尺による文脈補填」「存在未確認の別場面文脈」のどれを判断するかが明記されている。
14. 人間向け時刻が`HH:MM:SS`で表示されている。
15. 長い発話でも全文内の文字時刻位置を選べる。
16. 次候補へ移動した直後に、次候補のAI案が再生される。
17. 内部編集や離れた前振りが必要な候補を、単純な不採用へ潰さない回答経路がある。
18. 隣接尺を追加する場合、増えた必要情報と増えた視聴コストを分けて確認できる。
19. 1セッションの独立判定が5件前後を超えていない。重要な認定では、さらに必要最小限へ絞られている。
20. セッションの終了点が明示され、次のバッチへ自動で進まない。
21. 総判定数、1セッションの判定数、予定セッション数、分割順が事前申告と一致する。

## 2026-07-14 手直し確認v002の教訓

不合格だった旧画面は、概算時刻の入力、1文字STT候補、細かな時刻調整、自動保存、完了後に戻れない遷移を同時に置いた。人間が正しく操作できず、10件の回答を無効化した。

置換後は、三択を画面下に固定し、発話全文の中で開始・終了を選び、いつでも変更し、最後に結果をコピーする構成へ絞った。旧結果は `progress-invalid-unusable-ui.json` として残し、採点には使わない。

## 2026-07-15 置換後画面の追加不合格

置換後の画面にも、公開判断をしないと境界を選べない隠れた解放条件、候補範囲の外へ十分に進めない文脈制限、発話クリック時の暗黙再生、区別しにくい再生ボタンが残った。発話表示へ変えただけでは、人間が境界を判断できる導線にはなっていなかった。

以後は実装前に「判断と編集の独立」「候補外へ伸ばせる文脈」「選択と再生の分離」「再生元と長さの明示」をUX契約として固定する。実画面検証では公開する場合だけでなく、未回答・選ばない・文脈不明の状態も通す。

## 2026-07-15 UI v003正式確認の教訓

固定上位5候補×2素材の正式回答は、公開する3、選ばない4、文脈不明3だった。公開3件の連続区間境界は保存でき、基本操作について人間から「他は悪くなかった」と評価された。一方、時間は測っておらず、15分条項は未判定である。

最大の問題は機能ではなく、閲覧観点が曖昧だったこと。「そのまま一つの連続区間として公開する」「現在区間のカット・無音除去で使える」「隣接尺を足して文脈を補う」「別場面の文脈映像が見つかれば使える可能性がある」を分離していなかったため、3/10を候補価値やランキングの合否へ直接使えない。連続延長は文脈を補える場合もあるが、視聴コストを増やして評価されにくくする危険を伴う。必要な別場面が実在するかも未確認である。

次回は、問いと許容する編集を画面より先に固定する。時刻は`HH:MM:SS`、境界は発話全文内の文字時刻位置、次候補への移動後はAI案を再生する。発話位置選択時の暗黙再生禁止は維持する。
