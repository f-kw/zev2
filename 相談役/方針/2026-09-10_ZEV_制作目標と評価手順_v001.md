## 2. 目標と成果の単位

製品の方向は「見たものが気持ちいい動画を作る」。ZEVをショート専用に限定せず、要求 → Planner → Skills → 編集仕様 → ZEV Core → 動画という構造を維持する。

**当面の開発目標：制作要求に沿って素材を選び、構成し、実際に使える動画の初稿を自動で出す。**

人の確認時間を短くすることだけを目的にせず、使える出力と、それを得るために残った人の仕事を一緒に測る。現段階の人手の小さな制作方針は許容するが、採用ID・正解区間・カット時刻を人が先に埋めて自動選定の成功としない。将来の完全な人間編集者代替を、この評価の成立条件にしない。

成果の単位は「固定した制作要求に対する動画1本」。本編内の10区間、複数の候補、同じ要求での再生成版は、それぞれ独立した制作成功件数に増やさない。1区間の確認は、その区間についての補助評価である。

今後の本番評価では、出力を見る前に次を既存の制作要求から記録する。

| 項目 | 固定する内容 |
| --- | --- |
| 対象と意図 | 使用素材、何を見せたいか、視聴者にどのような理解・体験を届けたいか |
| 成果物 | ダイジェスト等の用途、目標尺または尺の扱い、必要な形式・文脈 |
| 条件 | 使用する制作方針・実装版、要求上の制約、比較対象がある場合はその条件 |
| 判定対象 | 制作要求の識別子と版、初稿の識別子、判定者、判定する範囲 |

公開先や尺などが要求にない場合は「未指定／未確認」と記録する。出力の長さから目標尺を逆算しない。採否がその不足条件に依存する場合は、当該点を判断不能とする。今回の手順確認のために024の元要求を後付けで変更しない。

## 3. 採否の定義

「採用」は、指定された制作要求の成果物として使うことへの人間の明示的な同意を指す。好意的な感想、リンクを開いたこと、再生したこと、機械検査合格、修正すれば良くなりそうという見込みとは区別する。実公開は必要条件にしない。

### 3.1 初稿への回答

| 初稿への判断 | 定義 |
| --- | --- |
| そのまま採用 | 指定された対象を、追加編集なしで使うことに同意した |
| 修正が必要 | 採用には変更が必要。修正候補または不足がある。採用成立はまだ記録しない |
| 不採用 | この制作要求には使わないと明示された |
| 判断不能 | 見えていない、条件が足りない、好みを決められない等の理由で判断できない |
| 未評価 | 回答自体をまだ受けていない。判断不能と混ぜない |

自然な言葉で答えてよい。主作業は回答原文を残し、どの判断に対応するかを記録する。曖昧な返答を採用へ補完しない。事実照合の返答しかない場合、採否は未評価のままにする。

### 3.2 制作要求ごとの現在の結果

| 結果 | 成立に必要な記録 |
| --- | --- |
| 初稿をそのまま採用 | 初稿の識別と、その初稿を使う明示的な同意 |
| 修正後に採用 | 実際の変更内容、修正版の識別、修正後の採用への明示的な同意 |
| 不採用 | 使わないという明示的な回答と対象版 |
| 判断不能 | 判断不能という回答と不足理由 |
| 未完了 | 未生成・生成失敗・未提示・未評価・修正待ち・中止など。具体的な状態を併記する |

「修正すれば採用」は修正待ちであり、「修正後に採用」の件数に含めない。初稿への判断は修正後も保持する。修正を別の要求に付け替えて、初稿の採用率を良く見せない。

全尺視聴を採用の必須条件にはしない。ただし、何を見たか、採用への同意が全体か一部分かを分けて記録する。一部分への回答から全体への同意を推定しない。人が全体の採用に同意した場合でも、全編の映像・音声を観測した証拠にはならない。

制作上の採用、技術的な検査完了、正式完成、公開許可はそれぞれ別に記録する。本書の採用判定で024の未完了検査を合格にしない。

## 4. 事実照合と修正理由の扱い

事実照合は、選んだ理由を映像・音声が裏づけているかを調べる補助評価とする。採用理由自体が制作要求に沿っているかも照合する。理由と映像が一致していても、その理由が要求を外していれば制作成功にはならない。

1. 既存採用理由の原文と、その出所を先に保持する。
2. 確認する主張を、理由を強めずに具体化する。024では「何を知った／予想したか → 出来事や行動 → 反応・理解の変化」を使う。
3. 映像・音声を見た範囲で「一致／不一致／照合不能」を記録する。未視聴は「未確認」とする。
4. 判定範囲と観測根拠を添える。発話者の予想・感想と、ゲーム内で実際に起きた事実を分ける。

起点と反応の両方を含むという条件は、今回の024の制作意図に対する確認内容であり、ZEV全用途の必須構造にはしない。主張に「試した」が含まれる場合、その行動も観測対象になる。文章やSTTの読み直しを映像・音声の確認と記録しない。

主張が曖昧なら、どこが曖昧かを残す。記録形式の全面改修を先行しない。説明を書き直して既存出力に正解を後付けせず、明確化案は旧主張と分ける。

修正内容は次の語で記録できる。複数を選んでよく、独自点数や重みは付けない。

| 修正内容 | 観測する問題 |
| --- | --- |
| 選び直し | 別の場面が必要、制作意図と選定内容が合わない |
| 構成・順序 | 組合せ、前後関係、重複、終わり方を変える必要がある |
| 前後範囲 | 導入や反応が不足する、余分な前後が残る |
| 途中カット | 区間内部の不要部分を取り除く必要がある |
| 字幕・表示 | 本文、時刻、読みやすさ、位置等の修正が必要 |
| 映像・音声 | 音量、欠落、不自然な切替等の修正が必要 |
| 条件・情報不足 | 要求や観測が足りず、適否を決められない |

修正種別から実装の責任箇所を自動確定しない。字幕問題でも認識・入力・描画など複数の原因があり得る。ここでは観測した問題と修正案を記録し、原因調査や修正実装は別の作業範囲として扱う。

## 5. 数値の定義と測り方

### 5.1 件数

本番比較では、出力を見る前に評価対象の制作要求一覧を固定する。同じ一覧に対する生成失敗、中止、未提示、不採用も取り落とさない。良かった候補だけを後から分母へ入れない。

Nをその制作要求数、Aを初稿そのまま採用、Bを修正後採用、Rを不採用、Uを判断不能、Pを未完了とする。各要求の現在の結果を重複なく1つへ置き、N = A + B + R + U + Pとする。

- 初稿のまま使えた結果：A件／N件。
- 実際に修正して使えた結果：B件／N件。Aと別に示す。
- 不採用・判断不能・未完了：それぞれ件数と理由を示す。
- 最終的な採用総数を示す場合もAとBの内訳を消さない。
- Nが0なら率は算出しない。今回の1区間の手順確認は本番のNへ入れない。

初稿が使えたかを主に見て、人の実作業と待ち時間を併記する。生成した候補数や短くした秒数を、そのまま制作成功件数にしない。

### 5.2 人の実作業時間

人がその制作要求に能動的に関わった時間を、役割と作業ごとに記録する。単位は秒、表示時は分秒でもよい。

| 作業 | 含める時間 |
| --- | --- |
| 要求・方針の具体化 | 人が制作条件を書き、案を読み、内容を決める時間 |
| 視聴・判断 | 再生、停止、見直し、説明の読取、判断に使う時間 |
| 修正指示 | 修正点を考え、伝える時間 |
| 人による編集・再確認 | 人が実際に編集する時間と、修正版を判断する時間 |
| 操作・準備 | 当該要求のために人がファイルを探し、開き、設定する時間 |

同じ人が視聴しながら判断した時間は二重に足さない。複数の人が参加した場合は人ごとに測り、人の合計作業時間として示す。AI側へ移った準備処理は人の作業時間へ混ぜず、準備・処理時間として別記する。

手元の時計や既存記録で開始・終了・中断を記録すればよい。計測用アプリや専用の仕組みを新設しない。チャットの返信間隔を人の作業時間と見なさない。測れなかった時間は未計測とし、測定済み分だけの合計を総時間と呼ばない。

不採用候補、使わなかった修正版、試行の失敗に費やした人の時間も残す。初回の評価準備と、毎回の制作で必要になる時間は分けて示す。過去の024の人の作業時間を今回後から推定で埋めない。

### 5.3 待ち時間・機械処理

- 初稿提示までの経過時間：必要な入力が揃って制作処理を開始した時点から、要求された範囲の初稿を人が確認できる状態で提示した時点まで。
- 動画の生成終了時刻と、初稿を実際に提示できた時刻を別に残す。重い検査や提示準備を挟んだ時間を除外して速く見せない。
- 修正がある場合は、修正指示から修正版提示までの経過時間も別に記録する。
- 人の都合による待機、中断、入力待ちが記録されている場合は内訳を示す。都合のよい控除で合計を書き換えない。
- 準備、生成、確認用処理等の機械処理時間・費用は、既存ログで得られたものだけ示す。未計測・不明を0にしない。
- 今回は既存動画を再利用する。切り出し・提示の所要時間を新規動画生成の速さとは呼ばない。

素材尺・出力尺は条件として併記する。「人の時間÷素材尺」は必要なら補助情報にできるが、1.0を自然な合格ライン・上限とはしない。素材が長いだけで有利になるため、これを主指標にしない。

### 5.4 改善を主張できる範囲

初回は現状の測定であり、改善の証明ではない。以後は同じ素材・制作要求・用途・尺の条件で比較し、採否と人の作業時間、提示までの時間を並べる。時間が短くても採否が悪化した場合は、改善とまとめず得失を示す。

要求、判断者、提示方法、評価範囲が違う場合は違いを記録する。採否を独立した客観品質点に変換しない。再評価で判断が変われば両方を保持し、都合のよい回答だけを残さない。比較時の順序や版の表示による影響も記録するが、今回の日を空けた再視聴や盲検試験を必須工程にはしない。

同じ素材への修正と再評価は改善作業であり、未見素材への一般化の実証とは分ける。採用率・時間の目標値、任意の重み・合格点は本書では設けない。
