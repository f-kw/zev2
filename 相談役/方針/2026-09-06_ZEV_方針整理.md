# 2026-09-06 ZEV 方針整理

## 1. ZEVの基本方針

ZEVはショート動画専用システムではなく、複数の動画生成用途に対応できる動画生成基盤として進める。

目標は「人間の優秀な編集者を完全に代替するAI」ではない。ZEVの基盤は、区間化・切り出し・連結・テロップ・描画・renderなどの再現可能な動画生成処理に置き、その上にAIによる探索・理解・接続・構成支援を加える。

高度な自律編集の完成を、ZEVの製品成立・リリース条件にはしない。現在確認済みの能力だけでも実用価値を作り、AI能力の向上はその価値をさらに飛躍させるものとして扱う。

## 2. 基本アーキテクチャ

ZEVの基本構造は次とする。

**要求 → Planner → Skills → 編集仕様 → ZEV Core → 動画**

### Planner

Plannerは単なるSkill呼び出しルーターではない。

各Skillなどから得られた候補集合を受け取り、以下を判断・調整して最終的な編集仕様を作る。

- どの候補を採用するか
- どの候補を捨てるか
- どの候補同士を組み合わせるか
- 各候補の前後をどこまで含めるか
- 目標尺の中で何を優先するか
- 重複をどう処理するか
- 全体の内容に偏りがないか
- ユーザーの要求に対して各信号・候補をどの程度重視するか

「候補から選ぶ」工程をPlannerの重要な責務とする。

### Skills

Skillは専門能力・部品として候補や判断材料を生成する。

例：

- 発話の意味的重要箇所の抽出
- コメント反応・コメント密度の解析
- 映像探索・映像観測
- 区間化
- 遠方接続
- テロップ生成
- 重複候補の検出
- その他、今後追加される動画生成能力

Skillは今後、追加または強化できる独立した部品として設計する。

### ZEV Core

Plannerが確定した編集仕様を受け取り、区間切り出し、連結、字幕・テロップ、描画、出力などを再現可能な形で実行する。

AIの判断が変化しても、確定後の動画生成処理まで曖昧にしない。

## 3. Geminiの位置付け

Gemini Agentic VideoはZEVそのもの、またはZEVの中核判断主体にはしない。

主に映像探索・映像観測を担うSkillの実装手段として利用する。

想定用途：

- 長尺動画から特定の行動・場面・変化を探す
- 候補区間で実際に何が起きているか観測する
- 発話だけでは取得できない非言語情報を補完する
- 必要な箇所を追加・詳細観測する

Gemini固有の実装をSkillの内側に閉じ込め、将来より適したモデルや手法が出た場合に交換可能な構造を目指す。

## 4. ダイジェスト生成

ダイジェストは単純な機械的連結とは考えない。Plannerを必要とする動画生成系として扱う。

候補材料として、少なくとも次のような情報を利用できる。

- 発話内容から得た意味的重要箇所
- コメント数・コメント密度・コメント急増などの視聴者反応
- 前後文脈
- 重複関係
- 目標尺

意味的重要度とコメント反応は、必ず両方を満たす必要はない。

意味的に重要だがコメントが少ない箇所も採用対象になり得る。一方、意味的重要度が通常でもコメントが大きく反応した箇所は見どころとして採用できる。

Plannerがこれらの候補を比較し、ユーザー要求に応じて採否・優先度・前後範囲・構成を決める。

したがって、コメントの多い区間を機械的につないだだけのものは、ZEVのダイジェスト完成とはみなさない。

## 5. 遠方接続

遠方接続は、時間的に離れた素材から意味的な関係を発見し、新しい接続を作るZEVの重要なAI拡張能力として扱う。

ショート動画では特に、強い発言と、その意味を完成させる離れた発言を接続し、テロップで必要な文脈を補うことで高密度な動画を作れる可能性がある。

## 6. ショート動画の位置付け

ZEVをショート専用から汎用動画生成基盤へ切り替える。

これはショートを捨てるという意味ではない。Plannerがユーザー要求に応じてSkillsを選択・調整し、共通Coreから異なる動画形式を生成できる見通しが立ったため、ショートだけに製品全体を限定する必要がなくなった。

ショートは引き続き主要ユースケースとする。

特に初期段階では、

**遠方接続 + テロップ**

を中心に、バズを狙えるショート動画の品質向上を目指す。

## 7. 第一完成の定義

ZEVの第一完成条件を次の2系統のEnd-to-End生成とする。

1. **ダイジェスト生成**
2. **遠方接続による動画生成**

両方を、共通の

**Planner → Skills → 編集仕様 → ZEV Core**

の構造から完成動画まで生成できることを第一完成の条件とする。

ダイジェストでは、複数の異種候補からPlannerが選択・調整して構成する能力を実証する。

遠方接続では、離れた素材から意味的関係を発見し、新しい接続を作る能力を実証する。

個々の部品を100点にしてから第一完成とするのではなく、まずこの2系統をEnd-to-Endで成立させることを優先する。

## 8. 第一完成後の成長モデル

第一完成後は、ZEV全体を毎回再設計するのではなく、部品の追加・強化を基本的な開発モデルとする。

- 新しい動画生成能力 → 新Skillの追加
- 既存動画生成の品質向上 → Skillの強化・交換
- 対応可能な依頼の拡大 → Plannerが扱えるSkill構成・調整能力の拡大
- 映像理解モデルの進歩 → 映像観測Skill内部の強化・交換

まず必要な材料を揃えて組み立てられる状態を作る。その後は、部品を強力にする、または部品を増やすことでサービス全体を成長させる。
