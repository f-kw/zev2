# Q4：別Digestの確定字幕に対する意味役割と許容表現の判断

あなたは、この指示文と一緒に渡されたC-allの新しい判断入力を読み、全字幕について意味役割と許容できる有限表現の集合を判断する担当です。
過去の具体的な演出ラベルや人間の品質回答を正解として与えていません。以下の人間方針は今回反映する意図的な入力であり、その方針も知らない独立評価ではありません。

## 読む対象と限界

- 指定された入力と本指示文だけを読んでください。参照pathは来歴です。別ファイル・過去の回答・以前の選択・画像や動画を追加取得しないでください。
- 確定字幕325件、全12保持場面の前後文脈、保存音声の候補・音量頂点・ASRを全体として扱います。字幕の目立つ箇所だけに絞らないでください。
- 音声の数値や過去ASRは人声の感情そのものではありません。音声を実際に聞いた、画面を見た、重要な映像を隠さないと断言しないでください。
- 保存音声は入力に明示された通常完成版の過去観測です。新しい演出版の観測ではありません。ASRには誤りがあり得ます。
- 本文・改行・表示区間・保持順序・接続方式は固定です。文字の追加／削除／統合、表示延長、間の変更を判断しないでください。

## 今回反映する人間方針

- Panelは使える表現です。必要な箇所で最も目立つこと自体を除外理由にしません。画像内容を覆う影響は今回の入力だけで観測済みにできません。
- Panel内部のセンタリングは実装が保持します。無地・方眼紙・コミック枠の既存背景を自動使い分けへ接続します。背景数や演出数のノルマはありません。
- 動き系の使用可を維持しますが、このC-allは通常字幕94pxです。既存のPulse・Bounce・Shakeの96px条件に適合しないため、それらを許容集合へ入れてはいけません。
- 保存されている未回答のQ1出来栄え確認やQ3の仮説を、今回の選択根拠にしません。
- 同じ表現が続く、目立つ、無字幕があるという事実だけを欠陥としません。頻度の調整、毎N秒、交互配置、点数／重み付きランキングは行いません。

## 意味役割と表現

入力の役割と有限表現表に従います。物理的に使えない表現を示した観測は必ず守ります。

- `normal`：内容上、有限演出を付ける必要がない場合。集合は `[{"preset":"normal"}]`。
- `focus`：言葉の意味、状況整理、内容上の要点を示す場合。ColorとPanelの許容集合を考えます。両方使えるなら両方を残してよく、具体的な一つの選択は後段が固定します。
- `vocal-energy`：保存音声と文脈から声量や発話の勢いを強調する根拠がある場合。この素材ではScaleだけが候補になり得ます。音量の頂点だけで感情を認定せず、混合音や認識の限界を理由へ残します。
- `reaction`：反応を示す意味役割でも、この素材ではBounce／Shakeが物理条件不適合です。内容上は反応演出が必要だが適合表現がないなら `unrepresentable` として残し、意味的に演出不要なNormalへ黙って置き換えません。別の役割が内容上妥当なら、その理由で判断してください。
- 内容判断に根拠が足りない場合は `unresolved`。全件を無理に解決しないでください。

## Panelの二段階選択

Panelの背景をColorと同列の独立表現へ増やしません。まずColor／Panel等の表現種類の許容集合を返し、Panel choice内で背景の許容集合を指定します。

```json
{"preset":"panel","allowedBackgroundPresets":["plain","graph-paper","comic-frame"]}
```

- `plain`：無地の背景。
- `graph-paper`：方眼紙の意匠。
- `comic-frame`：コミック枠の意匠。

背景の内容上の理由があれば集合を絞って構いません。同程度に使えるなら複数を残します。全種類を出す目的で割り当てず、根拠なく文脈と背景を一対一の固定規則にしません。背景理由は同じ字幕行の理由へ簡潔に含めてください。
任意path・SVG・色・座標・倍率・未知背景は返せません。

## 回答の形式

JSONのみを指定された出力ファイルへ保存してください。冒頭・末尾の説明やMarkdownの囲みは付けません。

最上位のキーは次の5つだけです。

```json
{
  "schemaVersion":"presentation-orchestration-judgment-v002",
  "inputSha256":"入力にある同名の値",
  "completion":"complete",
  "captions":[],
  "connections":[]
}
```

全字幕・全接続を入力のIDで一度ずつ返します。各行は次の形です。

```json
{"captionId":"入力の字幕ID","status":"resolved","semanticRole":"focus","allowedPresets":[{"preset":"color","scope":"whole-caption"},{"preset":"panel","allowedBackgroundPresets":["plain","graph-paper","comic-frame"]}],"reason":"この文脈で許容する理由。観測と推測を分ける。","evidenceIds":["実在する入力根拠ID"]}
```

未解決・適用不能は `status` をそれぞれ `unresolved`／`unrepresentable`、`semanticRole` は `null`、`allowedPresets` は `[]` とし、理由と実在根拠を残します。
Color全体は `{"preset":"color","scope":"whole-caption"}`、Scaleは `{"preset":"scale"}`。部分Colorが必要なら `scope:"partial-caption"` と固定本文中の `targetText` を指定し、複数回出現する文は1始まりの `occurrence` を付けます。部分Colorを選ぶ集合に他表現を混ぜません。
同一表現を重複させません。入力にないID、存在しない根拠、未知キーを加えません。

このC-allの接続方式は変更対象外です。全接続を以下の形で保持してください。

```json
{"connectionId":"入力の接続ID","status":"resolved","semanticRole":"continuation","allowedPresets":["normal-cut"],"reason":"今回のC-allは保存済みの通常接続を維持するため。","evidenceIds":["同じ接続ID"]}
```

全対象を読み終えた場合だけ `completion:"complete"` とします。結果の良し悪し、候補数、全編品質、人間の好みは採点しません。
